## Failure, loss and click boundaries

Only absent capture capability and an actual DOMException NotFoundError permit the explicitly labeled listener-only fallback. A missing/disconnected owned control cancels through existing PointerCancelled; arbitrary exceptions must log and cancel rather than become fallback or escape as Runtime defects. Log an acquisition limitation once, without pointer-move logs. Release checks the retained owner's capture, catches/logs release failure, and completes finalization without cancellation messages or disposal failure.

“Current owned physical control” in the loss policy means the retained **successfully captured current resource**, not a fresh identity-only DOM query. Ignore loss from old/foreign controls, loss while a newer capture still exists, and loss when the current session is listener-only and has no acquired capture owner. This last case matters when an old delayed loss names the same physical element/pointer ID as a later fallback session: false hasPointerCapture alone cannot prove that the fallback lost capture. A genuine loss for the current successfully acquired retained owner with no newer capture cancels the matching session. Keep this distinction in the scoped native resource; no Model generation, serialized flag or alternate gesture owner is authorized. A finalizer does not emit semantic cancellation. Current `graph.ts:1977-1994` cancellation matches pointer ID, so source review must ensure event routing establishes the owner match before issuing that existing message.

The final packet explicitly incorporates this distinction. Its private weakly canvas-keyed owner registry is an acceptable narrow bridge between native subscriptions: it identifies only the scoped successful resource, never decides gesture semantics, and never enters Model/ports. Registration and cleanup must use exact resource identity; an old finalizer must not delete a replacement entry or release that replacement's capture. The earlier corrected `7ead490b32044b2a8687656663d105c958803ad375045222fc5fcfd1abc0d475` packet is superseded by the final hash above. No further design correction is required within this bounded scope.

Actual trusted cases must observe capture on the initiating handle while pending and after activation, absent preview/start/autopan below and at equality, release on normal up/Escape/acknowledged origin/removal/disposal, and fresh recovery. Reconnection remains immediately active and uses its selected physical control. Prove replacement/old-loss isolation and genuine-current-loss cancellation. Separately prove below-threshold clicktrue completion exactly once, clickfalse no click activation, direct element.click, keyboard independence, and no click session after an activated drag. Synthetic NotFound/unsupported cases prove listeners, not successful capture. An arbitrary acquisition failure and release failure must leave the Runtime/lifecycle healthy with no accepted graph mutation or leaked resource. These obligations fit the already authorized native contract files; no new production path or test file is granted.
