## Required corrections

### [CORRECTNESS-096-01] Limit producer acknowledgment to Model processing

- **Evidence**: `plans/096-resume-native-appearance-accessibility.md:272-276` proposes yielding public `Render.afterCommit` and then promising that the configuration committed or was superseded by a later committed revision. D `dist/render/render.js:17-23,53-58` waits for the runtime notifier when present. D `dist/runtime/renderer.js:377-408` deliberately settles that notifier when a frame is abandoned, including crash and paused view paths, without patching the live Model. D `dist/runtime/runtime.js:247-253,378` supplies the real commit service and runs the command in the runtime scope, so using the actual public service does not remove this limitation.
- **Impact**: An appearance response can honestly describe a producer transition while the displayed DOM remains a historical or failure view. The unconditional committed-or-superseded promise would falsely establish DOM acceptance from a response alone.
- **Effort**: M, including contract changes and healthy/paused/failure/disposal native evidence.
- **Risk**: LOW for narrowing the claim; HIGH if implementation invents a private commit service or additional renderer authority to preserve it.
- **Confidence**: HIGH. The abandoned-frame release is explicit in the actual installed renderer.
- **Fix sketch**: Define `applied`, `unchanged`, `invalid` and producer `failed` as captured results of Model request processing. Retain public `Render.afterCommit` as an output synchronization attempt that may finish without a live configuration patch. Require actual root revision and rendered output for healthy native coalesced-commit proof, separately from response settlement. Explicitly document and test paused/crashed/disposed boundaries without treating a reply as DOM acceptance. Do not import private Runtime services or promise that crash always emits or always suppresses a response; the honest guarantee is narrower.

This correction changes the acknowledgment wording, not producer equality, safe revision exhaustion, captured response values or client correlation. A later greater-revision observation still orders Model configuration. It establishes no matching DOM by itself.

### [CORRECTNESS-096-02] Freeze Vue's last-valid prop projection policy

- **Evidence**: `plans/096-resume-native-appearance-accessibility.md:15,87,105` requires invalid updates to preserve valid configuration and output, but gives no concrete Vue failure policy. H `packages/vue/src/flow-canvas.ts:826-855` derives a complete prop tuple and calls `Effect.runSync(decodeFlowAppearance(input))` inside a computed getter. H `:858,866-885` gives that throwing getter to consumers and media lifecycle. Main `plans/057-public-contract-design.md:67` says supplied partial label keys override the pinned defaults for those keys.
- **Impact**: Copying the historical computed decoder leaves invalid reactive props capable of invalidating the configuration getter and rendering/watch paths. Tests need a defined accepted projection, replacement rule and recovery behavior rather than relying on Vue's error handling to leave some old DOM in place. Merging each replacement label object into stale configuration would also turn declarative props into undocumented patch accumulation.
- **Effort**: M, including mounted invalid-initial, invalid-subsequent, removal/replacement and recovery assertions.
- **Risk**: MED. Prop omission/default behavior and reactive batching must remain compatible with current native signatures.
- **Confidence**: HIGH for the historical throwing path and missing policy; the proposed implementation remains unverified.
- **Fix sketch**: Decode the whole current native prop tuple atomically against canonical defaults. Each reactive `ariaLabelConfig` object replaces the previous prop object and merges only with canonical label defaults. Keep a single last-valid normalized native configuration projection, independent of accepted graph state. Specify invalid initial input as canonical default output plus a structured boundary warning; invalid later input keeps the previous valid projection; a later valid tuple applies atomically. Preserve native prop defaulting and characterize own undefined separately from the strict new Vanilla/Foldkit update boundary.

The tuple policy needs public `useFlowAppearance`, actual colors/computed ARIA/control/MiniMap output, unchanged graph/viewport and no accepted graph events as assertions. Assert that omission of a formerly supplied label restores its canonical default on a valid replacement. The three interactive flags must become visible together after the existing reactive owner acknowledgment, with no intermediate accepted tuple. Callbackless Vue interactivity remains disabled. This initial-invalid policy is an explicit native choice for approval, not permission to reset a malformed Foldkit Model or persistence packet.

### [CORRECTNESS-096-03] Match the pinned formatter's signed 32-bit inputs

- **Evidence**: `plans/096-resume-native-appearance-accessibility.md:91,104,139` prescribes pre-move absolute truncated/integer inputs and treats them as reference requirements. P `packages/react/src/components/NodeWrapper/index.tsx:148-158` invokes the formatter with `~~internals.positionAbsolute.x` and `~~internals.positionAbsolute.y` before moving. H `packages/vue/src/flow-canvas.ts:4674-4675`, H `packages/foldkit/src/graph.ts:2105-2106`, and H `apps/vanilla/src/mount-flow.ts:7437-7438` use `Math.trunc`. A `packages/core/src/domain/flow-values.ts:15-18` does not restrict graph coordinates to the signed 32-bit range.
- **Impact**: Ordinary positive coordinates hide a real difference. Pinned inputs use JavaScript ToInt32 wrapping and normalize negative fractional zero. A custom formatter can observe different values from `Math.trunc`, even though graph geometry is otherwise valid. Exact formatter text defaults cannot establish input conformity.
- **Effort**: S for the explicit numeric contract and focused native/reference cases.
- **Risk**: LOW when restricted to formatter input conversion; graph position or movement changes would exceed this correction.
- **Confidence**: HIGH. The compared conversion expressions and allowed coordinate range were read directly.
- **Fix sketch**: Adopt JavaScript ToInt32 semantics for the pre-move current absolute x/y passed to the native formatter, matching the pinned `~~` behavior. Do not change stored geometry or movement calculations. Add independently expected formatter inputs around positive/negative `2^31` and `2^32`, negative fractions, ordinary fractions and nested positions, with actual custom formatter capture and controlled graph unchanged before acknowledgment.
