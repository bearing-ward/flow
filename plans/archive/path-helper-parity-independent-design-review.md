## Blocking finding

### [BUG-088-01] Cover and reconcile the same-side NaN gap predicate

- Evidence: `packages/core/src/domain/flow-edge-path.ts:416` computes the axis difference, and `:418-422` returns early only for `difference > offset` before otherwise computing the gap adjustment. Pinned `research/artifacts/xyflow/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/utils/edges/smoothstep-edge.ts:153-164` computes that adjustment only inside `diff <= offset`. Those conditions are equivalent for ordinary finite operands, but both comparisons are false when the difference is NaN. Flow therefore takes an adjustment branch upstream skips.
- Evidence: native `flow-edge-path.ts:424-430` can assign that NaN adjustment to the otherwise finite target gap. `:529-542` and `:617-634` consume the adjustment; `:645-662` writes routed points into the path string. With right/right sides, sourceX=NaN, sourceY=0, targetX=100, targetY=100, offset=20, static tracing selects targetAdjustment. Flow poisons targetGapped.x=120 with NaN; upstream leaves its zero adjustment. The penultimate point has y=100 on both adjacent segments, so the no-bend string contains `LNaN 100` in Flow versus `L120 100` upstream. This is a source deduction, not an executed tuple or fixture.
- Evidence: `node_modules/effect/src/Schema.ts:2999-3012` includes NaN in S.Number, and both public coordinate signatures use number. The design accepts this numeric domain at `plans/archive/path-helper-parity-design.md:99-105`, but `:49` still describes matching formulas and branch structure. Its mandatory matrix at `:156-160` requires NaN in each coordinate without explicitly requiring same-side routing for those values. Default bottom/top numeric cases can miss this branch. Existing tests at `packages/core/src/domain/flow-edge-path.test.ts:10-83` do not cover it.
- Impact: the proposed reference work can miss a known discrepancy inside the chosen numeric contract, or stop on an already discoverable defect after dispatch. This is separate from the documented outside-type invalid-side observation.
- Effort: S for the bounded plan/design amendment and regression cases; runtime verification remains part of execution.
- Risk: LOW for the amendment; MED for production correction until an actual pinned full-tuple capture establishes its behavior. Finite same-side gap behavior and raw arithmetic must remain intact.
- Confidence: HIGH for the predicate discrepancy and path consequence by static tracing. Executable reproduction is unverified.
- Fix sketch: explicitly record this known numeric-domain diagnostic and require same-side horizontal and vertical cases with NaN in the source/target routing coordinate, alongside finite gap below/equal/above offset controls. Include numeric option observations where they affect this predicate. Capture genuine pinned full tuples and the current Flow outcomes first. Primary must inspect the exact pre-fix discrepancy before authorizing only the predicate-equivalent correction, for example returning when `!(difference <= offset)`. Do not add a finite guard, reject NaN, sanitize output, copy expected formulas or widen renderer scope. Re-run the captured regression and existing finite branch tests after any separately approved correction.

No other blocking design finding was confirmed. The correction is already bounded by the plan's mismatch-to-primary STOP rule, but the known defect and its cross-branch case must be explicit in the reviewed packet.
