### [CORRECTNESS-03-R1] Generic type parameters still receive caller-input lifecycle variants

- **Priority/category:** P2, Correctness / Bugs; also a design-regression coverage gap.
- **Evidence:** `plans/callback-field-matrix-design.py:136` recognizes type references, intersections, union variants and exported declarations as helpers, but omits the retained description prefix `generic parameter`. Consequently `:145` assigns caller-input to `Edge#1.EdgeData` and `Node#1.NodeData`. The resulting roles are at `plans/native-node-edge-field-continuation-matrix.json:17771` and `:56649`; both original descriptions explicitly say generic parameter. The six update variants ask the runtime to observe an exact caller-input value named after that type parameter, for example `:94272` and `:214812`. Their ownUndefined variants use caller input/patch semantics, and `viaConsumingOperation` is false.
- **Actual contract:** Pinned `packages/react/src/types/nodes.ts:13` declares `Node<NodeData extends Record<string, unknown> = Record<string, unknown>, ...>`; `:16` passes the type argument to NodeBase. Pinned `packages/react/src/types/edges.ts:54` similarly declares EdgeData and passes it at `:57`. Pinned `packages/system/src/types/nodes.ts:23` places the corresponding runtime value in the separate `data: NodeData` field. A generic argument is not an own runtime property that can become undefined, be patched or be observed under the member's extraction ID. Accepted 087 reinforces that distinction at `packages/core/src/domain/flow-data-contract.schema.ts:31`–`:33`, deriving node/edge types from the codec's decoded document type.
- **Impact:** The final source/type packet can inherit nonexistent runtime input obligations for these six cells or confuse proving subtype propagation with proving a field named NodeData/EdgeData. The revised claim that all type-only dimensions use consuming-operation links is incomplete because these two type-only records are never classified into that set.
- **Effort/fix risk/confidence:** S design correction; low fix risk; high confidence from retained descriptions and actual pinned declarations.
- **Fix sketch:** Recognize generic-parameter declarations explicitly as type-only, preserving both exact original IDs. State the generic constraint and default type as compiler obligations. Link lifecycle dimensions to the real operation carrying the typed `data` value, without inventing a property or changing arbitrary decoded-data/serialization ownership. Keep the six cells OPEN.
- **Test coverage:** Existing generator regressions check the records already labeled type-only, allowing this omission to escape. Add a design regression over every retained `generic parameter` row, asserting type-only roles and consuming-operation linkage; verify these two exact identities and six cells. This is a request for reviewable design correction, not permission to execute source/compiler/product probes.
