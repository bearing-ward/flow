## Required revisions

### [TEST-01] Separate public allowlist cancellation from completion membership proof

- **Evidence**: Original amendment `plans/native-reconnect-admission-amendment.md:15` says allowlist replacement between preview and release determines release admission, and `:25` requires both admitted-to-denied and denied-to-admitted between start/preview and terminal reduction while preserving public policy. The real public setter routes through `packages/foldkit/src/application.ts:1109` to `Graph.Message.SetAllowedTargets`. `packages/foldkit/src/graph.ts:1634` changes the list and clears pointerSession, gestureSession and keyboardConnectionSession. `application.ts:1968` returns the routed result without adding a separate lifecycle event comparison for this HostAction. There is no non-cancelling actual public list-update route in the inspected candidate.
- **Impact**: A real public list replacement cannot preserve that same ongoing reconnect until completion. Both directions first cancel the session; a later terminal pointer/key activation cannot prove same-session admission against the new list. A reducer test that swaps only the list while retaining a session can test current membership, but presenting it as native public continuation would be false evidence. An executor could otherwise remove existing cancellation or add a private browser Model setter to satisfy the requested matrix, which violates this amendment's scope and policy.
- **Effort**: S for a bounded design/test clarification and explicit expected outcomes; existing required native and unit matrix remains.
- **Risk**: LOW for the clarification. HIGH if implemented as an unreviewed public setter or lifecycle-policy change.
- **Confidence**: HIGH. Both setter bodies, routing and both completion bodies were personally read; no browser reproduction was needed to establish the explicit clearing operation.
- **Fix sketch**: Require actual public SetAllowedTargets tests to assert the existing session cancellation, no residual proposal from later release, actual cleanup, unchanged accepted graph/measurements/revision and a fresh admitted retry. Separately label completion latest-list checks as direct Graph/app reducer tests built from a Schema-derived Model with a live session and the independently supplied current list. Never call those reducer constructions same-public-gesture continuation. Preserve SetAllowedTargets and current lifecycle behavior; report any required change outside the two completion guards as a new STOP.

The public setter's existing canonical terminal behavior needs characterization, not an invented assertion that it emits the completion branch's terminal event. The guarded denied/admitted completion cases still require exact terminal event counts for their real before/after reduction. Public cancellation and completion are different paths.
