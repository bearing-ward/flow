### Recommended exact policy and bounded correction

Approve this policy before a new source pass: **all six external native fields are validated before createProgram returns; own undefined inherits/no-origin-request, and any defined invalid value rejects before Runtime.embed or restoration. Valid creation options do not overwrite a valid preserved Model merely because they were checked eagerly.** This is an additive clarification of timing, not a claim that the frozen plan already mandated synchronous scalar rejection.

In the already allowed `packages/foldkit/src/application.ts`, import the existing public core resolveConnectionOptions and apply this exact private preparation after the existing requestedOrigin decode, before Runtime.makeElement:

```ts
const connectionOptions = Object.freeze(
  resolveConnectionOptions(interactionOptions)
)
const {
  nodeOrigin: _nodeOrigin,
  connectionLineStyle: _lineStyle,
  connectionLineContainerStyle: _containerStyle,
  ...legacyInteractionOptions
} = interactionOptions
const initialInteractionOptions = {
  ...legacyInteractionOptions,
  ...connectionOptions,
  nodeOrigin: requestedOrigin,
}

The frozen object has exactly the five required scalar fields returned by the authoritative resolver; the shallow creation snapshot retains every legacy option. No public option, Model field, port, test API, Schema copy, cast, dependency or config authority is added.
