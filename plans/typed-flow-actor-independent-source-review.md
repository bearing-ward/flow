- **Evidence**: `packages/core/src/domain/flow-typed-actor.ts:191-199,217-226,261-268` maps SchemaError to the public failure before flowBoundary runs. `packages/core/src/domain/flow-typed-ownership.ts:169-174` consequently logs the replacement Cause, not the original SchemaError. These are the same translation defect, not separate lifecycle failures.
- **Impact**: malformed viewport/codec/checkpoint input, broken lease predicates and terminal activation failures retain their public payloads but lose the underlying reason needed to diagnose them. In particular, an activation defect can disable all subsequent writes while leaving no structured record of that defect. The current unit matrix asserts outcomes and cleanup, not original logger causes, so successful gates miss this requirement.

- **Confidence**: HIGH. The original Causes disappear at the cited translation points; no wrapper subsequently recovers them. The existing flowBoundary cause logger does not repair earlier mapError/catch loss.
- **Fix sketch**: retain and log the original SchemaError, caught exception or failed activation Cause at its boundary while returning exactly the current frozen public payload. Use the existing `FlowSpan.editFailure`, `FlowAttribute.failureName` and `FlowAttribute.failureMessage`; preserve the first sticky terminal transition and closed-owner guard. Add logger assertions through real exported actor operations and public capture/gate callbacks, with distinct harmless original schema/provider-failure/defect fixtures and unchanged public outcome assertions.
