## Recommended executable bounded design

Recommend capturing keyboard baseline AND preventing native transient DOM previews from becoming authoritative node measurements at the existing native producer boundary. This avoids any false measured response or new transport status: no preview sample is sent, so no measurementResults ACK is invented or changed. Preserve genuine current-generation public MeasureNode acceptance as it is; arbitrary explicit caller-owned measurements remain their existing protocol boundary.

Exact functional paths proposed: packages/foldkit/src/graph.ts, measurement-observer.ts and application.ts:lifecycleMessagePhase ONLY. No core, node-measurement-lifecycle client, DOM resource composition, styles, public API/port shapes or dependencies. No private Model setter, fake lease, generation prediction, geometry subtraction, global observer pause or stored snapshot restoration.

1. Extend existing KeyboardResizeSessionSchema with position and size derived from existing authoritative position/size Schemas. At first valid selected-node keyboard activation, capture accepted node position and actual current graph dimensions once. Repeated same node/direction accumulates delta while retaining this baseline; a different direction/node starts a new baseline. previewResizeInput and FinishKeyboardResize use that same captured baseline. Preserve minimum/bounds/origin/direct-child compensation, no-change/rejected paths and control modes.
2. In graphView's existing rendered native node, add a concrete native lifecycle data marker only when that node is the active pointer/keyboard resize preview participant. Marker belongs to transient DOM output, never the document/save. Direct children whose preview changes only position retain normal size/local-handle measurement. No new wrapper or Model authority. Exact marker name/Schema encoding must be fixed by reviewed implementation.
3. In measurement-observer.measure, after exact active issued-slot ownership check and before reading geometry, inspect this marker on the exact current element. If transient, return false without onMeasure, observed count or request sequence advancement. Keep lease active/current and registration untouched. Other slots still measure. A manual refresher request during transient preview truthfully reports the existing failed/not-measured outcome; never successful cached dimensions. This must be asserted rather than hidden. Native ResizeObserver callbacks consume current DOM geometry rather than stale ResizeObserverEntry geometry, so callbacks delivered after terminal removal of the marker read the actual restored/current DOM; callbacks during active preview suppress delivery. Late REGISTER ACK checks current element/marker before first delivery; pending retired lifetimes remain governed by existing conditional invalidation.
4. On cancel or controlled refusal, clearing the session removes the transient marker and renders the unchanged accepted document against the retained genuine baseline measurement. On any actually accepted node size change (uncontrolled finish or later real controlled document ACK), invalidate only that node's prior measurement record in Graph's existing post-accepted-document-change pass at2621–2641: filter its old record from measurements.nodes, retain every core-issued generation and all unrelated nodes, increment measurement revision only when a record is actually removed. Compare the old and newly accepted size structurally; no proposal/refusal invalidation, no fabricated measurement or lease/generation. Current internal query becomes honestly unmeasured/declared fallback until new physical measurement arrives. Normal accepted document authority supplies the new rendered size through existing declared fallback; no pending-size registry or second geometry authority is introduced. Also preserve existing removed-node generation retirement/pruning.
5. Extend the existing observer MutationObserver filter to the exact transient marker in addition to data-node-id. Marker changes are distinct from node-identity changes: never retire/re-register solely for preview phase. For a current exact active slot becoming settled, invoke existing measure on that exact current element AFTER the real DOM patch; it reads actual fresh bounds and sends the actual still-current lease. This concrete settlement measurement is required because successful pointer acceptance may keep the same preview-to-accepted physical size and therefore cause no ResizeObserver event. On preview activation, skip delivery. On cancellation/refusal, settled DOM baseline is measured truthfully. If registration is pending during marker settlement, no fake measurement is sent; its later actual ACK invokes current measure. Identity removal/replacement still retires and conditionally invalidates normally. Other slots and ordinary external/manual native refresh remain live. If reading DOM or delivery fails, retain existing explicit failed measurement/structured failure behavior and do not claim readiness.
6. Add FinishKeyboardResize to release classification only for actual arrow-key finish, preserving other-key/no-active/no-change/rejected behavior, canonical event names, controlled proposed and uncontrolled accepted ordering. Real cancellation remains cancelled; do not infer success from absence of a session.

This is the complete recommended bounded design: native preview delivery is suppressed before geometry reads; keyboard baseline is captured once; actually accepted size changes invalidate only old physical samples while preserving real generation authority; marker settlement triggers fresh real measurement even when accepted DOM size is unchanged from preview. No cached sample is returned as measured for a new input. Keep application MeasureNode response semantics and all port shapes unchanged. Explicit caller-owned public measurement input remains its existing protocol route, separate from native producer proof. This design requires primary/cold review, especially accepted-size invalidation and concrete settle-trigger ordering, before source execution.
