- replaceEncoded(input:unknown,expectedRevision:number): Effect<FlowTypedCommitResult,FlowTypedError,RD|RE|RI|RC>.

- makeTypedFlow({contract,initial encoded|decoded,viewport,encodedInputCapture?,checkpointGate?}): Effect<TypedFlow<C,RI,RC>,FlowTypedError,RE|RI|Scope> for decoded initial; RD|RE|RI|RC|Scope for encoded or genuinely dynamic initial.

RD/RE are C.DecodingServices/C.EncodingServices; RC is a separate inferred encoded-input capture service defaulting to never. RI stays the accepted decoded-isolation environment. Read/observe/decoded writes/save do not acquire RC, and decoded construction does not require RD/RC. Exact encoded/decoded/dynamic constructor overloads are required. These are an explicit proposed service refinement for cold review, not already compiled declarations. Derive serializable revision/commit/checkpoint values from new Schemas and generic snapshot via inferred Struct(toType(C),ViewportSchema), retaining exact C.Type. Existing FlowTypedFailureSchema is unchanged. FlowTypedCheckpointSchema must refine only its viewport field with an x-first/y-second finite check over the authoritative ViewportSchema, retaining exact Viewport Type/Encoded and services never. Existing ViewportSchema/type/concrete behavior remains unchanged. Complete checkpoint preparation also validates/copies the entire finite plain-JSON value before stage. New capture/gate contracts are functional interfaces, never Model/port/persistence fields.

FlowTypedEncodedInputCapture<RC>.capture takes unknown and returns Effect<unknown,FlowTypedFailure,RC>. Default is private plain-JSON data copy before Schema, rejecting accessors/custom prototypes/symbols/cycles/undefined/functions/DOM/bigint/nonfinite/sparse arrays explicitly. Preserve special own keys safely. Custom encoded classes and own-undefined/default branches require an explicit trusted capture capability preserving private state/absence before caller decoder/checkers. Arbitrary C remains supported; do not silently JSON.stringify or discard values. The capture capability must be cold-approved here; factory087 fields remain unchanged.

Freeze viewport/checkpoint order and errors: initialization first descriptor-copies fixed viewport data without accessor execution or discarding numeric leaves, validates shape/zoom through unchanged ViewportSchema, then checks x finiteness followed by y; only then run caller document capture/codec/isolation. Nonfinite x rejects exactly `{_tag:'FlowCodecFailure',operation:'encode',message:'Checkpoint viewport.x must be finite'}`; y uses `Checkpoint viewport.y must be finite`; both invalid means x wins. No live owner/writer/activation/observer worker, stage or accepted notification exists on initialization rejection. For init/every write, private graph validation/integrity/sealing precedes separate document encoding; finite-JSON-copy output; assemble complete checkpoint; parse exported refined FlowTypedCheckpointSchema; finite-JSON-copy/check the entire checkpoint; freeze; only then stage/CAS. Other malformed/nonfinite complete checkpoint uses operation encode/message `Checkpoint must contain only finite JSON values`, except the specified coordinate errors. No coercion, document-only check or changes to saved/concrete schemas.

FlowTypedCheckpointGate.stage receives a separate frozen checkpoint and returns Effect<FlowTypedCheckpointReservation,FlowTypedFailure> with services already provided in the composing scope. Reservation has trusted pure nonthrowing isCurrent():boolean, idempotent abort:Effect<void>, and accepted:Effect<void,FlowTypedFailure>. Stage returns only after real required staging ACK, never displays candidate accepted state. Core preparation identity and bridge owner epoch distinguish same-revision races. Abort cannot revert another stage or accepted commit. Invalid/failed stage, terminal health failure, cancellation/disposal or CAS conflict reject before acceptance. Core-only default ACK is checkpoint preparation itself. Postcommit accepted activation runs in an independent ordered worker and cannot rollback acceptance. On success release its transient staging identity once through non-reverting abort. On failure/defect, stop before taking another activation and serialize first sticky gate metadata `{_tag:'FlowProjectionFailure',revision:r,message:'Checkpoint activation failed'}` for failed accepted revision r, including0 for postcreation initialization activation failure. Pending/new writes report r, never their prospective revision. New writes check gate health before preparation, final CAS checks it again, late stage-return handoff checks it even if its request is already settled. Reads/encode/independent observers remain usable. No queued accepted callback, new CAS/notification or native success is allowed after the failure transition; no recovery/replacement API is added. CommitResult stays core-only.

Stage failure before acceptance is per-request, leaves gate healthy, and maps exactly to `{_tag:'FlowProjectionFailure',revision:p,message:'Checkpoint staging failed'}` for prospective p, initialization p=0.
