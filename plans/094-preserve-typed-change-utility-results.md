## Problem and proposed decisions for independent review

Current pure apply functions constrain all payloads to JSON-backed FlowNode/FlowEdge and return arbitrary N[]/E[] after replacing their writable fields. A false-selected edge or branded/literal position can become a different value while the declaration still promises the original narrow type. Node/edge add/replace aliases duplicate Schema fields manually. Grouping also repeatedly copies each growing per-ID queue; this is pre-existing, not introduced by the proposal.

The proposed contract is synchronous apply over ordinary caller-owned outer data records. It retains original ordered shallow collection semantics and nested decoded payload identity, including Date/private-class data, without JSON validation or hidden codec/actor/isolation effects. Output explicitly widens only fields written by the utility. A union's type/data correlation remains intact. Readonly input collections are accepted and the result collection is mutable. Existing concrete change decoders/default type parameters stay intact.

Five explicit DESIGN decisions:

1. **Outer domain:** plain caller-owned item records whose required fields are own enumerable data properties. Whole-item classes, inherited/non-enumerable required members, outer accessors/prototype-dependent invariants and arbitrary dependent Schema refinements are unsupported. Nested decoded Date/private classes remain supported by identity. TypeScript's structural geometry bound cannot enforce descriptors; documentation must state this limitation and runtime tests must retain the counterexample. This is the same shallow shell behavior as the library. Do not advertise universally sound Omit preservation over arbitrary object shells, introduce a silent prototype-preserving clone, or insert a speculative runtime validator. Independent reviewer must explicitly judge whether this restricted contract is sufficient before execution.
2. **Honest outputs:** authoritative Schema write view includes own undefined on optional properties. A homomorphic key-remap removes written keys from each input branch, then intersects the write view. No `N & Writes`, arbitrary N[] promise, or cast-based output. Geometry/literal brands on replaced position/width/height/measured/selection/dragging/resizing disappear; unrelated branded identity, type/data/custom own fields persist. Root exact-optional mode's old private transient-only array return incompatibility is an explicit declaration correction, not waived or hidden. Preserve concrete FlowNode/FlowEdge compatibility tests and report any real caller requiring adaptation as STOP.
3. **Public aliases from Schema:** derive NodeChange<N>/EdgeChange<E> through real internal generic builders and `ReturnType<typeof builder<Schema.ConstraintCodec<N>>>['Type']`. Builders remain PRIVATE; no runtime generic-builder exports. This avoids offering arbitrary optional whole-item codecs as a supported new decoder. Actual concrete NodeChangeSchema/EdgeChangeSchema and all their variants remain byte/behavior unchanged. Type-only instantiation does not manufacture a codec, replace caller services, or put arbitrary data into Model/persistence. No handwritten public add/replace union.
4. **Index:** derived pure aliases keep existing absent-only `index?: number`; internal builders use `optionalKey(Int)` solely to derive that alias. Existing public concrete add decoder still uses `optional(Int)` and admits own undefined; pure numeric splice semantics still accept fractional/negative/oversized/NaN/Infinity number values. Keep this existing decoder/pure-Type mismatch explicit in docs/tests. Do not narrow pure index to Int or silently alter concrete decoders to fix it. Public generic schema builders can be a separately designed future feature with required-item metadata.
5. **Private grouping:** initialize per-ID queues as actual nonempty tuples and append with push. Remove/replace resets the private queue, add queues retain original order/native splice behavior. No caller array/change/item mutation. This removes repeated queue copying only; it is not a measured speedup or whole-algorithm linearity claim. Typed output spreads may allocate additional shallow objects; retain identity/value semantics and measure only if a performance claim is made.
