## Second finding resolved: terminal publication failure and release

Design `:214,220,238-252,264-266` and Plan089 `:56-60,103,120,122` now specify sticky actor-owned failure metadata, precise public errors, preparation and final CAS guards, late stage-return guards, and shared release ownership.

An activation failure serializes a short writer transition before another activation is dequeued. It retains every accepted core revision/checkpoint, stops admission/dequeue, records the first exact ProjectionFailure, settles every pending unaccepted write and claims the failed/queued/already-returned leases for release. New writes do no preparation; a write that started earlier cannot bypass health at CAS or a late handoff. A stage failure before acceptance remains per-request and keeps the gate healthy. Closed, interruption, health, revision and lease failure precedence is frozen. Revision0 postcreation activation failure remains distinct from initialization stage failure.

Each stage invocation owns one total local lease state and one release-completion Deferred. The writer claims release once; a separate cleanup job executes non-reverting abort outside the writer; later terminal/finalizer paths join the same completion. This prevents failure/close/finally from independently invoking abort. Successful activation also releases its transient staging identity through that shared protocol. No release can roll back accepted authority or another generation.

The installed `Effect.ts:14737-14741` uninterruptibleMask/restore signature supports an interruptible stage with a narrowly protected return handoff. Stage owns partial-acquisition cleanup until it returns; core then registers the returned lease or assigns it immediately to release. The owner finalizer keeps writer/cleanup resources alive while preparation handoffs and release jobs finish, then shuts queues. Cleanup jobs cannot be interrupted away after claiming an identity. Installed Queue/Deferred/Scope/fork APIs cited in the first review support these resources without changing public service channels or inventing a runtime.

This introduces no callback-held writer. Stage, activation and abort run outside writer actions; state transitions merely record ownership, terminal replies and cleanup jobs. Close settles requests before interrupting/joining preparations, so a callback awaiting a nested actor call can resume with its terminal outcome. Cleanup completion must not be awaited inside the writer that needs to mark it released. The explicit outside-writer rule and live cleanup lane require that implementation discipline; real fiber/Deferred tests and existing deadlock STOP criteria must verify it. Trusted abort is required to terminate and not fail; a violating provider is a contract failure, not an accepted indefinite cleanup or reason to release twice.
