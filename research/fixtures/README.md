# Behavior fixtures

`measurement-contract.json` records the shared nested, hidden, zero-sized, culled-fit, and remove/re-add measurement cases. Core schema/state tests cover measurement validity, stale generations, readiness, immutable projections, and pruning. The same cases run through production controller/composable/runtime APIs in Vanilla, Vue, and Foldkit via `apps/shared-e2e/measured-geometry-contract.ts`; host tests also exercise real DOM resizing and observer cleanup. `measured-geometry-reference.json` records initial and refreshed dimensions, handle bounds, and visible/include-hidden readiness from two independent captures at the pinned upstream SHA. The script requires a clean disposable checkout and compares repeated normalized results.

`graph-edit-reference.json` records a twice-reproducible mounted `@xyflow/react` instance probe at the pinned SHA. Rebuild and capture it from a disposable full checkout with `bun run scripts/capture-graph-edit-reference.ts --checkout /absolute/path/to/xyflow`. The script refuses a different SHA or a dirty checkout, uses the upstream pnpm lockfile, and writes the capture here. Its current proof boundary is collection addition; valid full-collection `setNodes`/`setEdges` calls that update one node and one edge data value; node/edge data merge and replacement; missing update IDs; and descendant/incident-edge deletion. `apps/vanilla/e2e/public-edits.e2e.ts` compares that valid setter output to Flow after projecting required top-level node labels out and retaining IDs, positions, parents, and data. Setter cases do not test removing nodes, dangling endpoints, or controlled ownership. Controlled acknowledgement, protected deletion, and updater queue scheduling remain unverified. The metadata timestamp is outside `cases`; renderer-measured node geometry and timestamps are normalized away.

`graph-edit-selected-reference.json` records a second selected capture from the same twice-checked full checkout and script. Its utility cases exercise `applyNodeChanges` with position/select/unknown-remove changes, duplicate-endpoint `addEdge`, and `reconnectEdge` with `shouldReplaceId: false` and changed handles. The controlled deletion case awaits `onBeforeDelete`, records `onEdgesDelete`, edge changes, `onNodesDelete`, node changes, and `onDelete`, and then reads both the result and unchanged owner inputs. It establishes proposal callback order only; it does not establish owner acknowledgement. The script compares both the main and controlled deletion captures from two fresh Chromium pages before writing either fixture. Normalization excludes timestamps and renderer-measured geometry while preserving collection and event order.

`provider-session-reference.json` is captured with `bun run scripts/capture-provider-session-reference.ts --checkout /absolute/path/to/xyflow-checkout`. The script requires the exact pinned commit and a clean checkout, builds the pinned packages, and compares two fresh Chromium captures before writing. It records `useNodeId` context values, `useNodes` and `useNodesData` projections (including requested-ID order and omission of a missing ID), `toObject`, and an imperative set/restore sequence for document and viewport. `capturedAt` is metadata outside compared cases; measured node geometry is removed. The Flow public-core comparator lives in `packages/conformance/src/provider-session-reference.test.ts`; host production behavior remains independently covered by each host's `public-state.e2e.ts`.

`reference-captures.json` stores three browser-observed behaviors from xyflow commit `0a1f9575b25679f2880175de8d3eae21aedde921`. The immutable imported tree omits the `tooling/` workspace and built package outputs, so it cannot start by itself. The captures were run from a disposable full checkout at the exact pinned commit; its install and build did not change `research/artifacts/`.

Reproduce the first two captures from that full checkout with:

```sh
pnpm install --frozen-lockfile
pnpm build
cd tests/playwright
FRAMEWORK=react pnpm exec playwright test -c playwright.react.config.ts --project=chromium -g 'draggable=false prevents dragging|custom drag handle works'
```

The commands run the named pinned tests. A temporary Playwright probe read the same nodes' inline transforms before and after each action. The JSON retains those observed values and reduces them to `transformChanged` booleans; `packages/conformance/src/index.test.ts` checks the pinned commit and normalized results. Flow's custom-handle E2E independently asserts the same outside/inside booleans in `apps/vanilla/e2e/graph-renderers.e2e.ts`. This is a normalized comparison of those two outcomes, not a claim about matching coordinates, timing, or the rest of either adapter.

The `xyflow-left-resize-direct-child` capture used a temporary React example route with a fixed 960×640 browser viewport and graph viewport `{ x: 0, y: 0, zoom: 1 }`. It rendered a 90×60 parent at document position `(80, 100)` with a 20×20 direct child at local position `(15, 15)`. Chromium dragged the parent's left resize control from screen point `(80, 170)` to `(100, 170)` twice. Both observed runs ended with parent position `(100, 100)`, size `70×60`, child world position `(95, 115)`, and derived child local position `(-5, 15)`. Raw rendered bounds retain the example shell's 40 px vertical layout offset; normalized document coordinates use inline transform translations and omit that offset. The temporary probe route was not added to the imported upstream tree.

Re-run this capture from the disposable full checkout by adding the temporary route and running:

```sh
FRAMEWORK=react pnpm exec playwright test -c playwright.react.config.ts --project=chromium e2e/resize-probe.spec.ts
```

The route must render the stated nodes with React Flow's `NodeResizer`, use the stated fixed viewport, and read both node transforms and rendered bounds before and after the exact pointer action. `packages/conformance/src/index.test.ts` checks that the two normalized recorded captures match and asserts the parent bounds and child world/local positions. Flow's `controlled left resize restores parent and child positions until the atomic bounds change is acknowledged` E2E uses the same graph geometry and pointer delta, then checks the acknowledged result.

## Public-edit fixtures

`public-edit-contract.json` is a versioned Flow-authored set of fixed inputs and expected candidate documents or errors. The conformance unit test schema-checks the file and runs all five transactions through the shared core preparation function. Data merge/replacement, cascading deletion, protected-edge conflict, protected-descendant conflict, and invalid-endpoint rollback also run through the production JavaScript controller, Vue composable, and Foldkit Runtime ports in each host's `public-edits.e2e.ts`. The protected-descendant case requests deletion of a parent containing a `deletable: false` child with an incident edge; all hosts assert the typed conflict and unchanged complete accepted graph. The host tests compare candidate or accepted documents and typed errors; the data edit additionally verifies observer ordering and rendered node identity/IDs for each production host. Vanilla also verifies rejected edits leave events and DOM unchanged. Edge JSON data save/restore is verified in each playground. The shared `queuedDisposal` scenario sends its trigger and queued transaction through each production host; all three assert trigger acceptance, disposed settlement for queued work, and zero late notifications. Host-native result shapes remain covered by their lifecycle E2Es alongside controlled acknowledgement, Vue canvas isolation/split-model cases, and Foldkit runtime isolation/reentrant requests.

## Shared public-state fixtures

`public-state-contract.json` adds four versioned Flow-authored scenarios, driven through the real JavaScript controller, a Vue descendant composable, and Foldkit Runtime ports. It is not an upstream capture. Each run compares complete accepted snapshots and point lookups, semantic proposal sequences, accepted-state notifications, graph neighbors/connected edges, rendered DOM, and disposal observation.

`renderer-contract.json` is the shared schema-decoded node/edge scene for renderer coverage. It keeps graph data, renderer type keys, edge path variants (including an omitted-path case that defaults to straight), handles, labels, and markers framework-neutral; each adapter's renderer registry and DOM lifecycle remain host configuration. Its custom edge uses a custom stroke with both open and closed arrow markers. Host E2Es must separately prove identity/data updates, type replacement, unknown-type fallback, refreshed handle endpoints, native controls, rendered SVG hit targets, omitted-path output, and teardown. `renderer-contract-reference.json` is generated only by `scripts/capture-renderer-contract-reference.ts` from a clean disposable checkout at the pinned SHA. The capture retains normalized measured node/handle geometry, all five built-in edge paths, custom label presence, markers with generated IDs removed, and the unknown-edge fallback. This fixture must not be hand-edited. A missing executable upstream checkout leaves comparison claims unverified; it does not invalidate Flow host tests.

## Evidence limits

The eight shared rendering fixtures and four public-state fixtures establish only the listed Flow contracts across three adapters. Feature-specific vanilla tests do not imply Vue or Foldkit support. The custom drag-handle comparison is deliberately narrow: both runs reduce the node transform to unchanged outside the handle and changed inside it. The resize comparison is limited to one left-edge drag at zoom 1 with a 90×60 parent and a 20×20 direct child; other directions, nested extent behavior, cancellation, panel positions, portals, native multi-pointer cancellation, broader accessibility, cross-browser behavior, property coverage, and performance budgets remain unverified against xyflow or outside the tested scope.

## Viewport operations

`viewport-contract.json` is a shared Flow-authored fixture for client/pane coordinate conversion, fractional and per-side pixel fit padding, controlled proposal timing, operation supersession/disposal, and observation boundaries. It deliberately has no extent case: Vanilla public-operation extent enforcement is unverified, Vue/Foldkit extent cells are intentionally unmapped by the selected policy, and the pinned reference capture does not exercise `translateExtent`. Core constraint math is unit-tested separately. Vanilla `apps/vanilla/e2e/flow-followups.e2e.ts`, Vue `apps/vue/e2e/viewport-operations.e2e.ts`, and Foldkit `apps/foldkit/e2e/public-state.e2e.ts` drive production APIs; their assertions include real DOM transforms and rendered bounds. The Foldkit playground controls are covered separately by `apps/foldkit/e2e/viewport-controls.e2e.ts`. `viewport-contract-reference.json` is captured twice from a clean disposable checkout pinned to `0a1f9575b25679f2880175de8d3eae21aedde921` with `bun run scripts/capture-viewport-contract-reference.ts --checkout /absolute/path/to/xyflow-checkout`. It records normalized upstream results and events; volatile frame timing is retained only in raw environment output. Imported artifacts remain immutable.

## Interaction lifecycle

`interaction-lifecycle.json` is the schema-decoded declaration of shared cases for connection/reconnection outcomes, full/partial rectangle selection, all eight resize directions, minimum sizes, cancellation reasons, and expected proposal/acceptance ordering. `packages/conformance/src/index.test.ts` checks the fixture schema and runs selection and resize calculations through core contracts; it does not execute host cancellation transitions or prove event ordering. The three host `interaction-lifecycle.e2e.ts` suites separately exercise production adapters: Vanilla connection/reconnection/cancellation and host isolation; Vue and Foldkit connection/reconnection, keyboard activation, selection/resize, controlled/uncontrolled outcomes, and cancellation. Lifecycle callback proof is separate: Vanilla `gesture-options.e2e.ts` asserts selected native callback sequences, and Foldkit `interaction-lifecycle.e2e.ts` asserts `onInit` and rejected/accepted connection record ordering through its typed event port. Vue’s `activation-callbacks.e2e.ts` asserts click-connect/reconnect change → adoption → terminal order, drag and pointer rectangle-selection order in controlled/uncontrolled modes, and uncontrolled keyboard rectangle-selection order. Vanilla callbacks may receive native events; Vue emits decoded values; Foldkit records contain schema-validated values and no DOM events. These are host-specific contracts, not a parity claim. The callback matrix remains partial: Foldkit tags click activation as `inputKind: click` on shared operation records (without click-only event names) and omits pane/node/edge double-click and context-menu records; its `onError` record is limited to edit failures. Programmatic Foldkit viewport start/change/end uses `viewportEvents`, a separate schema without controlled proposal/acknowledgement status. Vue pinch zoom and button-array pan are absent; Foldkit pinch, button-array pan, `selectNodesOnDrag`, and activation-keycode options are absent. Vanilla keyboard reconnection remains unsupported; its declared `zoomOnPinch` behavior and trusted native multi-pointer capture are unverified. `interaction-lifecycle-reference.json` records selected pinned-upstream connection terminal cases and eight resize directions with child snapshots. The capture script requires a clean disposable checkout pinned to `0a1f9575b25679f2880175de8d3eae21aedde921`; two runs must have matching normalized cases. Keyboard rectangle selection, grouped/repeated keyboard resize, some input-option combinations, Vanilla dynamic-handle replacement during reconnect, complete callback-order coverage, and native multi-pointer capture remain open.

## Pure path helpers

`path-helper-reference.json` captures all five existing pure exports from a clean disposable checkout at `0a1f9575b25679f2880175de8d3eae21aedde921`, built `@xyflow/react`12.11.6. `scripts/capture-path-helper-reference.ts` performs the pinned frozen install/build and requires two fresh Bun-process captures to agree. The 628 observations contain 504 numeric-domain cases and 124 outside-type diagnostics. Scalar tags retain NaN, infinities, negative zero, undefined, null and strings without JSON null loss. Full five-tuples and the center's four-tuple remain intact. `packages/conformance/src/path-helper-reference.test.ts` compares every numeric tuple and keeps malformed observations separate. This fixture does not cover a mounted renderer or host lifecycle.
