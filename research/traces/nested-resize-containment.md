# Nested resize containment

A parent resize must contain its direct children with `extent: 'parent'`. Every direct child keeps its world position and measured size, including children permitted to overflow. The normal vanilla resize scene opts its child into containment at `apps/vanilla/src/main.ts:193`.

## Core contract and geometry

`NodeResizeCalculationInputSchema` adds optional `childExtent` using `NodeExtentSchema` at `packages/core/src/domain/flow-runtime.schema.ts:535`. The existing public rectangle calculation and fixed host minima of 40 by 24 remain in place. No graph resize facade is introduced.

`graphResizeChildExtent` at `packages/core/src/domain/flow-graph.ts:330` selects only direct children with `extent: 'parent'`. It unions their committed local positions and resolved dimensions in the resized node's parent coordinate space. It ignores transient graph position overrides. Positive measurements precede declared sizes and the graph's existing fallback at `packages/core/src/domain/flow-graph.ts:83`.

For starting edges L, R, T, B and child edges Cl, Cr, Ct, Cb, an active left edge requires width at least `max(40, R-Cl)`; right requires `max(40, Cr-L)`. Top requires height at least `max(24, B-Ct)`; bottom requires `max(24, Cb-T)`. `childAxisMinimum` at `packages/core/src/domain/flow-runtime.schema.ts:675` reports a child beyond a stationary edge or outside an inactive axis. `calculateNodeResize` at `packages/core/src/domain/flow-runtime.schema.ts:704` intersects these minima with the existing external bounds. Empty intersections report a bounds issue. Hosts reject those candidates.

The returned child compensation is the inverse actual parent movement. Each host includes every direct child's compensated local position in one `NodeBoundsChange`. `applyNodeBoundsChange` at `packages/core/src/domain/flow-runtime.schema.ts:906` applies parent position, size, and child positions atomically. Children never scale.

## Conformity and deviations

**Conforming design intent:** pinned `packages/system/src/xyresizer/XYResizer.ts:202` captures direct constrained-child extents and `packages/system/src/xyresizer/XYResizer.ts:246` passes them to the resize calculation. Directional child clamps appear at `packages/system/src/xyresizer/utils.ts:165`. Flow's bounded browser and core tests establish its own containment and compensation behavior.

**Intentionally different:** Flow retains its public rectangle API, 40 by 24 host minima, final atomic proposals, and explicit rejection of infeasible bounds. Only `extent: 'parent'` contributes child constraints. This fix adds no `expandParent`, origin, or aspect-ratio behavior. Vue excludes transient resized-parent samples and Foldkit buffers them outside accepted measurement state to preserve accepted-state ownership.

**Unverified:** reference runtime parity, additional browsers, arbitrary external CSS changes during an active gesture, and OpenTelemetry delivery to a collector. Stale-generation receipt selection and newer same-generation handle retention are verified at the reducer boundary. The browser after-release case deliberately controls actual CSS box timing. The browser test boundary is local Chromium with the repository's native pointer/keyboard tooling and explicit production-observer attachment. The pinned reference is source evidence, not a side-by-side parity run.
