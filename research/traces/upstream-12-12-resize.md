# Resize lifecycle at the 12.12.0 pin

## Upstream production path

React's public `NodeResizeControl` constructs `XYResizer` with store-owned geometry and callbacks (`packages/react/src/additional-components/NodeResizer/NodeResizeControl.tsx:71`). The shared resizer starts its drag at `packages/system/src/xyresizer/XYResizer.ts:139`. It captures the last accepted previous values, adjusted start position, and child-local positions before mutating a proposal (`packages/system/src/xyresizer/XYResizer.ts:257`). When `shouldResize` rejects it, the handler restores those values (`packages/system/src/xyresizer/XYResizer.ts:333`). The end handler always publishes the accepted rectangle, even without an accepted drag step (`packages/system/src/xyresizer/XYResizer.ts:347`).

The input is a resize drag event and node geometry. Internal mutable state includes previous bounds, starting bounds, and child positions. Accepted changes become position and dimension changes through `NodeResizeControl`, which calls the store (`packages/react/src/additional-components/NodeResizer/NodeResizeControl.tsx:160`). The store publishes `onNodesChange` (`packages/react/src/store/index.ts:265`). In the controlled reference fixture, `useNodesState` applies those changes (`packages/react/src/hooks/useNodesEdgesState.ts:61`). `NodeWrapper` then renders the accepted transform, style, and inline dimensions (`packages/react/src/components/NodeWrapper/index.tsx:203`). Rejected changes do not reach the change callback. The public callback signatures are unchanged. The companion `onEnd` now always reaches `NodeResizeControl`, whose completion handler emits a `dimensions` change with `resizing: false` even without changed geometry (`packages/react/src/additional-components/NodeResizer/NodeResizeControl.tsx:162`, `packages/react/src/additional-components/NodeResizer/NodeResizeControl.tsx:172`).

## Flow production paths

The browser control starts a core immutable `FlowNodeResizeSession` through `startFlowNodeResize` (`packages/core/src/domain/flow-node-resizer.ts:380`). `stepFlowNodeResize` computes a proposed session and optional step, including bounds, adjusted start, and child compensation (`packages/core/src/domain/flow-node-resizer.ts:417`). The proposal leaves the input session intact.

Vanilla's public `createFlowNodeResizer` registers its controls with the controller (`apps/vanilla/src/node-resizer.ts:204`). The node's pointerdown listener resolves a resize control and starts the registered session (`apps/vanilla/src/mount-flow.ts:9286`, `apps/vanilla/src/mount-flow.ts:9146`). The registered control calls the core calculation on pointer movement, consults `shouldResize`, and adopts the proposed session only after acceptance (`apps/vanilla/src/mount-flow.ts:7522`, `apps/vanilla/src/mount-flow.ts:7540`). The candidate feeds its transient node and child geometry; release publishes the accepted `node-bounds` change and calls the registered end callback (`apps/vanilla/src/mount-flow.ts:9015`). A no-motion or fully vetoed gesture still calls that callback with the starting bounds. The preview writes accepted width and height to the DOM and updates child positions and measurements (`apps/vanilla/src/mount-flow.ts:8940`).

Vue's public `FlowNodeResizeControl` binds DOM pointerdown, move, and up directly to its lifecycle handlers (`packages/vue/src/node-resizer.ts:477`). It converts its pointer to flow coordinates and calculates a proposal (`packages/vue/src/node-resizer.ts:390`). It adopts the session after the veto callback and commits accepted bounds and child positions before emitting `resize` (`packages/vue/src/node-resizer.ts:403`). The commit publishes a `node-bounds` change (`packages/vue/src/node-resizer.ts:295`), and `FlowCanvas` derives the node's DOM left, top, width, and height from accepted geometry (`packages/vue/src/flow-canvas.ts:9116`). Release already emits `resizeEnd` from the session's previous accepted rectangle (`packages/vue/src/node-resizer.ts:432`).

Foldkit's public `createFoldkitNodeResizer` creates controls for a node view (`packages/foldkit/src/node-resizer.ts:334`). The graph DOM decoder reads the control attributes and creates a `GestureDown` message (`packages/foldkit/src/graph.ts:5161`). The Runtime sends these gesture messages to the graph reducer. `stepResizer` returns the unchanged model on a veto, preserving both session and preview (`packages/foldkit/src/graph.ts:2957`). Accepted preview geometry becomes the semantic release update. Application publication emits `onResizeEnd` whenever a resizer session finishes, including zero accepted steps (`packages/foldkit/src/application.ts:1934`). `selectLiveModel` applies the accepted preview to render geometry (`packages/foldkit/src/graph.ts:2758`), and the node view emits dimensions as CSS pixels (`packages/foldkit/src/graph.ts:7452`). Existing named telemetry and callback error boundaries continue to own lifecycle and failures; no pointer-move logs are added.

## Test paths

The React reference route mounts a new fixture through the real published 12.12.0 component (`apps/react-reference/main.tsx:176`, `apps/react-reference/resize-regression.tsx:32`). It is separate from imported upstream tests. The authored reference regression drives real mouse press, left-edge moves, and release (`apps/react-reference/e2e/resize-regression.e2e.ts:18`). It compares complete callback records and literal final widths.

Host regressions drive the public controls in their existing browser fixtures (`apps/vanilla/e2e/final-wiring.e2e.ts:1311`, `apps/vue/e2e/final-wiring.e2e.ts:885`, `apps/foldkit/e2e/node-resizer.e2e.ts:275`). Each tests no motion, a fully vetoed gesture, and accepted motion followed by a veto. They compare final callback rectangles and committed geometry. Foldkit also asserts release publication through its real application update in Vitest (`packages/foldkit/src/canvas-options.test.ts:438`).

## Conformity and deviations

- Conforming within the 12 authored Chromium release cases: a started resize ends with the last accepted rectangle, including no motion and full veto. All three cases pass in Vanilla, Vue, Foldkit, and React 12.12.0. The final focused verifier also passes its preserved scope. [Plan 151](../../plans/151-upstream-delta.md) records the exact commands, baseline failures, expected ledger failures, and full-profile result.
- Intentionally different: core returns an immutable proposed session. Hosts reject that value instead of rolling mutable fields back. Both approaches preserve previous bounds, adjusted start, and child positions.
- Conforming successful-release observer boundary from Plan 152: a shared completion projection now publishes the literal `dimensions` notification with `resizing: false` and last accepted dimensions in both ownership modes, even without changed geometry. The locked four-host proof passes 61 cases. [Resize completion node changes](resize-completion-node-changes.md) records the 24 matching observer cases, duplicate-end checks, Flow callback-failure guards, and the intentional node-removal cancellation difference. Whole-library cancellation parity remains unverified.
- Unverified beyond this release boundary: cancellation, native touch and capture behavior, all combinations of parent expansion and constrained children, and whole-library resize parity. Existing broader host tests remain separate evidence. Historical upstream captures retain their original release metadata.
