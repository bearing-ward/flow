# Gesture and resize lifecycle

## Reference paths

The React node wrapper is the browser entry for keyboard movement. On arrow keys for a selected draggable node it prevents default scrolling and delegates to `moveSelectedNodes` (`packages/react/src/components/NodeWrapper/index.tsx:128-160`). That helper reads the current store lookup, computes absolute movement and extents, updates internal positions, then calls `updateNodePositions` (`packages/react/src/hooks/useMoveSelectedNodes.ts:16-65`). Focus may call `getNodesInside` and `setCenter` when auto-pan-on-focus is enabled and the node is outside the viewport (`packages/react/src/components/NodeWrapper/index.tsx:163-181`). Pointer drag is wired through `XYDrag`; its movement path computes transformed pointer positions, aborts on multi-touch or node removal, checks the client-space drag threshold, updates node positions, and starts auto-pan (`packages/system/src/xydrag/XYDrag.ts:324-363`). Auto-pan schedules itself with `requestAnimationFrame` and applies `panBy` before updating node positions (`packages/system/src/xydrag/XYDrag.ts:232-256`). Drag end commits final positions and stops the scheduled frame (`packages/system/src/xydrag/XYDrag.ts:364-400`).

Resize begins in React's `NodeResizeControl`, which instantiates `XYResizer` and supplies node lookup, transform, snapping and pane geometry (`packages/react/src/additional-components/NodeResizer/NodeResizeControl.tsx:62-100`). Its callback translates resize and child-position changes into store node changes (`packages/react/src/additional-components/NodeResizer/NodeResizeControl.tsx:85-115`). The resizer captures current measured dimensions and local position, pointer coordinates, parent extent and direct child positions at start (`packages/system/src/xyresizer/XYResizer.ts:141-214`); subsequent drag computes new dimensions and child positions (`packages/system/src/xyresizer/XYResizer.ts:219-310`). The named browser tests cover node drag and keyboard movement (`tests/playwright/e2e/nodes.spec.ts:94-168`); no resize-specific test was found in the imported Playwright suite, so reference resize output is **Unverified** here.

## Flow paths

### Production path

The user entry is the selected node's lower-right button created by `renderNodeResizeHandle`; the node wrapper owns the pointerdown listener (`apps/vanilla/src/mount-flow.ts:338-353`, `apps/vanilla/src/mount-flow.ts:2091-2139`, `apps/vanilla/src/mount-flow.ts:2395-2400`). The host starts a `node-resize` discriminated session with the pointer id, pointer origin in flow coordinates, and initial dimensions chosen from the host measurement before declared size (`packages/core/src/domain/flow-runtime.schema.ts:95-125`, `apps/vanilla/src/mount-flow.ts:2106-2118`). The interaction collection validates unique pointer ownership, and resize is a separate session variant from node drag and pane pan.

Pointer movement converts screen input with `pointerInFlow`, computes a pure lower-right size change, and previews the wrapper dimensions. The host updates transient measurements and recomputes incident edge geometry from measured handles (`packages/core/src/domain/flow-runtime.schema.ts:287-306`, `apps/vanilla/src/mount-flow.ts:2032-2047`). Completion releases pointer capture and publishes one `node-size` change only when dimensions changed (`apps/vanilla/src/mount-flow.ts:2050-2089`). The change schema and `applyNodeSizeChange` modify only declared `FlowNode.size`; the host applies it in uncontrolled mode and restores the authoritative declared size in controlled mode until the caller acknowledges it (`packages/core/src/domain/flow-runtime.schema.ts:287-305`, `packages/core/src/domain/flow-runtime.schema.ts:360-387`, `apps/vanilla/src/mount-flow.ts:1747-1765`). Cancellation restores the prior declared or measured size and releases capture without publishing a semantic change (`apps/vanilla/src/mount-flow.ts:1320-1363`). Escape, blur, pointercancel, lost capture, node removal, and destroy route through that cleanup (`apps/vanilla/src/mount-flow.ts:2871-2925`, `apps/vanilla/src/mount-flow.ts:3825-3835`).

The selected node button is keyboard-focusable and labeled; CSS places it at the lower-right corner and uses a resize cursor (`apps/vanilla/src/mount-flow.ts:338-353`, `apps/vanilla/src/style.css:156-173`). Resizing does not change node position, start node drag, or start pane pan. The first contract has minimum dimensions 40 by 24 flow units, scales pointer deltas through the active viewport zoom, and stores only declared dimensions in the document; live measurements remain in host state (`packages/core/src/domain/flow-runtime.schema.ts:295-305`, `apps/vanilla/src/mount-flow.ts:2032-2047`).

### Test path

Core tests decode the resize session, reject invalid size input, enforce minimum dimensions, apply size without changing position, and reject non-finite results (`packages/core/src/domain/flow-runtime.schema.test.ts:36-50`, `packages/core/src/domain/flow-runtime.schema.test.ts:94-105`). Persistence tests encode and decode declared node sizes while excluding selection (`packages/core/src/domain/flow-persistence.test.ts:8-29`). Browser tests mount the vanilla host with an incident edge, resize at zoom 1 and 2 in controlled and uncontrolled modes, check preview path updates and single final changes, then exercise Escape, blur, pointercancel, capture loss, node removal, and destroy (`apps/vanilla/e2e/advanced-gestures.e2e.ts:167-207`, `apps/vanilla/e2e/advanced-gestures.e2e.ts:333-403`).

The pinned reference resize path remains traced above, but its resize browser output is **Unverified** because the imported browser suite has no resize-specific case. Flow's minimum dimensions, selected-only lower-right handle, and cancellation behavior are covered by Flow tests; no direct parity test against the pinned reference is claimed.

### Movement extension

`FlowNodeSchema` declares optional `draggable` and nonempty `ariaDescription`; persistence retains both while selection remains transient (`packages/core/src/domain/flow.schema.ts:68-80`, `packages/core/src/domain/flow-persistence.ts:25-43`). Core `moveSelectedNodes` omits hidden, descendant-selected, and locked nodes; `applyNodePositionChange` and `applyNodePositionsChange` reject locked targets (`packages/core/src/domain/flow-runtime.schema.ts:767-809`, `packages/core/src/domain/flow-runtime.schema.ts:822-867`). The host filters the selected drag set the same way, retains locked-node selection/focus, and reconciles `aria-description` on keyed updates (`apps/vanilla/src/mount-flow.ts:283-322`, `apps/vanilla/src/mount-flow.ts:753-760`, `apps/vanilla/src/mount-flow.ts:2235-2294`).

For active node drag, the host records the latest canvas pointer, requests a scoped frame through `FlowBrowserService`, pans through `panViewport` and the configured extent constraint, then reprojects that stationary pointer through the new viewport before recalculating transient node positions and incident edges (`apps/vanilla/src/flow-browser.ts:19-49`, `packages/core/src/domain/flow-runtime.schema.ts:601-608`, `apps/vanilla/src/mount-flow.ts:1275-1318`, `apps/vanilla/src/mount-flow.ts:2279-2317`). Completion, cancellation, node removal, and destroy close the frame scope; the keyboard path instead pans once to reveal the moved focused node and restores focus through the browser capability (`apps/vanilla/src/mount-flow.ts:1320-1355`, `apps/vanilla/src/mount-flow.ts:3506-3595`).

Browser tests cover locked mixed-selection pointer and keyboard movement, accessible description updates and removal, edge auto-pan and cancellation by Escape, blur, pointercancel, capture loss, node removal, and destroy; they also cover viewport extent clamping, edge preview and completion at zoom 2, controlled cancellation, and one-shot keyboard reveal (`apps/vanilla/e2e/movement-slices.e2e.ts:111-280`). These tests exercise the Flow contract, not direct reference parity.

## Conformity and deviations

- **Conforms:** the first Flow resize contract keeps graph state serializable, uses host measurements only as transient geometry, and translates pointer deltas through viewport zoom. Flow test boundary: core resize and persistence tests plus the vanilla resize browser cases above; no direct parity test against the pinned reference.
- **Intentionally different:** Flow currently exposes one lower-right handle on selected nodes, a 40 by 24 minimum, and does not resize multiple nodes, adjust child coordinates, expand parents, or lock aspect ratio. The reference resizer considers parent extent and direct child positions.
- **Unverified:** reference resize browser output remains unverified because no imported resize-specific browser case was found. Flow's broader resize contract remains open: `research/PROGRESS.md:116` is unchecked because this slice establishes only the bounded lower-right behavior and excludes other handles and hierarchy semantics.
- **Conforms:** Flow node drag auto-pans with a scoped frame, recomputes positions from the current viewport, and stops on cancellation. Keyboard movement reveals the focused node with a single viewport adjustment. Flow tests cover zoom 1 and 2 and frame cancellation; viewport extent clamping follows the existing pan constraint.
- **Intentionally different:** locked nodes are omitted from a mixed selected group while movable members retain their relative offsets. Descriptions use the native `aria-description` attribute and keep `aria-label` as the accessible name.
- **Unverified:** native pointer concurrency and two-contact pinch cancellation remain unverified in Playwright because they require native multi-pointer capture. The movement tests do not claim those gesture cells.
