## Pinned public and production path

`useNodesState` owns React state and applies node changes through `applyNodeChanges`; the pinned filename is `useNodesEdgesState.ts`, not `useNodesState.ts` (`packages/react/src/hooks/useNodesEdgesState.ts:51`, `packages/react/src/hooks/useNodesEdgesState.ts:59`, `packages/react/src/hooks/useNodesEdgesState.ts:61`). It performs no style-to-measurement mapping.

The imperative public `useReactFlow().updateNode` queues a node update by merging the supplied patch with the previous node (`packages/react/src/hooks/useReactFlow.ts:71`, `packages/react/src/hooks/useReactFlow.ts:97`, `packages/react/src/hooks/useReactFlow.ts:106`). `BatchProvider` processes that queue, diffs its nodes against the lookup, and invokes `onNodesChange` (`packages/react/src/components/BatchProvider/index.tsx:30`, `packages/react/src/components/BatchProvider/index.tsx:47`, `packages/react/src/components/BatchProvider/index.tsx:51`, `packages/react/src/components/BatchProvider/index.tsx:66`). The diff emits `item` itself for a changed object (`packages/react/src/utils/changes.ts:296`, `packages/react/src/utils/changes.ts:300`). Thus the replacement contains the previously measured `100x40`, alongside the new `200x100` style. It cannot already know the new DOM measurement.

Applying a replace change shallow-copies the item (`packages/react/src/utils/changes.ts:70`). React store `setNodes` adopts the resulting user nodes, copying their measured axes into a separate internal object (`packages/react/src/store/index.ts:120`, `packages/system/src/utils/store.ts:162`). `NodeWrapper` renders the node, its observer reports DOM dimensions, and system measurement emits a dimensions change (`packages/react/src/components/NodeWrapper/index.tsx:205`, `packages/react/src/components/NodeWrapper/useNodeObserver.ts:31`, `packages/system/src/utils/store.ts:441`, `packages/system/src/utils/store.ts:485`). Applying that dimensions change replaces `element.measured` with a fresh object, rather than mutating the earlier replacement item's measurement (`packages/react/src/utils/changes.ts:126`, `packages/react/src/utils/changes.ts:128`). The settled node becomes `200x100`; the captured replacement stays `100x40`.

## Conformity and deviations

- **Conforming:** Flow preserves the old measurement in the emitted replacement and accepts the new size through a later dimensions event. Core and the executed pinned utility path support the same payload ownership. Browser runs exercise the unchanged upstream case in all three hosts as an expected failure.
- **Conforming at the retained-payload boundary:** The React browser replay now confirms the same old-measurement snapshot as Flow. UP-128-044 is a broken pinned upstream test, not an intentional production difference. Its assertion remains unchanged, apart from correcting the port's extra Flow metadata fields to the original expected object.
- **Unverified:** Svelte replacement-event equivalence remains untested. The shared React browser case and the three Flow cases cover this replacement and later dimensions sequence; they do not establish framework-wide parity or OpenTelemetry collector delivery.
