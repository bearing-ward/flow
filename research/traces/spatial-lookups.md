# Spatial lookups and viewport culling

## Reference: spatial lookup to output

The public React instance exposes `getNodesBounds`; its hook reads the current `nodeLookup` and `nodeOrigin`, then delegates to the system geometry helper (`packages/react/src/hooks/useReactFlow.ts:276-279`). The helper resolves each supplied id or node through that lookup, skips stale ids, converts resolved node boxes, and returns a zero rectangle when no nodes resolve (`packages/system/src/utils/graph.ts:192-235`). `getNodesInside` accepts the runtime lookup, a screen-space rectangle and the viewport transform, converts the rectangle into flow coordinates, then scans lookup values. It uses measured, declared or initial dimensions, absolute positions, hidden/selectable flags, initial-handle state and dragging state when deciding membership (`packages/system/src/utils/graph.ts:264-303`).

For viewport rendering, `useVisibleNodeIds` supplies the viewport rectangle and current transform to `getNodesInside` (`packages/react/src/hooks/useVisibleNodeIds.ts:8-14`). `NodeRenderer` maps those ids into keyed `NodeWrapper` elements in the rendered node container (`packages/react/src/container/NodeRenderer/index.tsx:38-97`). Selection is a separate public browser path: `Pane` commits pointer-moved selection rectangles against `nodeLookup` and calls `getNodesInside` with the configured partial/full mode and nonselectable exclusion (`packages/react/src/container/Pane/index.tsx:187-225`). Its selection auto-pan uses repeated animation frames and recomputes selection after a successful pan (`packages/react/src/container/Pane/index.tsx:259-284`).

The reference browser coverage exercises real node dragging, non-draggable nodes, custom drag handles, and selection gestures (`tests/playwright/e2e/nodes.spec.ts:94-168`, `tests/playwright/e2e/pane.spec.ts:263-315`). No test in the pinned artifact directly names `getNodesBounds`; its empty/unresolved-id and nested-position cases are therefore **unverified at the test boundary**.

## Flow: public host to geometry and rendered output

The browser-facing `mountFlow` function decodes input, creates the host and returns controller methods (`apps/vanilla/src/mount-flow.ts:3748-3791`). Host reconciliation constructs a `FlowGraphView` from the document, host measurements and preview positions. When `renderOnlyVisible` is enabled, it converts the viewport to flow coordinates, selects visible edges, retains their endpoints, and includes nodes that are unmeasured, intersecting, or required by a visible edge (`apps/vanilla/src/mount-flow.ts:1327-1371`). The reconciliation then creates/removes keyed DOM entries from that visible set (`apps/vanilla/src/mount-flow.ts:1373-1381`). Rectangle selection uses the same graph inputs but delegates to the separate `selectionInRect` contract (`apps/vanilla/src/mount-flow.ts:2281-2295`). `createFlowGraph` resolves child-local positions to absolute positions and applies measurement-over-declared-over-fallback sizing (`packages/core/src/domain/flow-graph.ts:25-68`); bounds/intersection use the graph's ordered nodes (`packages/core/src/domain/flow-graph.ts:125-145`).

Fit-view is exposed on the same controller and calls `fitViewportToNodes` (`apps/vanilla/src/mount-flow.ts:3581-3600`, `apps/vanilla/src/mount-flow.ts:3769-3777`). The core fit operation builds a graph with current measurements and preview positions, then uses `graphBounds`; an empty or fully hidden selection returns the current viewport because Flow bounds are `undefined` (`packages/core/src/domain/flow-fit-view.ts:57-67`). This differs from the reference helper's zero rectangle return for an empty/unresolved input (`packages/system/src/utils/graph.ts:202-235`).

Flow's core tests cover nested absolute positions, measurements, hidden inheritance, bounds, intersections and directed edge lookup (`packages/core/src/domain/flow-graph.test.ts:10-165`). The browser culling case exercises a public `mountFlow`, viewport updates, mounted DOM membership and visible crossing-edge endpoints at 1,000 offscreen nodes (`apps/vanilla/e2e/next-slices.e2e.ts:278-321`). It verifies semantic visibility, not a latency limit.

## Conformity and deviations

- **Conforms:** both systems use runtime dimensions and absolute positions for viewport intersection. Flow test boundary: pure graph tests plus mounted vanilla browser culling; no cross-running against the reference, so this is a contract comparison rather than a parity claim.
- **Deviates:** Flow's empty graph bounds are `undefined`, causing fit-view to preserve the current viewport; the reference helper returns `{ x: 0, y: 0, width: 0, height: 0 }`. Flow test boundary: empty graph bounds unit assertion; no empty fit-view browser assertion.
- **Unverified:** Flow has no spatial index and currently scans ordered graph nodes for intersections and selection. Benchmark coverage measures these specific core operations only; it does not characterize every host reconciliation, edge layout, or DOM cost.
