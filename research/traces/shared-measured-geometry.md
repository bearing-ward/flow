# Shared measured geometry and readiness

## Production entry points and current paths

The vanilla public mount decodes caller input before building its runtime in `apps/vanilla/src/mount-flow.ts`. That runtime owns `entries` and a `Map<NodeId, MeasuredNode>` beside the accepted document (`apps/vanilla/src/mount-flow.ts:934-938`). The browser adapter owns `ResizeObserver` acquisition and converts DOM dimensions into numeric `ElementSize` values (`apps/vanilla/src/flow-browser.ts:132-163`). The observer callback reveals the rendered element, associates it with the currently accepted node, stores the measurement, updates graph positions and edge geometry, then reconciles visible content (`apps/vanilla/src/mount-flow.ts:1492-1525`). Declared size changes also trigger a fresh DOM read and edge reconciliation (`apps/vanilla/src/mount-flow.ts:3205-3220`). Fit consumes a measurement map independently from the saved graph and falls back to declared/default dimensions (`packages/core/src/domain/flow-fit-view.ts:12-24`).

The Vue entry is `FlowCanvas` in `packages/vue/src/flow-canvas.ts`. It retains node elements, host-local renderer generations, and handle measurements in adapter-local maps/refs (`packages/vue/src/flow-canvas.ts:447-493`). Handle centers are measured relative to node bounds and normalized by current zoom (`packages/vue/src/flow-canvas.ts:493-553`). Its observer collects node measurements by map lookup and applies a batch once per observer delivery (`packages/vue/src/flow-canvas.ts:555-604`); lifecycle watches prune removed measurements, while node refs stage generation registration and handle observation (`packages/vue/src/flow-canvas.ts:607-677`). Explicit refresh batches current measurements and settles after unmount (`packages/vue/src/flow-canvas.ts:929-1000`).

Foldkit's app owns a root-scoped `MutationObserver` and `ResizeObserver`; it reads each rendered node's bounding box and sends only numeric measurements through typed `HostAction.MeasureNode` messages (`apps/foldkit/src/main.ts:113-160`, `apps/foldkit/src/application.ts:29-35`). The graph Model stores `FlowMeasurementStateSchema` separately from the accepted document (`apps/foldkit/src/graph.ts:52-62`), applies and prunes measurements on numeric messages/document replacement (`apps/foldkit/src/graph.ts:433-448`), and exposes app selectors for internal-node snapshots and readiness (`apps/foldkit/src/graph.ts:137-144`). `SnapshotRequest` returns the internal-node projection and initialized status, while measured actions return correlated `MeasurementResultSchema` values through a typed outbound port (`apps/foldkit/src/application.ts:39-91`, `apps/foldkit/src/application.ts:243-280`). Culling and rendered bounds use measured size when present and declared/default fallback otherwise (`apps/foldkit/src/graph.ts:535-585`). The playground toggle changes a real node box and handle offset, then awaits the correlated measurement result (`apps/foldkit/src/main.ts:494-558`). Foldkit browser tests assert live bounds, readiness/internal-node queries, disposed request settlement, and observer disconnect with no late callbacks after DOM changes (`apps/foldkit/e2e/measured-geometry.e2e.ts:17-172`, `apps/foldkit/e2e/measured-geometry.e2e.ts:174-246`).

## Shared measurement contract

Measurements use unscaled local graph units. A measured node's origin is its top-left; its position follows the graph rule: root positions are graph-local and child positions are parent-local. Derived absolute positions are read-only projections. Handle identity is `(nodeId, handleId)` and records its declared side plus measured node-local center and dimensions. Declared size remains caller-authored intent and fallback geometry; measured size is host runtime state.

The exposed `measurementStatus` enum contains only `unmeasured`, `measured`, and `hidden` (`packages/core/src/domain/flow-measurement.schema.ts:11-21`). Culling and removal are lifecycle conditions, not enum values. A culled node is not mounted and is excluded from readiness; its last measurement can remain available for geometry, or declared size can provide fallback geometry if it has never been measured. A removed node is absent from internal-node queries and its measurements are pruned. A zero width or height is a valid measurement and does not mean unmeasured. Hidden nodes are excluded from the default readiness result; including hidden nodes makes them block readiness until they are measured. Every observation carries a generation token; results from a previous renderer/node generation are ignored after replacement or removal.

Changing declared size never writes measured data into the document. Measurement updates advance a separate measurement revision and may notify geometry subscribers, but never create edit proposals, accepted document snapshots, or saved-document changes. `getInternalNode` returns an immutable snapshot of the current accepted node, derived absolute position, dimensions and measurement status. `updateNodeInternals(ids)` requests one scheduled measurement/handle refresh for each current rendered node. Missing IDs return an explicit missing result; disposed hosts settle requests with a disposed result. Repeated requests coalesce per animation frame and do not retry indefinitely.

| Case | Geometry/readiness state | Notification or request result |
| --- | --- | --- |
| Initial rendered node | `unmeasured`; declared size may supply fallback geometry | Readiness false until valid observation |
| Valid observer result | `measured`, including zero dimensions | Measurement revision only; no document proposal or accepted snapshot |
| Hidden node | `hidden`; omitted from default readiness | Including-hidden readiness waits for measurement |
| Viewport culled node | Lifecycle condition; enum status remains `measured` if a measurement exists, otherwise `unmeasured` | Not mounted and excluded from readiness; declared size supplies fallback if unmeasured |
| Removed/replaced node | Removed nodes no longer have an enum projection; measurements are pruned | Prior generation invalid; stale delivery ignored and query returns missing |
| Explicit internals refresh | Current rendered node re-read with current generation | Coalesced refresh result, geometry notification only |
| Disposed host | No active measurement lifecycle | Pending request settles disposed; no later observer/subscriber work |

## Tests and evidence boundary

The shared JSON fixture is decoded by `MeasuredGeometryContractSchema` and every case runs through actual host adapter APIs (`packages/conformance/src/index.ts`, `apps/shared-e2e/measured-geometry-contract.ts:13-18`, `apps/shared-e2e/measured-geometry-contract.ts:137-185`). Host E2E registrations use the vanilla controller, Vue `useFlow`, and Foldkit Runtime snapshot/action ports (`apps/vanilla/e2e/measured-geometry.e2e.ts`, `apps/vue/e2e/measured-geometry.e2e.ts`, `apps/foldkit/e2e/measured-geometry.e2e.ts`). Vanilla's public-controller browser case verifies real DOM-to-graph conversion at zoom 0.5 and 2, same-ID measurement isolation across two canvases, queued refresh settlement on destruction, and unchanged saved documents after measurement (`apps/vanilla/e2e/measured-geometry.e2e.ts:116-258`). Vue separately verifies queued refresh settlement on unmount and Foldkit verifies its disposed request and observer teardown (`apps/vue/e2e/measured-geometry.e2e.ts:76-104`, `apps/foldkit/e2e/measured-geometry.e2e.ts:64-172`). Browser assertions query production state and use live DOM bounds for resizing; the shared runner does not calculate observed measurements from fixture expectations.

Production browser assertions must read real bounding boxes and return observations from each host's actual public API. They must not use a test-only store or calculate observed values from fixture expectations. Saved-document compatibility remains version 1 and excludes all measurements (`docs/architecture.md:110-112`).
