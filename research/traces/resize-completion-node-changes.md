## React production path

The public `NodeResizer` renders `NodeResizeControl`. That control creates `XYResizer` with store-owned geometry at `packages/react/src/additional-components/NodeResizer/NodeResizeControl.tsx:71`. Real browser mouse input enters the d3 drag handlers at `packages/system/src/xyresizer/XYResizer.ts:139`. Accepted steps update previous bounds; a rejected step restores those bounds at `packages/system/src/xyresizer/XYResizer.ts:333`.

The drag end calls the public `onResizeEnd` before the internal `onEnd`, even without an accepted step, at `packages/system/src/xyresizer/XYResizer.ts:347`. The internal callback creates one `dimensions` delta with `resizing: false` and the last accepted width and height at `packages/react/src/additional-components/NodeResizer/NodeResizeControl.tsx:162`. It sends that unchanged delta to the store at `packages/react/src/additional-components/NodeResizer/NodeResizeControl.tsx:172`. The store applies it internally for default nodes and always calls `onNodesChange` at `packages/react/src/store/index.ts:265`. Controlled consumers apply the delta themselves. `NodeWrapper` renders the resulting node dimensions at `packages/react/src/components/NodeWrapper/index.tsx:203`.

The completion delta has no position or `setAttributes` member. It reports lifecycle state even when geometry is unchanged. Initial measurement notifications belong to a separate path and must settle before observing this gesture.

Node removal is an intentional cancellation-policy difference. Flow preserves those existing cancellation boundaries and suppresses post-removal completion. The shared removal tests cover both ownership modes and sessions before and after accepted movement. They prove Flow cancellation guards, not React node-removal parity. Whole-flow unmount suppresses completion in all hosts.

## Conformity and deviations

- Conforming successful completion: the 24 observer cases compare literal singleton completion batches across React and all three Flow hosts, with both ownership modes and all three gestures. Repeated release and capture-loss delivery do not duplicate the completion. The locked proof passes 61/61 cases: React 13 and 16 per Flow host. These counts include the separate teardown and callback-failure guards, which have the boundaries below.
- Conforming whole-flow unmount after a no-motion press: neither React nor Flow notifies completion after disposal. Flow also tests disposal after accepted movement; that extra Flow guard is not a reference parity claim.
- Intentionally different node-removal cancellation: React retains a late drag-end notification for a removed node. Flow preserves its existing owner-removal cancellation and suppresses that notification. The reason is that reconciliation already consumes the removed node's interaction owner. Vanilla, Vue, and Foldkit removal tests cover both ownership modes before and after accepted movement; the reference comparison observes no-motion removal in both modes. This is not node-removal parity.
- Intentionally different ownership and failure handling: core returns immutable resize proposals; Flow keeps atomic document geometry commits and isolates observer and end-callback failures. The six throwing-end tests prove that Flow still publishes completion once through its existing callback error boundaries. They do not claim React parity for thrown callbacks.
- Unverified beyond this boundary: native touch, live pointer cancellation, device behavior, broad constrained-parent combinations, and whole-library resize parity. Initial measurement changes and selection notifications remain separate observer paths. No OpenTelemetry delivery claim is made.
