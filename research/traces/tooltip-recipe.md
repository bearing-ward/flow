# Tooltip recipe trace

## Production paths

- **Vanilla:** `createFlowTooltip`, `FlowTooltip`, and `FlowTooltipOptions` are exported from the Vanilla package entry (`apps/vanilla/src/public.ts:92-94`). The helper creates plain-text tooltip content with `role="tooltip"`, associates it through `aria-describedby` while retaining any previous IDs, and shows it while the trigger is hovered/focused or the pointer is over the tooltip (`apps/vanilla/src/ui/tooltip.ts:26-51,53-100`). Pointer leave schedules a 100 ms delayed close; re-entry cancels that timer (`apps/vanilla/src/ui/tooltip.ts:57-81`). `destroy()` clears the timer, removes listeners, restores the trigger's prior `aria-describedby`, and removes the tooltip (`apps/vanilla/src/ui/tooltip.ts:101-120`). The production fixture composes two tooltips into a public `mountFlow` custom renderer and destroys/remounts the controller (`apps/vanilla/src/ui/tooltip-test.ts:14-60,63-97`).
- **Vue:** `FlowTooltip` is exported from `packages/vue/src/public.ts:3` and implemented as a native Vue `defineComponent` (`packages/vue/src/ui/tooltip.ts:1-92`). It creates a per-instance ID using Vue `useId`, merges/deduplicates existing `aria-describedby` references on the first slotted VNode, tracks pointer/focus visibility, and renders hidden tooltip text with `role="tooltip"` (`packages/vue/src/ui/tooltip.ts:10-24,26-50,53-89`). The production route is composed in `apps/vue/src/main.ts:242-315`; it decodes a graph document, renders two tooltips in a FlowCanvas custom node, and selects that recipe at `/ui-recipes/tooltip/` (`apps/vue/src/main.ts:285-315,1197-1201`).
- **Foldkit:** `createFoldkitTooltip`, `FoldkitTooltipMount`, and `FoldkitTooltipOptions` are exported from `packages/foldkit/src/public.ts:110-115`. The helper creates plain-text `role="tooltip"` content, preserves the trigger's existing description and input-ownership/tabindex attributes for teardown, associates and wraps the trigger, and toggles visibility from pointer/focus state (`packages/foldkit/src/ui/tooltip.ts:14-63,65-107`). Its idempotent destroy removes listeners and restores the original trigger and attributes (`packages/foldkit/src/ui/tooltip.ts:109-158`). The production route mounts a Runtime graph, watches for its trigger, attaches the helper using app-owned node data, and disposes the observer, tooltip, and Runtime on unmount (`apps/foldkit/ui-recipes/tooltip/main.ts:38-78,80-93,95-147`). The tooltip is positioned 8 px above the trigger, and an `::after` bridge spans that pointer transition area (`packages/foldkit/src/style.css:303-330`); the focused E2E now moves continuously in ten steps from trigger to tooltip and verifies it remains visible (`apps/foldkit/e2e/ui-recipes.e2e.ts:148-168`). Independent review approved this fix.

## Production test paths

- Vanilla `apps/vanilla/e2e/ui-recipes.e2e.ts:135-230` includes the Tooltip case and passed as a 3/3 focused suite. The Tooltip assertions cover two independently described triggers, tooltip role/text, hidden state, pointer/focus display and dismissal, movement from trigger onto the tooltip, unchanged viewport/node transform, destroy/remount, and reload.
- Vue `apps/vue/e2e/tooltip-recipe.e2e.ts:3-91` passed 1/1. It covers two distinct instances, preserved/deduplicated caller `aria-describedby` IDs, hidden state, hover/focus display and dismissal, tooltip role/text, stable node/canvas geometry, reload, and route teardown.
- Foldkit `apps/foldkit/e2e/ui-recipes.e2e.ts:98-179` passed 1/1 in the 3/3 focused suite; independent review approved the pointer bridge. It asserts tabindex and description association, hidden/revealed text, focus and hover, a ten-step pointer move from trigger to tooltip, unchanged canvas viewport, reload, and explicit teardown.

## Conformity and deviations

- **Conforming within tested outcomes:** All three hosts provide text descriptions associated with their triggers and show them on hover/focus; their focused tests cover dismissal, graph stability, and lifecycle boundaries. Foldkit's test specifically traverses the trigger-tooltip pointer bridge and remains visible.
- **Intentionally different:** Vanilla exposes an imperative DOM helper; Vue exposes a reactive component for one slotted trigger; Foldkit mounts native DOM around an existing trigger and returns explicit teardown. The hosts use distinct IDs, focus/pointer scheduling, and ownership restoration to fit their lifecycle models.
- **Unverified:** No pinned React runtime or current website comparison was run, so upstream markup, positioning, dismissal timing, and broader parity remain unverified. Packed-consumer coverage, broader screen-reader behavior, and cross-host equivalence are also unverified. The test boundary is the three focused local production suites/cases above.
