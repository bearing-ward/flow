# Shared node, edge, and handle renderer contract

Status: Flow behavior was exercised through Vanilla, Vue, and Foldkit production hosts. The pinned React Flow capture is from `0a1f9575b25679f2880175de8d3eae21aedde921` (`@xyflow/react` 12.11.6). It records only the custom-node, handle-refresh, custom-edge, marker, label, fallback, and built-in-path cases in `research/fixtures/renderer-contract-reference.json`; it is not a full API, example, accessibility, or visual-parity claim.

## Contract and ownership

`FlowNodeSchema` stores the node type key, JSON data, declared size, and serializable handles; `FlowEdgeSchema` stores the type key, edge path, label, JSON data, markers, and interaction width (`packages/core/src/domain/flow.schema.ts:48`, `packages/core/src/domain/flow.schema.ts:63`, `packages/core/src/domain/flow.schema.ts:86`, `packages/core/src/domain/flow.schema.ts:111`). Renderer functions, framework components, DOM nodes, measured dimensions, and active previews stay out of the document. `resolveEdgeHandles` resolves endpoint records, and `edgeAttachmentPosition` turns a host measurement and handle side into a graph-space endpoint (`packages/core/src/domain/flow-edge.schema.ts:28`, `packages/core/src/domain/flow-edge.schema.ts:37`, `packages/core/src/domain/flow-edge.schema.ts:55`). Core provides straight, Bezier, simple-Bezier, step, smooth-step, and label-anchor calculations (`packages/core/src/domain/flow-edge.schema.ts:78`, `packages/core/src/domain/flow-edge.schema.ts:110`, `packages/core/src/domain/flow-edge.schema.ts:131`, `packages/core/src/domain/flow-edge.schema.ts:143`, `packages/core/src/domain/flow-step-edge.schema.ts:230`, `packages/core/src/domain/flow-step-edge.schema.ts:237`).

Each host selects registries from host configuration by the node or edge `type`; it never writes callbacks into the saved document. Missing and unknown registrations use the host's default renderer. A node ID keys rendered identity. Updating data retains a same-type renderer; changing type replaces that renderer; removing a node or edge releases its host resources. Handles remain declarative IDs and sides in the document, while the host observes actual handle geometry and recomputes incident edge endpoints.

## Vanilla production path

The public JavaScript entry is `mountFlow` (`apps/vanilla/src/public.ts:1`, `apps/vanilla/src/public.ts:21`). It decodes mount options and the incoming document, then supplies the callback registries separately to `createFlowHost` (`apps/vanilla/src/mount-flow.ts:6775`, `apps/vanilla/src/mount-flow.ts:6780`, `apps/vanilla/src/mount-flow.ts:6784`, `apps/vanilla/src/mount-flow.ts:6786`). `FlowNodeRenderer` owns `update` and `destroy`; `FlowEdgeRenderer` may derive custom path geometry and returns a lifecycle instance (`apps/vanilla/src/mount-flow.ts:367`, `apps/vanilla/src/mount-flow.ts:441`, `apps/vanilla/src/mount-flow.ts:464`).

The controller creates a keyed node wrapper, selects `nodeRenderers[node.type ?? 'default']`, and renders the fallback label when no renderer is registered (`apps/vanilla/src/mount-flow.ts:3652`, `apps/vanilla/src/mount-flow.ts:3664`). Reconciliation calls `update` for the existing same-type instance; a renderer type change destroys the old instance and mounts the replacement (`apps/vanilla/src/mount-flow.ts:3171`, `apps/vanilla/src/mount-flow.ts:3178`, `apps/vanilla/src/mount-flow.ts:3182`, `apps/vanilla/src/mount-flow.ts:3188`). Handle elements are created from declared handle data and measured against their containing node; the edge renderer resolves both handles, derives measured endpoints, and selects the requested core path (`apps/vanilla/src/mount-flow.ts:766`, `apps/vanilla/src/edge-renderer.ts:120`, `apps/vanilla/src/edge-renderer.ts:211`, `apps/vanilla/src/edge-renderer.ts:250`, `apps/vanilla/src/edge-renderer.ts:262`). It paints SVG paths, hit paths, and host-scoped markers, while a host-owned HTML label layer tracks the path's graph-space label anchor (`apps/vanilla/src/edge-renderer.ts:47`, `apps/vanilla/src/edge-renderer.ts:84`, `apps/vanilla/src/edge-renderer.ts:346`, `apps/vanilla/src/edge-renderer.ts:512`). The playground registers both a custom node and custom edge geometry (`apps/vanilla/src/main.ts:392`, `apps/vanilla/src/main.ts:424`).

## Vue production path

The reusable entry exports `FlowCanvas` from `@flow/vue` (`packages/vue/src/public.ts:1`). Its `nodeTypes` and `edgeTypes` registries are host props; the previous single-component props remain available as fallback before the built-in default (`packages/vue/src/flow-canvas.ts:239`, `packages/vue/src/flow-canvas.ts:243`, `packages/vue/src/flow-canvas.ts:247`, `packages/vue/src/flow-canvas.ts:251`, `packages/vue/src/flow-canvas.ts:1353`, `packages/vue/src/flow-canvas.ts:1564`). The keyed wrapper receives node content, and declared handles are rendered as framework-owned buttons (`packages/vue/src/flow-canvas.ts:1357`, `packages/vue/src/flow-canvas.ts:1362`). The resize observer updates host measurement state; edge rendering resolves each endpoint against measured handles and calls the same core path functions before selecting a registered edge visual or fallback (`packages/vue/src/flow-canvas.ts:571`, `packages/vue/src/flow-canvas.ts:1451`, `packages/vue/src/flow-canvas.ts:1478`, `packages/vue/src/flow-canvas.ts:1490`, `packages/vue/src/flow-canvas.ts:1572`, `packages/vue/src/flow-canvas.ts:1583`). Marker IDs include the canvas ID, and definitions live in that canvas's SVG (`packages/vue/src/flow-canvas.ts:274`, `packages/vue/src/flow-canvas.ts:1412`). The label resolver uses measured endpoint positions with core `edgeLabelPosition`, or a schema-validated `edge.data.labelAnchor`; it suppresses labels when the edge or either endpoint is hidden (`packages/vue/src/flow-canvas.ts:1626`, `packages/vue/src/flow-canvas.ts:1629`, `packages/vue/src/flow-canvas.ts:1642`, `packages/vue/src/flow-canvas.ts:1675`). Labels are HTML children of the canvas-owned viewport overlay (`packages/vue/src/flow-canvas.ts:1687`, `packages/vue/src/flow-canvas.ts:1868`).

## Foldkit production path

The app entry calls `createProgram` with a renderer registry held outside `Model` (`apps/foldkit/src/main.ts:108`, `apps/foldkit/src/main.ts:136`). `createProgram` creates the `Graph.makeView` closure and an instance-specific marker scope; callbacks are supplied through this closure, not serialized into Foldkit state (`packages/foldkit/src/application.ts:343`, `packages/foldkit/src/application.ts:350`, `packages/foldkit/src/application.ts:352`). The graph view uses node IDs as keys, passes `FlowNode` values to the optional node view, and uses the label fallback when no view is registered (`packages/foldkit/src/graph.ts:615`, `packages/foldkit/src/graph.ts:620`, `packages/foldkit/src/graph.ts:849`, `packages/foldkit/src/graph.ts:891`, `packages/foldkit/src/graph.ts:897`).

For edges, the view combines host measurements or declared dimensions with core endpoint/path/label geometry, defaulting omitted `edge.path` to `straight`, then passes the resulting path, label position, and scoped marker IDs to the optional edge view (`packages/foldkit/src/graph.ts:689`, `packages/foldkit/src/graph.ts:702`, `packages/foldkit/src/graph.ts:712`, `packages/foldkit/src/graph.ts:728`, `packages/foldkit/src/graph.ts:731`, `packages/foldkit/src/graph.ts:747`, `packages/foldkit/src/graph.ts:928`, `packages/foldkit/src/graph.ts:936`, `packages/foldkit/src/graph.ts:986`). Marker fill and stroke follow `edge.stroke`, defaulting to `#64748b` (`packages/foldkit/src/graph.ts:783`, `packages/foldkit/src/graph.ts:805`); marker definitions and wide hit paths stay within each keyed edge group (`packages/foldkit/src/graph.ts:763`, `packages/foldkit/src/graph.ts:814`). Focusable hit paths translate Enter and Space to edge selection (`packages/foldkit/src/graph.ts:821`, `packages/foldkit/src/graph.ts:825`). A sibling HTML layer owns label positioning in graph coordinates (`packages/foldkit/src/graph.ts:974`, `packages/foldkit/src/graph.ts:1042`).

## Test and reference boundaries

`research/fixtures/renderer-contract.json` is a shared, schema-decoded Flow input with two typed nodes, multiple handles, all five core path variants, a custom-stroke edge with arrow and arrowclosed markers, an unknown type, a missing-path edge, and the dynamic-handle scenario. Production browser suites feed this fixed document to the real Vanilla controller, Vue `FlowCanvas`, and Foldkit `Runtime` entry (`apps/vanilla/e2e/renderer-contract.e2e.ts:446`, `apps/vue/e2e/renderer-contract.e2e.ts:15`, `apps/foldkit/e2e/renderer-contract.e2e.ts:412`). Each suite compares sorted node and edge identity plus type, path, label, and marker semantics through `apps/shared-e2e/renderer-contract.ts:51`, and measures rendered SVG endpoints against the corresponding rendered handle boundary with a one-CSS-pixel tolerance (`apps/shared-e2e/renderer-contract.ts:66`, `apps/shared-e2e/renderer-contract.ts:105`). They also assert the missing-path edge renders an actual straight M/L SVG path. Foldkit production tests verify marker fill/stroke follows the custom edge color and Enter/Space select focused edge hit targets (`apps/foldkit/e2e/renderer-contract.e2e.ts:372`, `apps/foldkit/e2e/renderer-contract.e2e.ts:544`). Vue production tests compare Bezier label positions to core geometry, custom label anchors, and hidden edge/endpoint behavior (`apps/vue/e2e/renderer-contract.e2e.ts:154`). Host suites poll for renderer readiness before sampling; only framework scheduling differs, not the normalized semantic or geometry assertion. The conformance unit suite also schema-checks the fixed scene. These are separate adapters; the tests do not merge their framework lifecycle observations into a claim that their DOM trees are identical.

The executable React capture validates that its disposable checkout is clean and at the pinned commit, builds the upstream system and React packages, mounts public `ReactFlow`, and compares two normalized captures in a fixed 1280-by-720 viewport (`scripts/capture-renderer-contract-reference.ts:84`, `scripts/capture-renderer-contract-reference.ts:96`, `scripts/capture-renderer-contract-reference.ts:108`, `scripts/capture-renderer-contract-reference.ts:144`, `scripts/capture-renderer-contract-reference.ts:170`). Its fixture records measured node/handle values, rendered path strings before and after a dynamic handle move, custom-label presence, normalized marker structure, and unknown-type fallback (`research/fixtures/renderer-contract-reference.json:1`). Pinned production evidence for registry fallback and node props is in `packages/react/src/components/NodeWrapper/index.tsx:55`, `packages/react/src/components/NodeWrapper/index.tsx:228`, and `packages/react/src/components/EdgeWrapper/index.tsx:43`; portal ownership for complex HTML edge labels is documented in `packages/react/src/components/EdgeLabelRenderer/index.tsx:13`. The pinned browser suite checks marker URLs (`tests/playwright/e2e/edges.spec.ts:148`). This capture is a bounded comparison of those outputs; it is not a full upstream suite run or a current-website inventory refresh.
