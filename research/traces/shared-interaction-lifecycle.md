# Shared interaction lifecycle trace

This trace follows the current connection path through each production host. It records implemented call paths only; it does not claim that the three hosts expose equivalent gestures.

## Production paths

### Vanilla public mount and connection

The browser caller invokes `mountFlow`, which decodes options and the input document before composing the host at [apps/vanilla/src/mount-flow.ts:7217-7240](../../apps/vanilla/src/mount-flow.ts). The node's pointer-down handler selects a resize handle, connection handle, or node-drag path at [apps/vanilla/src/mount-flow.ts:4285-4325](../../apps/vanilla/src/mount-flow.ts). A connection end hit-tests the candidate, preserves click-connect activation when configured, and rejects missing or wrong-kind targets at [apps/vanilla/src/mount-flow.ts:5453-5513](../../apps/vanilla/src/mount-flow.ts). The adapter validates a full connection candidate in core before publishing an edge-add change; accepted document state and rendered edge output are reconciled by the host controller.

The host owns pointer capture, DOM hit-testing, previews, and cancellation. Scoped pointer listeners dispatch completion, while window blur, capture loss, pointer cancel, Escape, removal, and destroy route through the active-gesture cancellation path at [apps/vanilla/src/mount-flow.ts:5221-5249](../../apps/vanilla/src/mount-flow.ts) and [apps/vanilla/src/mount-flow.ts:6315-6334](../../apps/vanilla/src/mount-flow.ts). Core receives decoded IDs and geometry, not browser events. The accepted edge collection is projected into keyed DOM groups and paths by [apps/vanilla/src/edge-renderer.ts:328-391](../../apps/vanilla/src/edge-renderer.ts).

Vanilla's public `FlowHostOptions` declares lifecycle and canvas callbacks, including native event listeners and operation payloads, at [apps/vanilla/src/mount-flow.ts:684-738](../../apps/vanilla/src/mount-flow.ts). Connection start/end dispatch passes the activation discriminator (`pointer-connect` or `click-connect`) through the boundary callback helper at [apps/vanilla/src/mount-flow.ts:2660-2679](../../apps/vanilla/src/mount-flow.ts). Host initialization invokes `onInit` with the controller and routes a thrown initialization callback to `onError` when supplied at [apps/vanilla/src/mount-flow.ts:8835-8845](../../apps/vanilla/src/mount-flow.ts). These are Vanilla callback contracts; they do not establish equivalent callback payloads in Vue or Foldkit.

### Vue component and connection

The public component is `FlowCanvas` in [packages/vue/src/flow-canvas.ts:259-303](../../packages/vue/src/flow-canvas.ts). Its node pointer handler distinguishes native controls from graph input, resolves the source handle and measured anchor, then stores an adapter-local pointer session at [packages/vue/src/flow-canvas.ts:1580-1664](../../packages/vue/src/flow-canvas.ts). Pointer release hit-tests the target, constructs a complete `FlowConnection`, calls the caller validator, applies core validation, and publishes the edge-add proposal at [packages/vue/src/flow-canvas.ts:1665-1752](../../packages/vue/src/flow-canvas.ts). The render function draws the transient SVG connection preview and attaches pointer completion/cancellation listeners at [packages/vue/src/flow-canvas.ts:2227-2362](../../packages/vue/src/flow-canvas.ts).

The decoded document remains the semantic source for endpoints. `publish` emits the proposal; controlled mode waits for owner acknowledgement, while uncontrolled mode adopts the edge change at [packages/vue/src/flow-canvas.ts:794-840](../../packages/vue/src/flow-canvas.ts). The render path resolves edge geometry and creates a keyed SVG group at [packages/vue/src/flow-canvas.ts:2058-2119](../../packages/vue/src/flow-canvas.ts). Vue selection begins in a Shift+blank-canvas pointer handler, stores pointer ownership and flow coordinates, then computes a normalized rectangle and calls core `selectionInRect` on release at [packages/vue/src/flow-canvas.ts:1976-1985](../../packages/vue/src/flow-canvas.ts). Resize controls start a host-local session from the selected node's measured internal dimensions; pointer movement calls core `calculateNodeResize`, and pointer release publishes the final node-bounds change at [packages/vue/src/flow-canvas.ts:1841-1901](../../packages/vue/src/flow-canvas.ts) and [packages/vue/src/flow-canvas.ts:2007-2019](../../packages/vue/src/flow-canvas.ts). These are bounded pointer paths. The Vue production suite separately covers keyboard connection/reconnection, rectangle selection, and focused resize in [apps/vue/e2e/interaction-lifecycle.e2e.ts](../../apps/vue/e2e/interaction-lifecycle.e2e.ts); those tests do not establish every cancellation/lifecycle callback family.

`FlowCanvas` declares decoded emits for drag, connect, reconnect, selection, move, pane/node/edge input, initialization, and validator-boundary errors at [packages/vue/src/flow-canvas.ts:517-663](../../packages/vue/src/flow-canvas.ts). For a connection terminal, `endConnectionLifecycle` clears the active lifecycle and emits `connectEnd` or `reconnectEnd`; click activation additionally emits `clickConnectEnd` at [packages/vue/src/flow-canvas.ts:1379-1402](../../packages/vue/src/flow-canvas.ts). Pointer and click starts are assembled separately at [packages/vue/src/flow-canvas.ts:2428-2441](../../packages/vue/src/flow-canvas.ts) and [packages/vue/src/flow-canvas.ts:2891-2903](../../packages/vue/src/flow-canvas.ts). Vue emits decoded values, not native DOM events. The lifecycle-specific Vue E2E asserts click-connect, reconnect, drag, and pointer-selection ordering; its uncontrolled keyboard-selection case also asserts accepted-state adoption before the terminal event. These fixed cases do not cover every cancellation reason or controlled keyboard acknowledgement.

### Foldkit graph message and connection

Foldkit's graph Model stores the document, viewport, and one transient pointer session; it does not store native event objects at [packages/foldkit/src/graph.ts:39-74](../../packages/foldkit/src/graph.ts). The graph transition records decoded pointer identity, client coordinates, node ID, and handle ID at [packages/foldkit/src/graph.ts:494-548](../../packages/foldkit/src/graph.ts). On release, the update clears the pointer session and routes either to node movement or candidate validation at [packages/foldkit/src/graph.ts:478-491](../../packages/foldkit/src/graph.ts). Connection completion resolves current source/target nodes and handles, enforces caller-provided allowed targets, validates the full candidate in core, and emits edge-add through the semantic change path at [packages/foldkit/src/graph.ts:382-437](../../packages/foldkit/src/graph.ts). Pointer cancellation messages carry a pointer ID and clear only the matching active session; the document subscription includes the event ID at [packages/foldkit/src/graph.ts:1120-1129](../../packages/foldkit/src/graph.ts).

The Foldkit app observes rendered nodes to feed measurements through typed host actions at [apps/foldkit/src/main.ts:274-292](../../apps/foldkit/src/main.ts). Public `createProgram` configuration selects full or partial selection mode; the Foldkit graph Model stores only decoded pointer identity, flow coordinates, selection mode, and resize values, never native event objects. Its graph transition calls core `selectionInRect` and `applySelectionSetChange` on selection release, and `calculateNodeResize` plus `applyNodeBoundsChange` on resize release at [packages/foldkit/src/graph.ts:660-761](../../packages/foldkit/src/graph.ts). Adapter subscriptions map DOM pointer events to serializable graph messages after canvas/viewport coordinate conversion at [packages/foldkit/src/graph.ts:1435-1500](../../packages/foldkit/src/graph.ts). The graph view renders the selection overlay and eight resize controls at [packages/foldkit/src/graph.ts:1065-1205](../../packages/foldkit/src/graph.ts). The production suite covers pointer reconnect and dynamic handle replacement, keyboard reconnect and rectangle selection, full/partial pointer selection, all eight resize directions with accepted geometry and nested child compensation, focused keyboard node selection and resize, cancellation (including reconnect blur and capture loss), synthetic touch connection, and selected input ownership. Grouped/repeated keyboard resize commits once after keyup and cancels without committing on Escape.

Foldkit's `InteractionEventSchema` defines the serializable lifecycle vocabulary and deliberately has no DOM event field at [packages/foldkit/src/graph.ts:193-238](../../packages/foldkit/src/graph.ts). The application compares the previous and next active sessions, maps operation kinds to start/progress/end records, and marks controlled connection/reconnection terminals as `proposed` until owner acknowledgement at [packages/foldkit/src/application.ts:1163-1206](../../packages/foldkit/src/application.ts) and [packages/foldkit/src/application.ts:1317-1384](../../packages/foldkit/src/application.ts). It publishes those records through the typed `interactionEvents` port at [packages/foldkit/src/application.ts:245-251](../../packages/foldkit/src/application.ts) and [packages/foldkit/src/application.ts:1476-1493](../../packages/foldkit/src/application.ts). `onInit` is emitted on the first ready graph transition; the current `onError` record is attached to failed edit responses only at [packages/foldkit/src/application.ts:1466-1483](../../packages/foldkit/src/application.ts) and [packages/foldkit/src/application.ts:737-746](../../packages/foldkit/src/application.ts). Programmatic viewport replacement and operations instead publish start/change/end records through `viewportEvents` at [packages/foldkit/src/application.ts:190-199](../../packages/foldkit/src/application.ts) and [packages/foldkit/src/application.ts:838-863](../../packages/foldkit/src/application.ts); these records do not carry controlled proposal/acknowledgement status or become `interactionEvents` move callbacks.

Click activation enters through `ClickHandle`, which reuses the connection transition and records `inputKind: 'click'` in the active session at [packages/foldkit/src/graph.ts:1322-1347](../../packages/foldkit/src/graph.ts). The lifecycle mapper carries that discriminator while using the common connection operation records at [packages/foldkit/src/application.ts:1135-1150](../../packages/foldkit/src/application.ts); the host E2E checks the click input kind at [apps/foldkit/e2e/interaction-lifecycle.e2e.ts:163](../../apps/foldkit/e2e/interaction-lifecycle.e2e.ts). For configuration replacement, the graph reducer clears pointer, gesture, keyboard-connection, and keyboard-resize sessions in `ReplaceDocument` at [packages/foldkit/src/graph.ts:1082-1095](../../packages/foldkit/src/graph.ts). The application routes that host action and compares the previous and resulting graphs to publish lifecycle records at [packages/foldkit/src/application.ts:1527-1546](../../packages/foldkit/src/application.ts); a disappeared active session is classified as cancellation at [packages/foldkit/src/application.ts:1260-1267](../../packages/foldkit/src/application.ts). ## Conformity and deviations

- **Conforming:** Core rejects missing endpoints, wrong-kind handles, and duplicate edges through `validateFlowConnection`; its unit boundary is `packages/core/src/domain/flow-connection.schema.test.ts`. Vanilla, Vue, and Foldkit call that validator on their connection paths.
- **Intentionally different:** Vanilla exposes native callbacks with host input kind, Vue emits decoded component payloads (including distinct `clickConnectStart`/`clickConnectEnd` events), and Foldkit emits serialized operation records through a typed port. Foldkit represents click activation with `inputKind: 'click'` on common operation records rather than click-only callback names, and carries no native event objects. Foldkit's lifecycle records distinguish `proposed` from accepted connection terminals, while its separate programmatic `viewportEvents` omit controlled proposal/acknowledgement status. Vue defaults `selectNodesOnDrag` to false while Vanilla enables it unless false; Vue's default preserves existing shared conformance semantics and explicit true is separately tested. These are host-specific contracts, not parity claims.
- **Unverified:** Vue has direct order assertions for click-connect, reconnect, drag, pointer rectangle selection, and uncontrolled keyboard rectangle selection; controlled keyboard-selection acknowledgement order and the full operation × cancellation-reason callback matrix remain open. Foldkit lacks pane/node/edge double-click and context-menu record kinds, its `onError` record currently reports edit failures only, and the complete cross-host callback-order matrix remains open. Vanilla keyboard reconnection remains unsupported. Vue pinch zoom and pan button arrays are absent; Foldkit pinch, pan button arrays, `selectNodesOnDrag`, and pan/zoom activation keycode options are absent. Vanilla's declared `zoomOnPinch` behavior is not established. Trusted native multi-pointer capture remains reserved for Plan 060. Synthetic browser input is not a substitute.
