# Schema Studio on Foldkit compared with Vanilla and recorded ChartDB behavior

Plan 124 ports the Vanilla behavioral specification to Foldkit. The ChartDB comparison uses only `research/references/chartdb/REFERENCE.md` and the recorded `results/S1.json` through `results/S16.json`. No ChartDB source was fetched, read, or copied. The shared domain, seed, and DBML remain unchanged.

The reference and Flow tests are independent observations. This work runs Flow in Chromium, with no live ChartDB or React runtime. The existing [Vanilla comparison](schema-studio-vanilla-comparison.md) supplies the reference boundary and reasons for the original clean-room differences.

## Production call paths and ownership

The page loads `apps/foldkit/schema-studio/index.html:10` and composes two persistent runtimes in `apps/foldkit/schema-studio/main.ts:181` and `apps/foldkit/schema-studio/main.ts:448`. The application runtime owns schema history, settings, selection, menu/editor state, clipboard, and floating connection state through `ModelSchema` at `apps/foldkit/schema-studio/model.ts:50`, schema-backed messages at `apps/foldkit/schema-studio/model.ts:82`, update at `apps/foldkit/schema-studio/model.ts:219`, and the application view. The graph runtime owns accepted Flow state, gestures, measurements, and rendering through the public `@flow/foldkit` API. The host's model variable mirrors the application runtime for native callbacks; it does not mutate graph state directly.

For a real pointer drag, the rendered canvas invokes `pointerResource.begin` at `packages/foldkit/src/graph.ts:7553`. Native pointer ownership starts in `packages/foldkit/src/graph.ts:6028`; `NodeDragMoved` at `packages/foldkit/src/graph.ts:3811` updates the gesture. `selectLiveModel` at `packages/foldkit/src/graph.ts:2689` supplies the view at `packages/foldkit/src/graph.ts:7082`. Node positions and the custom edge projections therefore come from the same render graph. `FoldkitEdgeGeometry` exposes detached source/target internals at `packages/foldkit/src/graph.ts:5186`. The application renderer at `apps/foldkit/schema-studio/renderers.ts:13` reads those endpoints, uses the shared nearest-side rule, computes the smooth-step path, publishes the interaction path, and renders SVG markers plus HTML cardinality labels.

Resize follows `GestureMoved` at `packages/foldkit/src/graph.ts:4107`, or `ResizeByKeyboard` at `packages/foldkit/src/graph.ts:4580`. `previewMeasurements` at `packages/foldkit/src/graph.ts:2640` preserves current-generation handle offsets while moving resized borders. `selectLiveModel` combines those measurements with pointer, keyboard, or custom-resizer bounds. Rendering and instance snapshots now share this projection. The snapshot entry at `packages/foldkit/src/application.ts:942` calls it at line 945; instance `getInternalNode`/`getInternalNodes` use those requests at `packages/foldkit/src/instance.ts:403`. Accepted graph state stays separate until release. Escape discards the preview.

The snap button and native Shift listener at `apps/foldkit/schema-studio/main.ts:782` produce application messages. Their update branches at `apps/foldkit/schema-studio/model.ts:371` and `apps/foldkit/schema-studio/model.ts:386` run host commands through `apps/foldkit/schema-studio/main.ts:300`. `HostAction.SetCanvasOptions` enters the decoded port contract at `packages/foldkit/src/application.ts:179`, routes at line 2233, and patches the graph model at `packages/foldkit/src/graph.ts:3398`. It keeps the pointer session and existing elements. Field-handle attributes enter at `packages/foldkit/src/graph.ts:7162`; the public measurement observer is composed at `apps/foldkit/schema-studio/main.ts:614` and measures changes without application DOM lookup.

Graph accepted-state notifications enter the application at `apps/foldkit/schema-studio/main.ts:492`. The `Accepted` branch at `apps/foldkit/schema-studio/model.ts:406` translates parent-relative geometry back into shared schema positions, records history only for model changes, and projects a new document through `apps/foldkit/schema-studio/graph.ts:69`. Semantic connection records enter at `apps/foldkit/schema-studio/main.ts:585` and use the shared endpoint validation. Viewport updates enter `recordViewport` at `apps/foldkit/schema-studio/main.ts:507`; they drive status, lost-canvas recovery, minimap updates, and the background phase.

Native context-menu cancellation remains package-owned at `packages/foldkit/src/mouse-observation.ts:191` and line 198. Serializable notifications reach the app at `apps/foldkit/schema-studio/main.ts:538`; the host converts client coordinates through the public instance before opening the menu. Button-0 Control-click selection is handled at `packages/foldkit/src/graph.ts:3117`; physical button-2 right-clicks retain their menu behavior. Application-owned buttons and editors use application data attributes at `apps/foldkit/schema-studio/main.ts:624`, without looking up private Flow node content.

## Separate test paths

The Schema Studio suite opens the actual application, dispatches native Playwright mouse/keyboard/wheel input, and inspects the rendered output and application diagnostic status. Foldkit class names, resize attributes, animation names, and reconnect acknowledgement differ from Vanilla's host API. The settle helper waits for the queued Foldkit update before waiting for the viewport operation to finish. It retains the same seed, geometry, selection, deletion, zoom, resize, marker, and export assertions.

The drag test at `apps/foldkit/e2e/schema-studio.e2e.ts:277` and width-resize test at `apps/foldkit/e2e/schema-studio.e2e.ts:1195` compare the path with the pointer still held against the path after release. The resize path waits for the drawn final width and two animation frames for observer delivery before capturing the held path. This is a browser scheduling boundary, not a sleep or a reducer-only proof.

`apps/foldkit/live-internal-node/main.ts` is a separate public-API fixture. `apps/foldkit/e2e/live-internal-node.e2e.ts:37` reads the asynchronous instance while native pointer resize is held, for both built-in and custom resizers. It compares live dimensions with the DOM, bulk/single reads, and unchanged accepted state, then cancels with Escape. The held-key test at `apps/foldkit/e2e/live-internal-node.e2e.ts:76` exercises the keyboard projection. Unit tests in `packages/foldkit/src/live-resize.test.ts` cover pure projection, mid-drag option changes, invalid decode, and Control-context selection. Those are distinct from native browser evidence.

## Conformity and deviations

- Conforming to the Vanilla application contract within the listed Chromium boundaries: S1-S16, bare-pane panning, Full box selection, held drag/resize relationship geometry, and context-menu default prevention. Recorded ChartDB comparisons are limited to the independently captured contracts above.
- Intentionally different from Vanilla: Foldkit owns its model through asynchronous messages and public ports. Its uncontrolled reconnection reports `accepted` where Vanilla's application callback reports `proposed`; both tests assert the same final relationship endpoint and count. The minimap uses Foldkit's 180x120 default rather than Vanilla's requested 180x110, so S14 uses a different bare-pane pointer. The editor is rendered by the application view instead of being imperatively inserted into a node's DOM. Foldkit uses its own host classes, resize attributes, and animation name. Notes publish input changes into history rather than waiting for blur. Show overlaps preserves the camera, auto-arrange uses the Show All camera policy, and area bodies permit pane gestures with interactive headers/resize controls. These choices keep controlled note state current and make pane gestures available inside areas; the inherited tests do not establish note undo grouping or those camera details. A separate localStorage key keeps the two demos independent. None requires a remount or private DOM lookup.
- Intentionally different from ChartDB, retained from Vanilla: original seed layout, colors, styles and marker artwork; selection retained after dragging; list-row focus; context creation at the original pane pointer; localStorage; and the Beyond additions. The recorded macOS Control-click menu differs from the requested Schema Studio multiselection behavior.
- Unverified: pixel parity with ChartDB, exact reference frame ordering, native touch/pinch, other engines/operating systems, overlapping-area priority, collector-side OpenTelemetry delivery, release acceptance, and `verify:full`. A focused verifier with broad saved browser scope is not the complete local suite.
