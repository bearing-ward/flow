The shared system store holds a node lookup and parent-to-child lookup. `updateChildNode` resolves the parent by ID, computes absolute position from the parent absolute position plus child-local position, and warns when the parent is absent (`packages/system/src/utils/store.ts:214`, `packages/system/src/utils/store.ts:222`, `packages/system/src/utils/store.ts:225`, `packages/system/src/utils/store.ts:286`, `packages/system/src/utils/store.ts:293`). During drag, `XYDrag` delegates candidate movement to `calculateNodePosition` and updates internal absolute positions (`packages/system/src/xydrag/XYDrag.ts:192`, `packages/system/src/xydrag/XYDrag.ts:201`). That helper resolves the parent, constrains against an extent, then returns both parent-local `position` and `positionAbsolute` (`packages/system/src/utils/graph.ts:429`, `packages/system/src/utils/graph.ts:430`, `packages/system/src/utils/graph.ts:456`, `packages/system/src/utils/graph.ts:464`).

This is framework UI, not a core graph model.

## Flow decisions and test boundary

Flow's document and geometry remain schema-derived core values; browser lifecycle and render callbacks remain in the vanilla host (`docs/standards.md:7`, `docs/architecture.md:7`, `docs/architecture.md:18`). The new contract will use parent-local positions for children and derive absolute values from a validated document, independent of array order. Invalid parent graphs fail at decode instead of warning during rendering. Children inherit hidden state from ancestors, siblings sort by stable `zIndex` then document index, and parents render behind descendants. A declared positive size supplies initial geometry; measured host dimensions take precedence. Custom node and edge registries are host callbacks, while core owns renderer-independent path and toolbar anchor geometry. Flow's tests establish these contracts within its core unit and vanilla browser boundaries; they do not establish direct React/Svelte output parity.

## Conformity and deviations

- **Conforming:** Both reference adapters expose renderer registries and place nodes from derived absolute geometry (`packages/react/src/container/ReactFlow/index.tsx:263`, `packages/react/src/components/NodeWrapper/index.tsx:205`, `packages/svelte/src/lib/store/index.ts:92`, `packages/svelte/src/lib/components/NodeWrapper/NodeWrapper.svelte:274`). Flow will also keep visual registration in the host and geometry in core.
- **Intentionally different:** xyflow's missing-parent path warns and can depend on lookup state while Flow rejects missing IDs and cycles before host state is created (`packages/system/src/utils/store.ts:225`, `packages/system/src/utils/store.ts:227`). Flow will not add automatic parent expansion or mutable internal lookup maps to its public document contract.
- **Intentionally different:** Reference node renderers are framework components, whereas Flow renderer callbacks receive a host-owned content container and lifecycle (`packages/react/src/components/NodeWrapper/index.tsx:228`, `packages/svelte/src/lib/components/NodeWrapper/NodeWrapper.svelte:94`). This supports Flow's framework-neutral vanilla host and does not define Foldkit or Vue behavior.
- **Unverified:** The cited upstream browser test checks toolbar placement and default visibility only (`tests/playwright/e2e/node-toolbar.spec.ts:34`, `tests/playwright/e2e/node-toolbar.spec.ts:84`). Flow's planned core and vanilla tests will verify its own nested geometry, sizing, renderer cleanup, and anchors; no side-by-side parity test or alternate adapter test is included.

These classifications compare selected contracts and proof boundaries. Source similarity does not establish full xyflow parity.
