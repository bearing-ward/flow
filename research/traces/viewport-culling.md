# Viewport culling

Status: production paths traced in pinned xyflow commit `0a1f9575b25679f2880175de8d3eae21aedde921`. The reference Cypress suite directly checks node counts with culling enabled. It does not directly assert edge culling or dynamic pan and zoom transitions. Reference paths below are relative to `research/artifacts/xyflow/0a1f9575b25679f2880175de8d3eae21aedde921/`.

## React production path

The public `ReactFlow` defaults `onlyRenderVisibleElements` to false at `packages/react/src/container/ReactFlow/index.tsx:77` and passes it into `GraphView` at `packages/react/src/container/ReactFlow/index.tsx:276`. `GraphView` forwards the setting to both renderers at `packages/react/src/container/GraphView/index.tsx:165` and `packages/react/src/container/GraphView/index.tsx:192`. Thus culling is opt-in; the normal path retains all node and edge IDs.

For nodes, `NodeRenderer` asks `useVisibleNodeIds` for IDs and renders keyed `NodeWrapper` elements at `packages/react/src/container/NodeRenderer/index.tsx:40` and `packages/react/src/container/NodeRenderer/index.tsx:72`. The hook reads node lookup, viewport transform, and pane width and height. With culling off, it returns every lookup key; with culling on, it calls `getNodesInside` with a pane rectangle and partial-overlap mode at `packages/react/src/hooks/useVisibleNodeIds.ts:8`. The shared function converts the screen rectangle to flow coordinates, obtains measured or declared node dimensions and absolute positions, checks rectangle overlap, and retains an unmeasured node for initial rendering or an actively dragged node at `packages/system/src/utils/graph.ts:272`, `packages/system/src/utils/graph.ts:287`, and `packages/system/src/utils/graph.ts:291`. This initial render exception allows DOM measurement before a node can be reliably culled.

For edges, `EdgeRenderer` asks `useVisibleEdgeIds` for IDs and mounts keyed `EdgeWrapper` elements at `packages/react/src/container/EdgeRenderer/index.tsx:60` and `packages/react/src/container/EdgeRenderer/index.tsx:66`. The hook returns all edge IDs when culling is off. With culling on and a nonzero pane size, it resolves each edge's source and target nodes and retains the ID when `isEdgeVisible` succeeds at `packages/react/src/hooks/useVisibleEdgeIds.ts:18` and `packages/react/src/hooks/useVisibleEdgeIds.ts:25`. The shared function constructs the bounding box enclosing both endpoint nodes, expands a zero-width or zero-height box, converts the viewport into flow coordinates, and requires positive overlap at `packages/system/src/utils/edges/general.ts:69`. This is an endpoint-bounds approximation, not a path-geometry intersection. Edges whose endpoint nodes are themselves outside the viewport can still render when their combined bounds intersect it.

## Svelte production path

The public `SvelteFlow` binds nodes and edges into its store at `packages/svelte/src/lib/container/SvelteFlow/SvelteFlow.svelte:72` and `packages/svelte/src/lib/container/SvelteFlow/SvelteFlow.svelte:80`; its viewport mounts `EdgeRenderer` at `packages/svelte/src/lib/container/SvelteFlow/SvelteFlow.svelte:185`. The store derives `onlyRenderVisibleElements` as false by default at `packages/svelte/src/lib/store/initial-store.svelte.ts:396`.

When enabled, the store reads viewport and pane dimensions, gets nodes inside the viewport, then lays out visible edges at `packages/svelte/src/lib/store/initial-store.svelte.ts:257`. `getVisibleNodes` calls the same shared `getNodesInside` geometry at `packages/svelte/src/lib/store/visibleElements.ts:20`. `getLayoutedEdges` excludes an edge with missing or hidden endpoint nodes, then uses the shared `isEdgeVisible` test at `packages/svelte/src/lib/store/visibleElements.ts:88` and `packages/svelte/src/lib/store/visibleElements.ts:96`. Unlike the React hook, a visible edge adds both endpoint nodes to the visible-node map at `packages/svelte/src/lib/store/visibleElements.ts:107`, so their handles can be mounted even if the individual node boxes are outside the viewport. The node and edge renderers consume these maps as keyed DOM children at `packages/svelte/src/lib/container/NodeRenderer/NodeRenderer.svelte:51` and `packages/svelte/src/lib/container/EdgeRenderer/EdgeRenderer.svelte:21`. With culling disabled, the store uses the full node lookup and lays out all edges at `packages/svelte/src/lib/store/initial-store.svelte.ts:271`.

## Conformity and deviations

- **Conforming:** Culling is opt-in, retains the document, measures before culling, uses endpoint bounds for edges, and restores nodes after viewport changes. Flow browser tests establish zoom and drag-completion behavior.
- **Intentionally different:** Flow promotes both endpoints of a visible crossing edge and uses a fixed 32-flow-pixel overscan. It retains offscreen measurements for re-entry.
- **Unverified:** Active-drag culling, crossing-edge DOM counts, and performance at scale lack dedicated tests. The pinned browser suite proves React node counts only, so upstream edge and Svelte parity remain unverified.
