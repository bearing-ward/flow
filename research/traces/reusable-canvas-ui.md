# Reusable canvas UI boundary

## Reference source path

The pinned xyflow React adapter defaults its `Background` to dots and scales the pattern with the viewport transform; variant, gap, color, and background color are component inputs (`packages/react/src/additional-components/Background/Background.tsx:19`, `packages/react/src/additional-components/Background/Background.tsx:37`, `packages/react/src/additional-components/Background/Background.tsx:53`). Its Controls render zoom, fit, and an interactivity toggle (`packages/react/src/additional-components/Controls/Controls.tsx:25`, `packages/react/src/additional-components/Controls/Controls.tsx:45`, `packages/react/src/additional-components/Controls/Controls.tsx:60`, `packages/react/src/additional-components/Controls/Controls.tsx:101`). The reference pane enables double-click zoom by default and passes that setting into the zoom pane (`packages/react/src/container/ReactFlow/index.tsx:99`, `packages/react/src/container/ZoomPane/index.tsx:111`).

The reference minimap computes visible-node bounds plus the current viewport rectangle (`packages/react/src/additional-components/MiniMap/MiniMap.tsx:19`, `packages/react/src/additional-components/MiniMap/MiniMap.tsx:41`), and its SVG delegates click coordinates to its minimap geometry (`packages/react/src/additional-components/MiniMap/MiniMap.tsx:151`, `packages/react/src/additional-components/MiniMap/MiniMap.tsx:189`). Panels are positioned DOM children above the viewport (`packages/react/src/components/Panel/index.tsx:16`, `packages/react/src/components/Panel/index.tsx:41`). Node toolbars render into a portal and position from node bounds (`packages/react/src/additional-components/NodeToolbar/NodeToolbar.tsx:108`, `packages/react/src/additional-components/NodeToolbar/NodeToolbar.tsx:118`, `packages/react/src/additional-components/NodeToolbar/NodeToolbar.tsx:129`); edge toolbars render through the edge-label portal (`packages/react/src/additional-components/EdgeToolbar/EdgeToolbar.tsx:48`, `packages/react/src/additional-components/EdgeToolbar/EdgeToolbar.tsx:60`).

The pinned React `ViewportPortal` selects the provider's viewport portal element and portals children into it, so they inherit its pan/zoom coordinate system (`research/artifacts/xyflow/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/ViewportPortal/index.tsx:7-13,34-41`).

For MiniMap specifically, the Vanilla public mount option is `ui.minimap` (`apps/vanilla/src/public.ts:1-9`, `apps/vanilla/src/mount-flow.ts:273-276`). The host enables one fixed 180×120 SVG with an accessible image name; clicks are converted to graph fractions and sent to the same canvas viewport publication path (`apps/vanilla/src/canvas-ui.ts:305-330`, `apps/vanilla/src/style.css:142-161`, `apps/vanilla/src/mount-flow.ts:7778-7853`). On graph refresh, Vanilla builds graph geometry from the current measurement map and rendered positions, calculates `graphBounds`, omits hidden nodes, and supplies visible nodes, bounds, viewport, and canvas size to the minimap renderer (`apps/vanilla/src/mount-flow.ts:2113-2147`). SVG node rectangles and the viewport rectangle are projected into the fixed viewBox (`apps/vanilla/src/canvas-ui.ts:435-499`).

## Flow production path

`mountFlow` decodes `FlowMountOptionsSchema` before acquiring the host (`apps/vanilla/src/mount-flow.ts:4369-4392`). The host assigns the optional background pattern and CSS variables to its canvas (`apps/vanilla/src/mount-flow.ts:385`, `apps/vanilla/src/mount-flow.ts:386`); stylesheet rules implement dots, lines, and no pattern (`apps/vanilla/src/style.css:26`, `apps/vanilla/src/style.css:38`, `apps/vanilla/src/style.css:42`). `createCanvasUI` creates opt-in accessible zoom/fit/select-pan buttons, a minimap and caller-provided panel slots (`apps/vanilla/src/canvas-ui.ts:21`, `apps/vanilla/src/canvas-ui.ts:38`, `apps/vanilla/src/canvas-ui.ts:59`, `apps/vanilla/src/canvas-ui.ts:76`, `apps/vanilla/src/canvas-ui.ts:105-133`). It does not clone caller content when the graph reconciles and restores caller elements on host destruction (`apps/vanilla/src/canvas-ui.ts:106-113`, `apps/vanilla/src/canvas-ui.ts:227-285`). The mode toggle changes transient host state. Pan mode uses a capture-phase pointer handler to start viewport pan before node and edge handlers; it skips UI overlay targets, so controls, panels and caller toolbars retain their pointer behavior (`apps/vanilla/src/mount-flow.ts:2828`, `apps/vanilla/src/mount-flow.ts:3955`). Keyboard movement remains available because keyboard handlers do not consult pointer mode (`apps/vanilla/src/mount-flow.ts:3201`).

For panel placement, the public path is `mountFlow` option decoding and host-only DOM validation, followed by passing caller elements to `createFlowHost` (`apps/vanilla/src/mount-flow.ts:4342-4365`). Validation rejects duplicate ids, reused elements and mixed legacy/array options (`apps/vanilla/src/mount-flow.ts:284-306`). `createCanvasUI` stores each element's original parent, sibling, class, style and hidden state, then moves the element into a screen-space slot beside the transformed viewport (`apps/vanilla/src/canvas-ui.ts:105-130`, `apps/vanilla/src/style.css:44-60`). The host restores focus after inserting its canvas in the caller root and the JavaScript controller exposes the host-local portal container (`apps/vanilla/src/mount-flow.ts:4123-4126`, `apps/vanilla/src/mount-flow.ts:651,6618-6620`, `apps/vanilla/src/mount-flow.ts:4368-4370`). On destroy, caller panels are returned to their saved DOM positions and attributes; focus and input selection are preserved and the portal is detached with the UI root (`apps/vanilla/src/canvas-ui.ts:227-285`).

The Vanilla `Panel` entry is caller-owned DOM placed in one of six screen-space slots. The focused production browser case mounts through `/src/public.ts` and asserts all six placements, the same caller element after mount, input focus and selection through updates, native button action, and exact restoration of caller parent/sibling/attributes after destroy (`apps/vanilla/e2e/canvas-ui.e2e.ts:409-665`). This is bounded vanilla host evidence; it does not establish pinned React layout or option equivalence.

Vanilla's `overlayPortal` remains a screen-space container created beside `.flow-viewport`; its host-isolation and native button test is separate legacy overlay evidence (`apps/vanilla/src/canvas-ui.ts:389-392`; `apps/vanilla/e2e/canvas-ui.e2e.ts:752-829`). Graph-space caller content uses `JavaScriptFlowController.mountViewportPortal(element)`, which appends a gesture-excluding wrapper inside the owning transformed viewport and returns an idempotent disposer (`apps/vanilla/src/mount-flow.ts:850,1037,1527-1580,8148-8151,8860-8863`). A module WeakSet rejects a node already mounted through any Vanilla controller (`apps/vanilla/src/mount-flow.ts:255,1532-1538`); on disposal/destroy the method restores the original parent and sibling, or leaves a previously detached node detached (`apps/vanilla/src/mount-flow.ts:1580-1603,7882-7888`). The dedicated graph-space E2E covers these contracts separately from the screen overlay fixture (`apps/vanilla/e2e/viewport-portal.e2e.ts:31-271`).

Zoom buttons and double-click use core `zoomViewportAt`, then send the result through the host's viewport change path (`apps/vanilla/src/mount-flow.ts:3929`, `apps/vanilla/src/mount-flow.ts:3941`). That path clamps zoom and pan extent, renders the viewport, and preserves controlled acknowledgement (`apps/vanilla/src/mount-flow.ts:1910`, `apps/vanilla/src/mount-flow.ts:1917`). Double-click anchoring converts the event point from canvas screen coordinates and the core math preserves that flow point while zoom changes (`apps/vanilla/src/mount-flow.ts:3931`, `packages/core/src/domain/flow-runtime.schema.ts:626`). The minimap is built from `createFlowGraph` geometry and `graphBounds`, including declared/measured dimensions and current position overrides (`apps/vanilla/src/mount-flow.ts:614`, `apps/vanilla/src/mount-flow.ts:621`, `packages/core/src/domain/flow-graph.ts:125`). Minimap clicks request a viewport centered on the selected graph fraction through the same semantic viewport path (`apps/vanilla/src/canvas-ui.ts:67`, `apps/vanilla/src/mount-flow.ts:3950`).

Toolbar geometry stays in core `flowToolbarAnchors`; the host filters anchors to rendered nodes and edges and calls `onToolbarAnchors` (`packages/core/src/domain/flow-toolbar-anchor.ts:15`, `packages/core/src/domain/flow-toolbar-anchor.ts:45`, `apps/vanilla/src/mount-flow.ts:638`). Callers may provide node and edge container elements keyed by ids. The host positions those existing elements, hides them when their graph item is culled or missing, preserves their buttons, and restores the elements on destroy (`apps/vanilla/src/canvas-ui.ts:90`, `apps/vanilla/src/canvas-ui.ts:136`, `apps/vanilla/src/canvas-ui.ts:147`). The demo's duplicate toolbar layer was removed when controls/minimap became reusable. Pane pointer-down ignores UI overlay targets so buttons and minimap clicks do not begin a pan (`apps/vanilla/src/mount-flow.ts:2735`).

## Flow test path

The browser suite mounts through `/src/public.ts`, checks background settings and accessible labels, exercises double-click and control zoom at the configured maximum, verifies minimap node/viewport geometry and navigation, captures a stable screenshot, verifies pan mode over a node preserves node transform and selection while moving the viewport, confirms controls still work in pan mode, then checks panel and caller toolbar preservation across a keyed update, viewport change, culling, and destroy (`apps/vanilla/e2e/canvas-ui.e2e.ts:4`, `apps/vanilla/e2e/canvas-ui.e2e.ts:26`, `apps/vanilla/e2e/canvas-ui.e2e.ts:61`, `apps/vanilla/e2e/canvas-ui.e2e.ts:93`). Added UI tests prove all six slots, same-element placement through document update and culling, focus and selection retention, exact caller restoration, duplicate rejection, no graph change from panel actions, and portal separation across two hosts (`apps/vanilla/e2e/canvas-ui.e2e.ts:166-310`). This suite tests Flow's vanilla adapter only; it does not mount a pinned reference fixture with equivalent inputs.

The MiniMap-focused Vanilla assertions check accessible rendering, node and viewport rectangles, click navigation (`apps/vanilla/e2e/canvas-ui.e2e.ts:56-71,123-128`), and that a live node resize changes its projected rectangle while visible-node reconciliation continues (`apps/vanilla/e2e/advanced-gestures.e2e.ts:1045-1085`). This test observes resize through the production resizing path; it does not independently compare each rendered rectangle against a separately computed projection oracle.

The Vue fixture mounts the exported `FlowMiniMap` as a `FlowCanvas` child (`apps/vue/src/minimap-test.ts:101-129`). `FlowCanvas` owns a `ResizeObserver`; for current registered node elements it reads rendered bounds, divides by viewport zoom, and applies accepted runtime measurements (`packages/vue/src/flow-canvas.ts:1119-1168`). The accepted measurement state and document are exposed to the MiniMap context through a computed `createFlowGraph` projection keyed by `measurementRevision` (`packages/vue/src/flow-canvas.ts:2473-2492`); the component derives SVG node rects from `selectFlowMiniMapProjection` (`packages/vue/src/minimap.ts:44-55,99-123`). In the focused browser path, the E2E changes the actual rendered `far` node's dimensions, waits for `useFlow().getInternalNode` to report accepted dimensions, confirms the declared document size is unchanged, then compares the rendered SVG rect's width and height to the projection built from accepted measurement state (`apps/vue/e2e/minimap.e2e.ts:33-96`, `apps/vue/src/minimap-test.ts:62-95`). The seven MiniMap E2Es passed 7/7 in the Vue host. This proves the DOM measurement-to-MiniMap path for this fixture and does not establish upstream parity or every renderer/lifecycle case.

The Vue public entry exports `FlowViewportPortal` (`packages/vue/src/public.ts:4`). Each `FlowCanvas` creates its own nullable target ref and provides it with computed gesture-exclusion class names (`packages/vue/src/flow-canvas.ts:819,2507-2512`); its target element is rendered inside the `.flow-vue-viewport` layer, which already applies the active `translate(x, y) scale(zoom)` transform (`packages/vue/src/flow-canvas.ts:5264-5281`). The component teleports its caller slot into that target and applies the owning canvas's configured no-pan, no-drag, and no-wheel class names to the wrapper (`packages/vue/src/viewport-portal.ts:4-49`). The target and wrapper cover the viewport with pointer events disabled; direct portal children can receive pointer events (`packages/vue/src/style.css:146-155`). FlowCanvas's existing pointer and wheel handlers consult those configured class names (`packages/vue/src/flow-canvas.ts:3792-3793,3851-3856`), so this adds no stop-propagation handler or second event router.

The mounted Vue fixture positions slot content in graph coordinates and hosts two independent canvases; the first overrides all three gesture-exclusion class names and the second uses defaults (`apps/vue/src/viewport-portal-test.ts:18-130`). Its focused production E2E passed 1/1 (`apps/vue/e2e/viewport-portal.e2e.ts:3-229`): it checks distinct target ownership, initial placement, boundary overflow/clipping, native child click and Enter plus wheel delivery, unchanged viewport through a portal wheel and pointer drag, position and size after a public viewport update, portal conditional unmount/remount, and removal at canvas teardown. This verifies those behaviors for the tested Vue fixture only; it does not establish upstream runtime parity, narrow-screen presentation, or focus restoration across unrelated focus changes.

Vue `FlowNodeToolbar` is a public screen-space component (`packages/vue/src/public.ts`, `packages/vue/src/node-toolbar.ts`). Each `FlowCanvas` owns a separate overlay target and provides the same accepted measured graph already projected for MiniMap (`packages/vue/src/flow-canvas.ts:819,2514-2538,2507-2512,5289-5295`). Core `nodeToolbarAnchor` derives all four cardinal anchors and start/center/end alignment from `graphNodeBounds`, projects the node edge through the active viewport, then applies offset in CSS screen pixels (`packages/core/src/domain/flow-toolbar-anchor.ts:21-77`). The component validates its public node id, position, alignment, and finite offset at render boundary, defaults to showing a toolbar only for its selected node when exactly one node is selected, and lets explicit `isVisible` override selection visibility. The mounted fixture and focused production E2E (`apps/vue/src/node-toolbar-test.ts`, `apps/vue/e2e/node-toolbar.e2e.ts`) pass 1/1. They verify a real node DOM resize updates accepted internal dimensions and recenters the toolbar, top and right/end placement, constant 10px/12px offset through zoom, fixed toolbar dimensions, selection and explicit visibility, hidden/missing node suppression, Playwright child click plus synthetic wheel/pointer gesture exclusion, two-canvas target ownership, and conditional component and canvas teardown. The screen overlay is distinct from `FlowViewportPortal`'s transformed target. This is bounded Vue implementation evidence; no reference runtime or screenshot comparison ran.

Foldkit's package-owned `mountFlowPanel` accepts caller-owned DOM content, moves it into a canvas-scoped screen-space wrapper, defaults to top-left and group role, and leaves focus and keyboard behavior with native children (`packages/foldkit/src/ui.ts:252`, `packages/foldkit/src/ui.ts:273`). Its wrapper marks no-pan/no-drag/no-wheel boundaries and `dispose` returns the content to its original parent and sibling position, idempotently (`packages/foldkit/src/ui.ts:293`, `packages/foldkit/src/ui.ts:311`). Styles provide six 12px inset positions, with horizontal centering for center positions (`packages/foldkit/src/style.css:95`). The focused mounted E2E passed 1/1 (`apps/foldkit/e2e/panel.e2e.ts:3`): all six placements are measured against the production playground canvas, and role/label/class, canvas scope, gesture markers, and caller DOM restoration are asserted. Dynamic position changes, responsive overflow, focused-element restoration, and pinned runtime comparison remain unverified; the helper is exported by `@flow/foldkit`; packed-consumer proof remains open.

Foldkit's package-owned `mountFlowViewportPortal(canvas, content)` moves caller-owned DOM under the selected canvas's transformed viewport, marks no-pan/no-drag/no-wheel boundaries, rejects concurrent reuse of mounted content, and returns an idempotent disposer that restores the original sibling position (`packages/foldkit/src/ui.ts:329-427`). The focused mounted E2E passed 1/1 (`apps/foldkit/e2e/viewport-portal.e2e.ts:9-188`): it checks containment under two canvas viewport elements, observes a transform on the playground viewport and changes it through zoom, exercises native click/Enter, verifies pointer drag and wheel leave viewport style unchanged, and checks duplicate rejection and canvas isolation. Its cleanup callback explicitly disposes the first mount twice and removes both canvases; the assertions verify both portal hosts are gone and both caller elements return to their original sibling order. The second mount therefore exercises observer-driven cleanup when its canvas is removed (`apps/foldkit/e2e/viewport-portal.e2e.ts:78-83,146-187`; observer at `packages/foldkit/src/ui.ts:411-421`). The test does not assert an independently calculated graph-space screen coordinate or bounding box. This is partial Foldkit-local implementation evidence only; no second live runtime or screenshot comparison ran. The helper is exported by `@flow/foldkit`; packed-consumer proof remains open. Framework child identity, clipping, responsive presentation, and broader native-input combinations remain unverified.

## Conformity and deviations

### ControlButton host paths

Vanilla exports `createFlowControlButton` from its public entry (`apps/vanilla/src/public.ts`). The helper creates a native `<button>`, applies the supported button fields and `aria-*` map, appends caller-owned DOM children, and registers the caller's click callback (`apps/vanilla/src/ui/control-button.ts`). Focus-visible styling comes from the existing Vanilla control-button rule (`apps/vanilla/src/style.css`). The production E2E imports through `/src/public.ts`, then checks the rendered native element, focus, Enter activation, callback, style, content, and disabled behavior (`apps/vanilla/e2e/control-button.e2e.ts`).

Foldkit exports `createFoldkitControlButton` through the package public entry (`packages/foldkit/src/public.ts`). The helper builds a native DOM button and leaves its ownership and content lifecycle with the caller (`packages/foldkit/src/ui/control-button.ts`); the package stylesheet supplies focus-visible indication (`packages/foldkit/src/style.css`). Its production E2E imports through the package-facing fixture and exercises equivalent native behavior (`apps/foldkit/e2e/package-ui.ts`, `apps/foldkit/e2e/control-button.e2e.ts`).

Vue's `FlowControlButton` remains a Vue component that forwards native attrs and slot content (`packages/vue/src/ui.ts`). In the focused host contract suite, disabled behavior is asserted on a custom FlowControlButton; the tested callback invocations are on FlowControls zoom/fit actions, not on a custom FlowControlButton callback (`apps/vue/e2e/canvas-ui-contract.e2e.ts`). These host-native lifecycle shapes are recorded as implementation evidence only. The E2Es do not mount the pinned React implementation or establish output parity.
