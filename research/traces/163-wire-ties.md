# Plan 163: wire ties

## Evidence and design boundary

The desired behavior is the maintainer's 2026-10-25 recording, broken down in `research/desired-features.md`. Plan 163 at commit `5fda81a` adopts D11: explicit toolbar mode, focusable/selectable/Delete-removable markers, one membership per edge, multiple ties per bundle, explicit edge removal, persistence beyond v4, pruning on edge deletion, membership retention on reconnection, four-unit lanes and at least two edges. There is no parity catalog entry.

Inspected recording frames are `/tmp/vid145/sheet1.jpg`, `/tmp/vid145/c_7.5.jpg` and `/tmp/vid145/c_22.jpg`. They show a thin lavender guide, a compact dark tooltip next to the pointer, mixed colored parallel lanes, and a short pale perpendicular tie bar. These frames establish appearance and demonstrated outcomes, not hidden source behavior or exact pixel constants.

The chosen ownership is document-level bundles, separate from opaque edge data and generated geometry. Rewriting each edge's manual route was rejected because it duplicates shared membership and cannot represent one atomic movable tie. A graph-space preview stays in app composition; one release submits one ordinary transaction. This keeps history and controlled acceptance with the existing owner. Browser capture, focus, listeners, animation frames and cleanup stay in `apps/`. New shared graph modules isolate the work from Plan 161's concurrent measurement changes.

## Round 2 spline review

The parent review identified visible corners in the first tie's approach and the last tie's exit. The original free spline was C1 at its joins, but every knot used the shorter adjacent span to size both derivatives. A 24-unit tie reach therefore restricted a long fan section to a very short control reach. The resulting tight curvature looked angular despite exact endpoint derivative equality.

`flowBundleSpline` at `packages/core/src/domain/flow-bundle-geometry.ts:216` now sizes each cubic's two controls to one third of that cubic's chord length. The source and target retain handle-side tangents. Tie entry, center and exit retain the common centerline tangent and local-normal lane offsets. Each join has parallel, forward-pointing derivatives, which establishes G1 continuity. Four-unit tie spacing, lane order, shared path labels and hit testing retain their existing owners. The configured router still uses its clearance-reserved rounded corridor.

The core regression at `packages/core/src/domain/flow-bundle.test.ts:191` checks both lanes through two bent ties. It checks the cross product and positive dot product of the exact incoming and outgoing cubic derivatives at every join. It also flattens every cubic into 1,024 intervals and bounds each consecutive tangent turn below 0.01 radians, including the joins. Running this test against `b395e32` failed the sampled-turn bound. The changed implementation passes. The Vanilla rendered-path regression also fails against the original implementation.

The browser regression at `apps/shared/wire-ties/acceptance.ts:194` reads each actual SVG path with `getPointAtLength`, samples every 0.1 graph unit from handle to handle and bounds consecutive tangent turns below 0.05 radians, about 2.86 degrees. It tests free splines and configured routing in all hosts. The existing obstacle-clearance exercises also check this bound on committed paths, live drag previews and the shared corridor between two ties. Assertions wait for the accepted route to reach the DOM. These numerical bounds apply to the regression fixtures, rather than all possible degenerate documents.

## Conformity and deviations

- **Conforming to the observed recording:** slash guide/count, a second-tie hint, mixed colored lanes, crossing-order membership, perpendicular markers, smooth fan sections and draggable graph-space ties. The test boundary is the pure contract plus the three-host gesture suite, with screenshots compared visually to the supplied frames. Final browser status is recorded above.
- **Intentionally different or specified beyond the recording:** D11's explicit toolbar, focus/Delete affordances, exclusive memberships, explicit edge removal, singleton pruning, persistent v5 bundles, clipboard and undo. These are the maintainer's adopted policy, not claims about the recorded editor's hidden behavior.
- **Intentionally different under a configured orthogonal router:** tie tangents align to the router's cardinal directions, with rounded fan/inter-tie sections and explicit unreachable fallback. This preserves the configured obstacle/port contract; the no-router recipe uses free-angle cubic splines. The real libavoid tests and configured-router browser case bound this behavior.
- **Unverified:** the recorded editor's implementation, its undisclosed activation/removal policy, exact screenshot pixel parity, other framework hosts, full-profile acceptance and collector-side telemetry delivery. Source similarity is not parity evidence.
