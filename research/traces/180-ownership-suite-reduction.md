# Plan 180 ownership suite reduction

## Test boundaries

Synthetic dispatch, reentry, disposal, supersession, acquisition faults and watcher drains run as direct Vitest adapter unit tests. Vue tests live beside the reusable adapter in packages/vue/tests/ownership/. Vanilla tests live in apps/vanilla/tests/ownership/, because @flow/vanilla owns its renderer and browser lifecycle there. Moving that production code into core would violate its browser-independent boundary.

The unit tests mount the real adapter into a document and call fixture functions directly. They run in Chromium through Vitest Browser Mode because the adapters require DOM event propagation, Vue rendering, ResizeObserver and requestAnimationFrame. They have no application navigation, Playwright Page object, application server, or page.evaluate bridge. They import source APIs and retain the literal callback streams, captures, snapshots, resource identities and errors from the original tests. These are DOM-backed unit tests, not Node-only reducer tests. The existing pure core session reduction tests remain separate.

Retained e2e suites cover native per-host pointer and keyboard input, actual capture, framework mounting, and rendered geometry. Renderer projection, custom geometry, renderer currency and numeric map mutation remain in the Vanilla ownership suite. Native threshold, connection, keyboard, viewport and host lifecycle suites remain per host. Foldkit input ownership remains unchanged.

Both unit hosts share one fixture for the document, root, synthetic capture receipts and pointer dispatch. The existing apps/shared-e2e fixture serves both direct unit tests and native browser contracts. Host-specific callback and renderer hooks stay with their implementation owner.
