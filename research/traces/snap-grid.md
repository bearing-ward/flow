# Snap-grid node movement

Status: pinned xyflow production paths traced at commit `0a1f9575b25679f2880175de8d3eae21aedde921`. No pinned test directly asserts snapped node coordinates. Paths below are relative to `research/artifacts/xyflow/0a1f9575b25679f2880175de8d3eae21aedde921/`.

## Public options and browser entry

React Flow exposes `snapToGrid?: boolean` and `snapGrid?: SnapGrid`; its prop comment says snapping applies while nodes are dragged at `packages/react/src/types/component-props.ts:374`. `ReactFlow` forwards both props into its store updater at `packages/react/src/container/ReactFlow/index.tsx:75` and `packages/react/src/container/ReactFlow/index.tsx:217`. The initial store uses `[15, 15]` with snapping disabled at `packages/react/src/store/initialState.ts:117`, and `StoreUpdater` tracks both prop changes at `packages/react/src/components/StoreUpdater/index.tsx:40`. A draggable node's `NodeWrapper` attaches `useDrag` at `packages/react/src/components/NodeWrapper/index.tsx:64`; `useDrag` creates the shared `XYDrag` instance and attaches it to the node DOM element at `packages/react/src/hooks/useDrag.ts:35` and `packages/react/src/hooks/useDrag.ts:63`.

Svelte exposes one optional `snapGrid` prop at `packages/svelte/src/lib/container/SvelteFlow/types.ts:228`. Its store derives `null` when the prop is absent at `packages/svelte/src/lib/store/initial-store.svelte.ts:312`. `NodeWrapper` attaches the `drag` action at `packages/svelte/src/lib/components/NodeWrapper/NodeWrapper.svelte:238`; the action passes `snapGrid` and `snapToGrid: !!snapGrid` to the same `XYDrag` engine at `packages/svelte/src/lib/actions/drag/index.ts:20`. React and Svelte therefore share drag geometry but differ in their public enablement options.

## State, geometry, and rendered output

At drag start, `XYDrag` reads the current transform and snap options, converts the browser event to flow coordinates, and captures the selected drag items with each node's initial pointer offset at `packages/system/src/xydrag/XYDrag.ts:259` and `packages/system/src/xydrag/utils.ts:34`. `getPointerPosition` subtracts the container's screen origin and applies the inverse viewport transform. It also returns a grid-snapped pointer coordinate used to skip redundant drag events at `packages/system/src/utils/dom.ts:11`. The underlying `snapPosition` rounds each flow-coordinate axis to its grid multiple at `packages/system/src/utils/general.ts:161`.

For one node, `XYDrag` subtracts the saved pointer offset from the current pointer and calls `snapPosition` on that candidate node position at `packages/system/src/xydrag/XYDrag.ts:158`. For multiple nodes, it calls `calculateSnapOffset` using the first drag item's candidate position; that helper returns the difference between the candidate and its snapped position at `packages/system/src/xydrag/utils.ts:126`. `XYDrag` adds the same offset to each candidate position, preserving the group's relative spacing, before `calculateNodePosition` applies node and group extents at `packages/system/src/xydrag/XYDrag.ts:146` and `packages/system/src/xydrag/XYDrag.ts:176`. The drag update runs only when a position changes, publishes the drag-item map with `dragging: true`, and sends a final `dragging: false` update on release at `packages/system/src/xydrag/XYDrag.ts:201` and `packages/system/src/xydrag/XYDrag.ts:364`.

React maps the drag-item map to `position` node changes, then applies default-node changes and invokes `onNodesChange` for controlled owners at `packages/react/src/store/index.ts:211` and `packages/react/src/store/index.ts:265`. `NodeWrapper` renders the resulting absolute position in a CSS `translate` at `packages/react/src/components/NodeWrapper/index.tsx:184`. Svelte updates its node array from the same drag-item map at `packages/svelte/src/lib/store/index.ts:61`; its `NodeWrapper` attaches the drag action and renders the moved node at `packages/svelte/src/lib/components/NodeWrapper/NodeWrapper.svelte:238` and `packages/svelte/src/lib/components/NodeWrapper/NodeWrapper.svelte:274`.

Keyboard movement also uses the grid. React takes each axis's grid interval as the arrow-key step and snaps the resulting position at `packages/react/src/hooks/useMoveSelectedNodes.ts:19`; Svelte does the same at `packages/svelte/src/lib/store/index.ts:327`. The React `screenToFlowPosition` public API accepts optional snapping and a grid override, then passes both through the inverse viewport calculation at `packages/react/src/hooks/useViewportHelper.ts:84`. Svelte's corresponding API accepts a snapping flag and uses its configured grid at `packages/svelte/src/lib/hooks/useSvelteFlow.svelte.ts:482`. These conversion APIs are separate from the node drag gesture.

## Flow implementation and test path

`SnapGridSchema` accepts finite, positive `x` and `y` intervals at `packages/core/src/domain/flow-snap-grid.schema.ts:5`. `snapPosition` rounds each axis independently, and `snapGroupDelta` snaps one group anchor then returns the shared displacement at `packages/core/src/domain/flow-snap-grid.schema.ts:12` and `packages/core/src/domain/flow-snap-grid.schema.ts:20`. `moveNodeDrag` and `completeNodeDrag` apply an optional grid to a single node. `moveNodeGroupDrag` applies the shared snapped delta to every selected node at `packages/core/src/domain/flow-runtime.schema.ts:504` and `packages/core/src/domain/flow-runtime.schema.ts:527`.

The vanilla mount option decodes the optional grid at `apps/vanilla/src/mount-flow.ts:79`. The node pointer path uses that grid for transient single and group positions, updates DOM node transforms and edge geometry, then publishes one final semantic position change on release at `apps/vanilla/src/mount-flow.ts:1477` and `apps/vanilla/src/mount-flow.ts:1518`. `publishChange` applies the final change in uncontrolled mode or restores the authoritative positions until controlled acknowledgement at `apps/vanilla/src/mount-flow.ts:1071` and `apps/vanilla/src/mount-flow.ts:1097`. The keyboard path uses each grid interval as its arrow step, with Shift multiplying it by four, at `apps/vanilla/src/mount-flow.ts:2557`. `moveSelectedNodes` then rounds each selected node independently at `packages/core/src/domain/flow-runtime.schema.ts:553`. The playground enables a 10-by-10 grid at `apps/vanilla/src/main.ts:135`.

The Flow unit test rejects nonpositive or nonfinite intervals, checks nonuniform rounding with negative coordinates, and checks that one snapped group anchor preserves member spacing at `packages/core/src/domain/flow-snap-grid.schema.test.ts:10`. The Flow Playwright test mounts two selected nodes with non-grid starting positions and a nonuniform grid at `apps/vanilla/e2e/gesture-options.e2e.ts:138`. It drags the group and checks one `nodes-position` change that preserves their 204-unit horizontal spacing, then presses ArrowRight and checks independent keyboard snapping at `apps/vanilla/e2e/gesture-options.e2e.ts:219`. All five tests in `gesture-options.e2e.ts` passed in the targeted Playwright run.

## Conformity and deviations

- **Conforming:** Flow's pure geometry rounds a single position to each grid axis and snaps a dragged group through one anchor displacement, matching the pinned xyflow source rule. Keyboard movement uses grid-sized steps and rounds each selected node independently, as in the React and Svelte paths. Unit tests cover nonuniform intervals, negative coordinates, and group spacing; the Flow browser test covers group drag and keyboard output. These are source comparisons, not a live upstream parity claim.
- **Intentionally different:** Flow uses one optional schema-validated grid with named axes. React exposes `snapToGrid` plus a tuple grid; Svelte uses a nullable tuple grid. Flow publishes one final semantic position change, while React emits position changes during the drag and on release and Svelte updates its node array during movement. The vanilla adapter owns pointer lifecycle.
- **Unverified:** Flow snap output has not been compared with a live pinned xyflow build. The pinned browser tests do not establish snapped positions. Snapping with zoom, extents, controlled acknowledgement, and cancellation remains outside the current Flow test boundary.
