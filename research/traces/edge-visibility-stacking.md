Inside `EdgeWrapper`, `defaultEdgeOptions` merge with the edge at `packages/react/src/components/EdgeWrapper/index.tsx:39`. Its store selector resolves source and target nodes, endpoint geometry, and elevated z-index at `packages/react/src/components/EdgeWrapper/index.tsx:73` and `packages/react/src/components/EdgeWrapper/index.tsx:91`. `getElevatedEdgeZIndex` returns the explicit z-index in manual mode. In basic mode it adds 1000 for a selected edge when elevation is enabled, plus the higher relevant node z-index, including parented nodes, at `packages/system/src/utils/edges/general.ts:40`. The wrapper returns no DOM when `edge.hidden` or any endpoint coordinate is unavailable at `packages/react/src/components/EdgeWrapper/index.tsx:120`. Otherwise it places one edge group inside its own SVG with `style={{ zIndex }}` at `packages/react/src/components/EdgeWrapper/index.tsx:183`; the built-in edge component then produces the visible SVG path at `packages/react/src/components/EdgeWrapper/index.tsx:218`. The group supplies visible-stroke pointer events at `packages/system/src/styles/init.css:127`.

The hidden edge remains in the store's edge array and can still be in `useVisibleEdgeIds` when viewport culling is off; rendering stops at the wrapper. Visibility and z-index do not mutate the public edge object on this path.

## Svelte production path

Svelte's visible-element derivation starts with the store edge array at `packages/svelte/src/lib/store/initial-store.svelte.ts:245`. `getLayoutedEdges` excludes edges with missing endpoints or hidden endpoint nodes at `packages/svelte/src/lib/store/visibleElements.ts:88`. When `onlyRenderVisibleElements` is enabled, it applies the same system `isEdgeVisible` geometry predicate at `packages/svelte/src/lib/store/visibleElements.ts:96`. It computes endpoint positions and effective z-index from the edge, defaults, selected state, and node state at `packages/svelte/src/lib/store/visibleElements.ts:129`. The store exposes that map as `visible.edges` at `packages/svelte/src/lib/store/initial-store.svelte.ts:278`; `EdgeRenderer` iterates its values in keyed order at `packages/svelte/src/lib/container/EdgeRenderer/EdgeRenderer.svelte:21`.

The Svelte wrapper destructures `hidden` and `zIndex` from the layouted edge at `packages/svelte/src/lib/components/EdgeWrapper/EdgeWrapper.svelte:24`. It creates an SVG only for `!hidden`, sets its CSS z-index, and mounts the edge group and edge component at `packages/svelte/src/lib/components/EdgeWrapper/EdgeWrapper.svelte:109` and `packages/svelte/src/lib/components/EdgeWrapper/EdgeWrapper.svelte:146`. Thus hidden edges can exist in the layouted map yet produce no SVG. Svelte also excludes edges whose endpoint _nodes_ are hidden during layout, unlike the cited React `useVisibleEdgeIds` hook, which does not itself check node `hidden`.

## Conformity and deviations

- **Conforming:** Hidden edges leave rendered output. Vanilla applies selected paint elevation only when enabled. Vue preserves document order and retained edge identity while applying CSS z-index. Focus survives the tested elevation changes.
- **Intentionally different:** Vanilla orders paths inside a shared SVG layer and labels and anchors in separate layers when elevation is active. Pinned xyflow positions independent SVG wrappers with CSS z-index.
- **Unverified:** Broader overlap hit ordering, other engines, and live React runtime parity remain unverified. Plan 138 tests local Chromium behavior through the unchanged upstream ports.
