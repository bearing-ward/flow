## Svelte production path

Svelte's visible-element derivation starts with the store edge array at `packages/svelte/src/lib/store/initial-store.svelte.ts:245`. `getLayoutedEdges` excludes edges with missing endpoints or hidden endpoint nodes at `packages/svelte/src/lib/store/visibleElements.ts:88`. When `onlyRenderVisibleElements` is enabled, it applies the same system `isEdgeVisible` geometry predicate at `packages/svelte/src/lib/store/visibleElements.ts:96`. It computes endpoint positions and effective z-index from the edge, defaults, selected state, and node state at `packages/svelte/src/lib/store/visibleElements.ts:129`. The store exposes that map as `visible.edges` at `packages/svelte/src/lib/store/initial-store.svelte.ts:278`; `EdgeRenderer` iterates its values in keyed order at `packages/svelte/src/lib/container/EdgeRenderer/EdgeRenderer.svelte:21`.

The Svelte wrapper destructures `hidden` and `zIndex` from the layouted edge at `packages/svelte/src/lib/components/EdgeWrapper/EdgeWrapper.svelte:24`. It creates an SVG only for `!hidden`, sets its CSS z-index, and mounts the edge group and edge component at `packages/svelte/src/lib/components/EdgeWrapper/EdgeWrapper.svelte:109` and `packages/svelte/src/lib/components/EdgeWrapper/EdgeWrapper.svelte:146`. Thus hidden edges can exist in the layouted map yet produce no SVG. Svelte also excludes edges whose endpoint _nodes_ are hidden during layout, unlike the cited React `useVisibleEdgeIds` hook, which does not itself check node `hidden`.

## Conformity and deviations

- **Conforming at the tested local Chromium boundary:** every host uses shared semantic edge levels and retained per-edge SVGs in document order; built-in labels use the same levels. The 2026-10-22 decision supersedes Vanilla's historical shared-SVG policy. The upstream ports and local overlap/focus regressions named above define the acceptance boundary.
- **Intentionally different representation:** Flow's built-in labels remain HTML. Vanilla retains attachment-centered reconnect controls in its host overlay and raises that overlay above the highest edge paint level. Pinned `packages/react/src/components/EdgeWrapper/index.tsx:251` instead owns controls inside its edge SVG, with a radius shift at `packages/react/src/components/Edges/EdgeAnchor.tsx:51`. Retaining Flow's documented control geometry preserves native reconnect and lifecycle contracts. The unchanged canvas, connection-threshold, and interaction-lifecycle suites define this separate control boundary. Foldkit reconnect controls and custom portal layers retain their existing policies.
- **Unverified:** other browser engines, broad culling parity, and live React runtime parity beyond the pinned unchanged ports and local Chromium overlap evidence.
