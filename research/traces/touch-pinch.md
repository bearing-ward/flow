# Touch pan and pinch zoom

Status: traced from pinned xyflow source at commit `0a1f9575b25679f2880175de8d3eae21aedde921`. The pinned browser tests cover one-finger touch panning and touch selection. They do not exercise a two-finger pinch or trackpad pinch. Flow's targeted Chromium touch test passed in this checkout with `bunx playwright test apps/vanilla/e2e/movement-slices.e2e.ts -g 'real touch pan and pinch' --reporter=line`. The full `bun run verify` also passed, including 48 browser tests.

All xyflow paths below are relative to `research/artifacts/xyflow/0a1f9575b25679f2880175de8d3eae21aedde921/`.

## Production path

`ReactFlow` defaults `zoomOnPinch` and `panOnDrag` to true, with zoom limits of 0.5 and 2. It passes these options into `GraphView` at `packages/react/src/container/ReactFlow/index.tsx:87-100` and `packages/react/src/container/ReactFlow/index.tsx:277-289`. `GraphView` forwards them to `FlowRenderer` at `packages/react/src/container/GraphView/index.tsx:135-149`. `FlowRenderer` sends the effective pan option and pinch option to `ZoomPane` at `packages/react/src/container/FlowRenderer/index.tsx:77-105`.

`ZoomPane` mounts `XYPanZoom` on `.react-flow__renderer`, stores the instance and initial transform, and forwards start, move, and end callbacks from the adapter at `packages/react/src/container/ZoomPane/index.tsx:70-107`. It updates the adapter with `panOnDrag`, `zoomOnPinch`, and the selection and connection states at `packages/react/src/container/ZoomPane/index.tsx:111-132`. `XYPanZoom` installs d3-zoom on the renderer with zoom and translation extents at `packages/system/src/xypanzoom/XYPanZoom.ts:83-100`, then installs its filter and zoom callbacks at `packages/system/src/xypanzoom/XYPanZoom.ts:172-215`.

For a one-finger touch drag, the pane's pointer capture handler returns before starting a selection when panning is enabled and the selection key is not pressed. This leaves the gesture for d3-zoom at `packages/react/src/container/Pane/index.tsx:141-160`. The d3 filter accepts `touchstart` when panning is enabled, except during active selection or connection, or inside a `nopan` element. Mouse-button arrays restrict mouse input only at `packages/system/src/xypanzoom/filter.ts:49-75` and `packages/system/src/xypanzoom/filter.ts:91-108`. The pane CSS sets `touch-action: none` at `packages/system/src/styles/init.css:69-72`.

For direct two-finger touch, the same d3-zoom installation receives the gesture. The filter explicitly rejects a multi-touch `touchstart` when `zoomOnPinch` is false, and calls `preventDefault` to suppress native page zoom at `packages/system/src/xypanzoom/filter.ts:77-84`. The pinned xyflow files delegate the two-touch geometry to d3-zoom. They do not define the midpoint or distance formula locally, so the exact direct-touch transform is outside this source trace.

Trackpad pinch follows a distinct wheel path. The filter treats Ctrl-modified wheel input as pinch when `zoomOnPinch` is true at `packages/system/src/xypanzoom/filter.ts:33-36` and rejects it when the option is false at `packages/system/src/xypanzoom/filter.ts:77-79`. When pan-on-scroll is active, `createPanOnScrollHandler` prevents native page zoom, computes a wheel zoom factor, and calls d3 `scaleTo` around the local pointer at `packages/system/src/xypanzoom/eventhandler.ts:73-94`. Otherwise `createZoomOnScrollHandler` forwards the wheel input to d3's saved zoom handler after handling `nowheel` and `preventScrolling` at `packages/system/src/xypanzoom/eventhandler.ts:143-162`. The wheel factor is derived from `deltaY`, `deltaMode`, and a macOS Ctrl multiplier at `packages/system/src/xypanzoom/utils.ts:36-40`.

d3 zoom events report `[x, y, zoom]` through `onTransformChange` at `packages/system/src/xypanzoom/eventhandler.ts:188-207`. `ZoomPane` emits the viewport and writes the transform into the store only for an uncontrolled viewport at `packages/react/src/container/ZoomPane/index.tsx:59-67`. `Viewport` observes that store transform and writes CSS `translate(...) scale(...)` to the rendered viewport element at `packages/react/src/container/Viewport/index.tsx:7-8` and `packages/react/src/container/Viewport/index.tsx:20-55`. Zoom is constrained by the d3 scale extent before this rendered output at `packages/system/src/xypanzoom/XYPanZoom.ts:83-86`.

## Test path and boundary

The pinned Playwright pane suite sends real browser touch input through Chromium CDP `Input.dispatchTouchEvent`, moving one touch point over four steps at `tests/playwright/e2e/pane.spec.ts:18-45`. With touch enabled, it checks that a touch drag changes the viewport translation and creates no selection when primary mouse dragging is reserved for selection at `tests/playwright/e2e/pane.spec.ts:215-235`. With Shift held, the companion case checks that the touch drag displays a selection rectangle while the viewport stays fixed at `tests/playwright/e2e/pane.spec.ts:237-259`.

The pinned test search found no direct two-touch pinch or Ctrl-wheel trackpad pinch case. The production path shows those inputs are routed, but the pinned browser tests do not establish their end-to-end transform behavior.

## Flow implementation and test boundary

Flow's canvas uses `touch-action: none` at `apps/vanilla/src/style.css:27-35`. The host stores a schema-derived `ActivePinch` and touch positions by pointer ID at `packages/core/src/domain/flow-runtime.schema.ts:72-80` and `apps/vanilla/src/mount-flow.ts:264-266`. On a first touch over empty canvas, it captures the pointer and starts the existing viewport pan. A Shift-modified pointer starts a selection rectangle instead at `apps/vanilla/src/mount-flow.ts:1622-1685`. On a second touch during a viewport pan, `startPinch` captures the second pointer and saves both positions with the current viewport at `apps/vanilla/src/mount-flow.ts:1566-1601`.

`movePinch` takes the two start positions, the two current positions, and the zoom limits. It scales zoom by the distance ratio, clamps it, and translates so the original flow position under the start midpoint stays under the current midpoint at `packages/core/src/domain/flow-runtime.schema.ts:449-485`. During pointer movement, the host calls this function and writes the result to the viewport element at `apps/vanilla/src/mount-flow.ts:1704-1715` and `apps/vanilla/src/mount-flow.ts:339-346`. The DOM output is CSS `translate(...) scale(...)` plus `data-x`, `data-y`, and `data-zoom` at `apps/vanilla/src/mount-flow.ts:166-171`.

The host publishes one semantic viewport change on the first pinch pointer's release and releases both captures at `apps/vanilla/src/mount-flow.ts:1873-1909`. Cancellation releases both captures and restores the authoritative viewport; both pointer cancellation and host destruction call that cleanup at `apps/vanilla/src/mount-flow.ts:1817-1852` and `apps/vanilla/src/mount-flow.ts:2397-2408`. Uncontrolled publication applies the new viewport; controlled publication restores the caller's authoritative viewport pending acknowledgement at `apps/vanilla/src/mount-flow.ts:973-982`. Ctrl-modified wheel input remains a separate cursor-anchored zoom path at `apps/vanilla/src/mount-flow.ts:2287-2313`.

Flow's browser scenario sends real Chromium CDP touch events. It asserts that one-finger movement publishes `x: 30` with unchanged zoom, then spreads two touch points around a fixed midpoint and asserts `x: -250` with `zoom: 1.5` at `apps/vanilla/e2e/movement-slices.e2e.ts:243-290`. That checks the translation needed to keep the midpoint's flow position fixed during zoom. The targeted test and the full verifier passed locally. The scenario does not assert a moving midpoint, rendered CSS, controlled acknowledgement, cancellation, or Ctrl-wheel behavior. Those remain separate test boundaries.

## Conformity and deviations

- **Conforming:** Flow sets `touch-action: none`, pans with one touch, and changes zoom with two touches. Flow's browser scenario checks the published pan, pinch zoom, and fixed-midpoint translation.
- **Conforming by source:** Ctrl-modified wheel input follows a separate cursor-anchored zoom path. The wheel factors differ, and the touch browser scenario does not exercise this path.
- **Intentionally different:** Flow owns pointer events and pure midpoint geometry directly, while xyflow delegates direct touch gestures to d3-zoom. Flow also emits one semantic viewport change when a pinch ends instead of forwarding the reference's start, move, and end callbacks.
- **Unverified:** The current Flow browser scenario does not check a moving pinch midpoint, CSS output, controlled acknowledgement, cancellation, or Ctrl-wheel. The pinned xyflow browser tests omit direct pinch and trackpad pinch assertions.
