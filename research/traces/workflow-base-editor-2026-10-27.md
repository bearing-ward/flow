## Shared public contracts

`SavedWorkflowSchema` at `packages/workflow/src/workflow-persistence.ts:16` defines `{ format: '@flow/workflow', version: 1, workflowVersion: 1, graph, theme }`. `SavedWorkflow` derives from its encoded schema. `encodeSavedWorkflow` at `packages/workflow/src/workflow-persistence.ts:38` validates workflow semantics before calling core's `encodeVersionedFlowDocument` at `packages/core/src/domain/flow-persistence.ts:588`. The returned JSON is detached from accepted state. Core selects the oldest graph envelope that represents the document, including version 6 for rotation.

`decodeSavedWorkflow` at `packages/workflow/src/workflow-persistence.ts:57` accepts unknown file data. It rejects unknown or extra envelope fields, then calls `decodeVersionedFlowDocument` at `packages/core/src/domain/flow-persistence.ts:660` and `decodeWorkflowDocument` at `packages/workflow/src/workflow-document.ts:49`. Core retains its established graph migration policy. Workflow envelope and semantic version 1 have no historical migration; unknown versions fail closed. `WorkflowPersistenceError` reports `invalid-workflow-envelope` without file content. Graph integrity and workflow decode/validation failures retain their typed errors.

Run status, outputs, credentials, provider objects and measurements have no saved workflow configuration field. The owner never inserts them into graph metadata. Core's saved projection omits selection and browser measurements. Opaque allowed JSON metadata remains caller-owned and must not contain secrets. No backend persistence, viewport restoration or resumable run is introduced.

The existing architecture rule rejects workflow package, subpath and implementation dependencies from core and every generic adapter. Plan 173 extends the negative fixtures to persistence imports in `scripts/check-architecture.ts`. The workflow package still depends only on its existing core and Effect peers. App composition reuses the existing optional layout workspace.

## Production browser paths

All hosts enter through their `/workflow/index.html` and `workflow/main.ts`, then compose `mountWorkflowControls` at `apps/shared/workflow/demo.ts:111`. That module prepares existing workflow edits and validation and owns the browser action queue, configuration focus and clipboard lifecycle. `mountWorkflowEditor` at `apps/shared/workflow/editor-controls.ts:114` adds layout, fit, theme and export. Export produces selectable JSON. Import decodes the envelope before public replacement, then restores theme only after acceptance. Raw workflow fixture imports retain their separate semantic decode path. Malformed imports leave accepted state and history intact.

Vanilla enters at `apps/vanilla/workflow/main.ts:96`. Its `createFlow` controller owns the uncontrolled document. `getSnapshot` and `getInternalNode` supply accepted state and measured internals to `getFlowLayoutInput`; `applyEdit` accepts one position edit. `fitView`, `setColorMode`, undo/redo, subscriptions and destroy are public controller operations. The subscription updates accepted workflow validation and transient runs, then refreshes browser controls. Renderer subscriptions release on destroy.

Vue enters at `apps/vue/workflow/main.ts:76` inside `FlowProvider` and a mounted `useFlow` scope. It reads `flow.document` and measured `getInternalNode`, edits with `applyEdit`, fits after `nextTick`, and passes reactive theme to `FlowCanvas.colorMode`. Accepted-state subscriptions refresh validation and cancel stale runs; `onScopeDispose` releases controls, run subscriptions and the run owner. The reusable Vue package contains no workflow dependency.

Foldkit enters at `apps/foldkit/workflow/main.ts:138`. Its runtime owns the accepted model. Public `createFoldkitFlowInstance` snapshot and `getInternalNodes` responses supply state and measured geometry. `applyEdit` checks the accepted response before proceeding. `createViewportClient` fits, history ports replay accepted state, and `HostAction.SetColorMode` changes theme. The node-measurement observer sends public MeasureNodes actions. Before reporting layout completion, the host waits for node positions and handle declarations in the DOM, then for the accepted fitted viewport's CSS transform. Disposal releases every client, observer, subscription and runtime.

Layout reads measured visible top-level nodes through `getFlowLayoutInput` at `packages/core/src/domain/flow-layout.ts:51`. The shared browser owner runs the existing ELK implementation at `packages/layout/src/public.ts:34` within `createFlowLayoutSession` at `packages/core/src/domain/flow-layout-request.ts:122`. Authored state and measurement revision changes discard stale results. `applyFlowLayoutPositions` preserves all other node fields; edges, workflow roles/configuration, child geometry, manual routes and bundles stay intact. One accepted edit makes layout one undo step. The app then fits and observes render readiness. No workflow-specific layout solver or persistence engine replaces core behavior.

Themes use native host color-mode APIs and core resolution, with a lifecycle-owned media-query listener for application chrome. Run UI remains explicitly labeled Offline simulation. Edits invalidate runs rather than save output into document history.

## Conformity and deviations

- Conforming to adopted Unit 5 and D1-D8: all three host routes compose measured ELK layout/fit, settings, history, clipboard, semantic validation, local save/reload/restore and the existing offline runner. Package, production-route browser, real WebSocket and packed-consumer checks define this functional boundary.
- Intentionally different: execution is deterministic local simulation, configuration panels are typed Flow controls, and local workflow persistence has a separately versioned envelope. These are adopted maintainer choices. Optional presentation groups remain spatial, room sync transports accepted documents, and neither executes subworkflows or distributed runs.
- Unverified: private upstream workflow internals, runtime subscriptions, exact layout coordinates and visual output, upstream persistence/failure/cancellation semantics, React/Svelte workflow hosts, external providers, durable jobs, run resumption and collector-side OTLP delivery. C records achievable public outcomes, not source similarity, upstream runtime parity or full-suite acceptance.
