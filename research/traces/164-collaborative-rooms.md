# Plan 164: collaborative rooms

## Requirements and design

Plan 164 at commit b5059ce implements unit 12 of Plan 149 and the recorded D12 decision. The approved integration is optional Yjs plus y-websocket. Hosting, authenticated room access, durability and offline retention remain open, as recorded in the package README. Imported research artifacts are unchanged.

The public [Collaborative example](https://reactflow.dev/examples/interaction/collaborative), accessed 2026-10-26, describes shared rooms, live edits and right-click creation and names Yjs/y-websocket dependencies. Linked [Yjs provider documentation](https://docs.yjs.dev/ecosystem/connection-provider/y-websocket) describes room transport, awareness, reconnect and provider destruction. The [UndoManager documentation](https://docs.yjs.dev/api/undo-manager) defines tracked origins and transaction capture. Subscription-only Pro source and hidden conflict policy were not accessed. These are public outcome requirements, not source-parity evidence.

I compared whole-document snapshot registers with per-entity field registers. A snapshot register loses unrelated concurrent edits and snapshot undo can replace peer work. Field registers with separate membership tombstones let distinct node/edge properties converge while a move never resurrects deleted membership. Live node reads are separate from accepted state in the hosts, so drag previews travel in awareness and are projected without durable history. Release publishes the accepted edit once; cancellation removes the preview. Arrays and opaque JSON remain atomic values. Core owns the deterministic relational projection; the optional package owns CRDT/transport/history; browser composition owns accepted-state binding, listeners, coordinates and framework cleanup.

Usage is scope acquisition through `acquireYjsRoom`, accepted before/after commits, subscription-driven remote replacement, then scope release. The integration's `history()` uses the Plan 150 status contract. Origin-scoped Yjs inverses replace standalone snapshot replay in room controls and keyboard shortcuts. The wrapper isolates one stack entry per Undo/Redo call so an overwritten entry cannot skip into an older transaction. Host standalone snapshot-history APIs remain for non-collaborative use.

## Production path

1. Real route entry points are `apps/vanilla/src/collaborative-demo.ts:13`, `apps/vue/src/collaborative-demo.ts:30`, and `apps/foldkit/src/collaborative-demo.ts:31`. They create the existing public hosts and compose the shared browser binding at `apps/shared/collaborative/demo.ts:68`. An absent `room` creates a random share URL. The initial document is empty, so concurrent joiners do not race to replace a seed snapshot.
2. Right-click enters the pane listener at `apps/shared/collaborative/demo.ts:241`. The host converts client coordinates to graph coordinates and submits one `add-nodes` edit with a UUID. Ordinary pointer dragging stays in the existing host gesture implementation. Accepted state enters `apps/shared/collaborative/demo.ts:197`; only changed semantic fields are committed. Rejected proposals never publish accepted state and therefore never reach the room.
3. `acquireYjsRoom` at `packages/collaboration-yjs/src/public.ts:529` uses Effect acquire/release. The provider disables BroadcastChannel, so room updates and awareness use the actual websocket server. `FlowRoomError` at `packages/collaboration-yjs/src/public.ts:25` represents acquisition, commit, decode and lifecycle failures. Status and typed last failure remain observable while the provider reconnects.
4. The map decoder at `packages/collaboration-yjs/src/public.ts:131` validates tuple keys, JSON values, boolean membership, entity-ID/key agreement, Flow nodes/edges/bundles and metadata. Its projection at `packages/core/src/domain/flow-room.ts:40` removes local selection/measurements, detaches missing or cyclic parents, retains orphan coordinates using authored parent bounds/origins, removes invalid extent constraints, filters dangling/invalid-handle edges, and prunes missing or multiply owned bundle memberships. Structurally invalid input retains the last valid document and records a typed decode failure. All ordering uses code-unit ID comparison, independent of client locale.
5. Local semantic delta publication is `packages/collaboration-yjs/src/public.ts:271`. Each accepted command is one Y.Doc transaction with a local origin. Equal register values are not rewritten, so duplicate semantic publication is also idempotent. Durable fields include group membership, tree expansion data, shape data, manual routes, ordered v5 bundle members/ties, node origin and opaque JSON. Membership is `$alive`; an existing entity move changes position only. Deleted fields remain in the CRDT for convergence and selective undo. A deleted parent can therefore contribute its last authored position to orphan projection.
6. A room invalidation enters `apps/shared/collaborative/demo.ts:116`. The binding reads current host state, overlays decoded peer drag presence with `projectFlowRoomPresence`, retains local selection/safe measurements through `restoreFlowHistoryDocument`, and replaces with a remote transaction origin. Matching remote receipts are suppressed from local publication, preventing echo and extra undo entries. Document application pauses during a local pointer gesture and reconciles after it ends. Viewport remains local. Independent fields merge; concurrent writes to the same atomic register use Yjs ordering, without a wall-clock last-writer promise.
7. Vanilla remote replacement calls public `update` at `apps/vanilla/src/mount-flow.ts:14820`, then ordinary reconciliation, graph-space positions at `apps/vanilla/src/mount-flow.ts:4449`, edge geometry/DOM paths at `apps/vanilla/src/mount-flow.ts:4484`, and node CSS transforms at `apps/vanilla/src/mount-flow.ts:1787`. Accepted state is published at `apps/vanilla/src/mount-flow.ts:3988`.
8. Vue uses public `useFlow().updateDocument` through `packages/vue/src/use-flow.ts:687`; replacement is owned by `packages/vue/src/flow-canvas.ts:2872`. The active document builds shared graph geometry at `packages/vue/src/flow-canvas.ts:1782`; Physical edge handles resolve at `packages/vue/src/flow-canvas.ts:9994`, node positions become CSS at `packages/vue/src/flow-canvas.ts:9818`, and the ordinary viewport/edge DOM projection is at `packages/vue/src/flow-canvas.ts:11857`. The synchronous accepted-state watcher at `packages/vue/src/flow-canvas.ts:1600` drives the same binding. Vue lifecycle cleanup releases the room before unmounting its application.
9. Foldkit decodes `ports.acceptedStates` and sends public `HostAction.ReplaceDocument` at `apps/foldkit/src/collaborative-demo.ts:90`. The Runtime's model replacement at `packages/foldkit/src/graph.ts:3758` retains measurement lifecycle ownership and clears active pointer sessions. The normal graph view creates geometry at `packages/foldkit/src/graph.ts:7630`, calculates edge paths at `packages/foldkit/src/graph.ts:5534` and `packages/foldkit/src/graph.ts:7910`, and feeds its keyed DOM view and viewport transform at `packages/foldkit/src/graph.ts:8179`. Snapshot requests acknowledge the asynchronous replacement before the next queued room application.
10. Presence rendering at `apps/shared/collaborative/demo.ts:168` converts graph-space awareness cursors through the local viewport. Stale async renders are discarded. Presence and viewport never enter semantic history. A single animation-frame sampler reads Vanilla/Vue `getNodes` or the Foldkit live snapshot during a pointer gesture. The core presence projection at `packages/core/src/domain/flow-room.ts:159` changes only displayed positions, ignores deleted IDs and orders simultaneous previews by actor ID. Cursor and drag presence are ephemeral; accepted release owns the durable transaction. Reconnect advances awareness on every new socket connection. Local controls/shortcuts use the selective replay owner at `packages/collaboration-yjs/src/public.ts:318`, and pointer boundaries group accepted changes. A fresh `FlowPasteOptions.idNamespace` decoded at `packages/core/src/domain/flow-clipboard.ts:42` on every button/native paste separates IDs through `packages/core/src/domain/flow-clipboard-ids.ts:2` and the shared parent/endpoint/handle/bundle remapper. Text inputs retain native undo.
11. Disposal at `apps/shared/collaborative/demo.ts:409` aborts listeners, cancels the animation frame, invalidates pending samples, removes accepted/room subscriptions and cursor DOM, drains queued work and closes the Effect scope. The provider, awareness timer, UndoManager and Y.Doc are destroyed; Vue unmounts and Foldkit releases its measurement observer, snapshot client, instance and Runtime. Playwright's webServer lifecycle separately stops the local server after each test run.

## Production and test boundaries

Pure tests at `packages/core/src/domain/flow-room.test.ts:14` assert literal repaired positions, parent-cycle order, orphan origins/extents, surviving descendant membership, physical handles, dangling edges/bundles, local-field exclusion and deterministic ephemeral preview projection. `packages/core/src/domain/flow-room-clipboard.test.ts:58` exercises the real clipboard reducer/edit validator with two independent namespaces and checks literal parent, endpoint, handle and bundle remaps. Transport tests at `packages/collaboration-yjs/src/public.test.ts:46` start a real local server and independent providers. They exercise field convergence, duplicate websocket frames followed by an observed delivery barrier, reconnect, delete-versus-move, selective/no-op undo, typed malformed coordinates, identity, membership and recovery, local presentation exclusion, isolated rooms and scope release.

Host wrappers execute the same browser suite in `apps/shared/collaborative/acceptance.ts:93`. Real right-click, pointer drag, wheel, buttons and keyboard shortcuts exercise user behavior. The public fixture hook reads accepted snapshots and drives precise concurrent-edit/extension setup; it does not simulate a CRDT merge or rendered drag result. A separate three-origin test in `apps/shared/collaborative/mixed-host.e2e.ts:9` proves Vanilla/Vue/Foldkit convergence over the real server. Managed servers are created per run and destroyed on completion/failure. Unit servers use a separate port and teardown.

Existing `hostMount`, `hostDestroy`, `controllerUpdate`, `documentDecode`, `documentIntegrity`, `editPrepare` and `editFailure` spans cover lifecycle, decode, commit and failure boundaries. ## Conformity and deviations

- **Conforming to the accessible public outcome description:** optional Yjs/y-websocket rooms, share URL, live shared node/edge editing and right-click creation are the implementation target. The test boundary is the local real-transport and three-host acceptance suites, whose final results are recorded above. This is functional closeness to the public description, not a hidden-source or demo pixel comparison.
- **Intentionally different or newly specified:** field-atomic conflict rules, deletion tombstones, deterministic relational projection, empty-room initialization, UUID allocation, origin-selective one-step undo, all five current document extensions and explicit local-only presentation state implement the adopted Flow contract. These policies are documented because public subscription-only source does not establish exact constants or conflict behavior.
- **Unverified/open:** hosting, authenticated room access, durability, persistent offline retention, server restart recovery, exact Pro implementation/source parity, full-profile acceptance and collector-side OpenTelemetry delivery. Anonymous localhost acceptance does not establish production access control or retention guarantees.
