# Base Node recipe trace

## Production paths

- **Vanilla:** The supported package entry exports `createFlowBaseNode` at `apps/vanilla/src/public.ts:70-71`. The helper builds a `section[role=group]`, derives its accessible name from the caller title unless overridden, and places caller content in its own wrapper (`apps/vanilla/src/base-node.ts:8-31`). The node renderer contract receives only the node's content element (`apps/vanilla/src/mount-flow.ts:4879-4896`); the Flow host creates the outer `.flow-node` and a sibling handles container before invoking that renderer (`apps/vanilla/src/mount-flow.ts:4882-4896`). Thus the recipe does not own node position, drag, or handle semantics.
- **Vue:** `FlowBaseNode` is exported from `packages/vue/src/public.ts` and implemented as a native Vue component that renders the title, group role, accessible name, and default slot (`packages/vue/src/base-node.ts:4-29`). FlowCanvas resolves a caller node visual separately from the outer node element (`packages/vue/src/flow-canvas.ts:4149-4154,4324-4343`) and constructs native connection handle buttons independently (`packages/vue/src/flow-canvas.ts:4161-4166`). Its node wrapper retains canvas focus and pointer handlers; the recipe installs no listeners of its own.
- **Foldkit:** `createFoldkitBaseNode` is exported from the package public entry (`packages/foldkit/src/public.ts:93`) and uses the runtime-supplied `HtmlBuilder` to render the original group/title/content shell (`packages/foldkit/src/base-node.ts:3-21`). Foldkit's graph renderer invokes registered renderers inside a runtime-owned, keyed node wrapper with its own pointer and keyboard behavior (`packages/foldkit/src/graph.ts:2990-3009`). The demo's renderer composes the helper around caller content and a native action button (`apps/foldkit/src/main.ts:156-167`). Native graph handles remain part of the Foldkit node output.

All three host fixtures are reachable at `/ui-recipes/base-node/`. Vanilla mounts a decoded one-node graph through the public DOM host; Vue mounts a `FlowCanvas` with a typed custom node visual; Foldkit's route loads the real playground and package-backed node renderer.

## Conformity and deviations

- **Conforming within this bounded outcome:** Each host offers a caller-composed node shell with a title-derived accessible name and caller content. The focused E2Es assert visible outcomes on each production host route. Keyboard evidence is limited to native focus and browser keyboard-to-click behavior observed by test-local listeners in `apps/vanilla/src/base-node-test.ts`, `apps/vue/src/base-node-test.ts`, and `apps/foldkit/e2e/base-node-recipe.e2e.ts`; it does not establish application action behavior.
- **Intentionally different:** Vanilla accepts a DOM `Document` plus options and optional `Node`; Vue exposes a native component with a default slot; Foldkit accepts its scoped `HtmlBuilder`. This preserves each host's rendering and lifecycle model. Flow's node wrapper and handle ownership remain with each host canvas.
- **Unverified:** No pinned React runtime or current website comparison was run. This trace does not claim markup, style, lifecycle, or API parity beyond the tested outcome. Exhaustive accessible naming combinations, resize/selection modes, screen-reader behavior, archive consumer packaging, and cross-host interaction equivalence remain unverified. Test boundary is the three local Playwright production routes listed above.
