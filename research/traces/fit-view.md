# Fit to view

Status: production and test paths traced from pinned xyflow commit `0a1f9575b25679f2880175de8d3eae21aedde921` and the implemented Flow fit-to-view slice.

Upstream citations are relative to `research/artifacts/xyflow/0a1f9575b25679f2880175de8d3eae21aedde921/`. Flow citations are relative to the repository root.

## Public contract and production path

`ReactFlow` accepts an initial `fitView` flag and `fitViewOptions`, and the public instance exposes an awaitable `fitView(options)` operation. The documented options include padding, a node subset, zoom limits, animation duration, and inclusion of hidden nodes (`packages/react/src/container/ReactFlow/index.tsx:124`, `packages/react/src/types/instance.ts:231`). The instance method queues a fit, pushes a node update through the batch queue, and returns a resolver promise; consecutive requests may share that resolver (`packages/react/src/hooks/useReactFlow.ts:294`).

```text
ReactFlow fitView prop or instance.fitView(options)
  -> store fitViewQueued, node adoption/measurement
    -> eligible node lookup and bounds
      -> padded, centered viewport under zoom limits
        -> panZoom.setViewport
          -> transform store -> viewport CSS transform
```

For the initial prop, the store can seed its first transform when pane dimensions and declared node dimensions are already available (`packages/react/src/store/initialState.ts:69`). The store otherwise waits for initialized nodes in `setNodes`, or for the node-internals measurement path, before resolving the queued fit (`packages/react/src/store/index.ts:120`, `packages/react/src/store/index.ts:130`, `packages/react/src/store/index.ts:180`, `packages/react/src/store/index.ts:196`). `resolveFitView` reads the current node lookup, pane size, pan-zoom adapter, and zoom limits and delegates to the shared fit helper; it resolves the public promise after that helper completes (`packages/react/src/store/index.ts:56`, `packages/react/src/store/index.ts:63`, `packages/react/src/store/index.ts:75`).

The shared helper filters to nodes with measured width and height that are not hidden by default. `includeHiddenNodes` permits hidden nodes with nonzero dimensions from the dimension fallback; `options.nodes` restricts the fit to matching ids (`packages/system/src/utils/graph.ts:344`, `packages/system/src/utils/graph.ts:351`, `packages/system/src/utils/graph.ts:361`). It unions their absolute boxes into a rectangle (`packages/system/src/utils/graph.ts:247`). With no nodes in the supplied lookup, `fitViewport` returns successfully without changing the viewport (`packages/system/src/utils/graph.ts:375`, `packages/system/src/utils/graph.ts:382`). The code has no second empty-set guard after filtering; the resulting bounds are the zero rectangle at the origin (`packages/system/src/utils/graph.ts:261`).

`getViewportForBounds` parses padding, computes width and height fit scales, clamps the lesser scale to min/max zoom, centers the bounds, then adjusts for asymmetric padding (`packages/system/src/utils/general.ts:304`, `packages/system/src/utils/general.ts:312`, `packages/system/src/utils/general.ts:315`, `packages/system/src/utils/general.ts:322`, `packages/system/src/utils/general.ts:327`). `fitViewport` sends the result to `panZoom.setViewport` with optional duration, easing, and interpolation (`packages/system/src/utils/graph.ts:390`, `packages/system/src/utils/graph.ts:399`). That adapter uses its transform path (`packages/system/src/xypanzoom/XYPanZoom.ts:248`); this call is distinct from the adapter's explicitly constrained `setViewportConstrained` path (`packages/system/src/xypanzoom/XYPanZoom.ts:233`). `ZoomPane` writes changes to the store in uncontrolled viewport mode, and the `Viewport` subscriber writes the store transform to CSS (`packages/react/src/container/ZoomPane/index.tsx:59`, `packages/react/src/container/Viewport/index.tsx:20`, `packages/react/src/container/Viewport/index.tsx:39`).

## Upstream test path

The React component test mounts nodes initially outside the pane with `fitView` and a 0.2 minimum zoom, waits, and checks that the first node is within the viewport (`examples/react/cypress/components/reactflow/view-props.cy.tsx:6`, `examples/react/cypress/components/reactflow/view-props.cy.tsx:24`). A second mount passes `fitViewOptions.padding = 0.5` and checks that its one node is within the viewport (`examples/react/cypress/components/reactflow/view-props.cy.tsx:29`). These assertions establish visible placement in those mounted cases. They do not assert the exact transform or padding, the imperative promise, node subsets, hidden-node inclusion, animation, controlled viewport acknowledgement, or no-node behavior.

## Flow production path

The public `fitView(options)` controller operation returns a boolean; its decoded options allow `nodes: "all" | "selected"`, fractional padding, and positive fallback dimensions (`apps/vanilla/src/mount-flow.ts:109`, `apps/vanilla/src/mount-flow.ts:148`, `apps/vanilla/src/mount-flow.ts:167`). The JavaScript boundary decodes options before calling the host (`apps/vanilla/src/mount-flow.ts:3387`). The host refuses a destroyed controller, filters the document to selected nodes when requested, and passes adopted node positions, the authoritative viewport, live canvas dimensions, zoom limits, and node measurements to core geometry (`apps/vanilla/src/mount-flow.ts:3200`, `apps/vanilla/src/mount-flow.ts:3205`, `apps/vanilla/src/mount-flow.ts:3210`). Its default fallback box for an unmeasured node is 150 by 44 flow units, with an option to override it (`apps/vanilla/src/mount-flow.ts:3221`). Browser `ResizeObserver` stores measurements by node id (`apps/vanilla/src/mount-flow.ts:439`, `apps/vanilla/src/mount-flow.ts:456`). There is no initial-fit prop or queued fit while measurements are pending.

The pure `fitViewportToNodes` function builds a shared graph view with positive measured dimensions when present and otherwise uses the declared or supplied fallback box. It skips hidden nodes and unions the eligible absolute positions and boxes (`packages/core/src/domain/flow-fit-view.ts:58` through `packages/core/src/domain/flow-fit-view.ts:65`, `packages/core/src/domain/flow-graph.ts:51` through `packages/core/src/domain/flow-graph.ts:67`, `packages/core/src/domain/flow-graph.ts:125` through `packages/core/src/domain/flow-graph.ts:138`). With no eligible nodes or pane size it preserves the current viewport (`packages/core/src/domain/flow-fit-view.ts:53` through `packages/core/src/domain/flow-fit-view.ts:55`, `packages/core/src/domain/flow-fit-view.ts:65` through `packages/core/src/domain/flow-fit-view.ts:69`). It reserves default 10 percent padding per side, or accepts a uniform pane fraction or per-side pixels, takes the lesser fit scale, clamps it to configured limits, centers the box, and corrects for asymmetric padding (`packages/core/src/domain/flow-fit-view.ts:71` through `packages/core/src/domain/flow-fit-view.ts:79`, `packages/core/src/domain/flow-viewport-operation.schema.ts:16` through `packages/core/src/domain/flow-viewport-operation.schema.ts:27`, `packages/core/src/domain/flow-viewport-operation.schema.ts:119` through `packages/core/src/domain/flow-viewport-operation.schema.ts:173`). The fallback box schema requires finite positive dimensions (`packages/core/src/domain/flow-fit-view.ts:34` through `packages/core/src/domain/flow-fit-view.ts:39`).

The host applies its optional translation extent, returns false for an unchanged result, and otherwise publishes a semantic viewport change with a span (`apps/vanilla/src/mount-flow.ts:3227`, `apps/vanilla/src/mount-flow.ts:3237`, `apps/vanilla/src/mount-flow.ts:3241`). The viewport change path adopts the result in uncontrolled mode, retains the authoritative viewport in controlled mode, and invokes rendering (`apps/vanilla/src/mount-flow.ts:1442`). `renderViewport` constrains and writes the CSS transform, then reconciles visibility if culling is enabled (`apps/vanilla/src/mount-flow.ts:507`, `apps/vanilla/src/mount-flow.ts:215`).

## Conformity and deviations

- **Conforming:** Both paths center node bounds using padding and zoom limits (`packages/system/src/utils/graph.ts:344`, `packages/system/src/utils/general.ts:315`, `packages/core/src/domain/flow-graph.ts:125` through `packages/core/src/domain/flow-graph.ts:138`, `packages/core/src/domain/flow-fit-view.ts:71` through `packages/core/src/domain/flow-fit-view.ts:79`). Mounted tests show node placement in the pane (`examples/react/cypress/components/reactflow/view-props.cy.tsx:24`, `apps/vanilla/e2e/advanced-gestures.e2e.ts:201`).
- **Intentionally different:** Flow uses positive measured dimensions when available and a configurable 150 by 44 fallback for unmeasured visible nodes (`packages/core/src/domain/flow-graph.ts:51` through `packages/core/src/domain/flow-graph.ts:57`). It now supports all, selected, or specified node ids, per-side pixel or fractional padding, and animated completion through explicit terminal results; controlled requests resolve as proposals (`packages/core/src/domain/flow-fit-view.ts:15` through `packages/core/src/domain/flow-fit-view.ts:79`, `apps/vanilla/src/mount-flow.ts:6832` through `apps/vanilla/src/mount-flow.ts:6868`). Upstream uses its pan-zoom adapter and has no equivalent explicit superseded/disposed terminal status (`packages/react/src/hooks/useReactFlow.ts:294`, `packages/system/src/utils/graph.ts:399`, `packages/system/src/xypanzoom/XYPanZoom.ts:248`).
- **Unverified:** Flow's new shared host contract tests exercise measured fit, scroll/offset conversion, controlled proposals, and animation cancellation in Vanilla, Vue, and Foldkit. They do not prove CSS-transformed hosts, hosted production behavior, or every upstream option combination.

The Flow test boundary is pure fit geometry plus mounted measured and culled-node placement. The upstream mounted test boundary is visible placement from initial fit props. These boundaries support only the compared behavior above.
