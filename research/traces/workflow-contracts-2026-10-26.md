## Foldkit key isolation regression

The AI fixture intentionally gives an output node and its incoming edge the same string ID. These are distinct core ID domains. ## Conformity and deviations

- **Conforming to the adopted Flow contract:** Unit 1's nine kinds, typed configuration, role-aware data/trigger connections, finite acyclic dependencies, opaque metadata, generic graph compatibility and document interoperability have explicit public-API tests. Dedicated real-host tests exercise the same fixture import boundary through each owner. Verification results are recorded in the Plan 169 handoff; focused acceptance does not establish full-suite acceptance.
- **Intentionally different from the observed template architecture:** An optional Effect/Schema package owns workflow meaning; existing adapters own canvas lifecycle. This avoids framework and provider dependencies in graph core. The test boundary is package acceptance, architecture fixtures, packed consumers and three host import previews. Typed configuration and DAG policy are adopted Flow choices because upstream configuration and scheduler behavior remain unobserved.
- **Intentionally different in service ownership:** Offline AI fixture model identifiers and local image asset event contracts require no key or network generation. This unit supplies contracts only. Providers remain Unit 6 work, and live service integration still requires a separate maintainer decision.
- **Unverified:** Upstream source internals, runtime branch/join behavior, edge-plus insertion, configuration UI, streaming, live providers and exact template DOM/layout. No reference workflow execution was run. Rotation remains unverified pending Plan 167 integration. Template catalog ratings remain unchanged; these contract tests do not establish template parity or completion of later delivery units.
