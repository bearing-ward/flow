# Connection auto-pan

Status: pinned xyflow production and test paths traced at commit `0a1f9575b25679f2880175de8d3eae21aedde921`. Reference paths below are relative to `research/artifacts/xyflow/0a1f9575b25679f2880175de8d3eae21aedde921/`.

## React production path

The public `ReactFlow` prop `autoPanOnConnect` enables panning while a connection is dragged near the viewport edge; its documented default is `true` at `packages/react/src/types/component-props.ts:633`. The React store initializes it to `true` and sets `autoPanSpeed` to 15 at `packages/react/src/store/initialState.ts:141`. `ReactFlow` passes both through the graph container at `packages/react/src/container/ReactFlow/index.tsx:240`. A source `Handle` accepts a primary mouse down or touch start, then passes the options, `panBy`, connection state callbacks, transform accessor, and connection drag threshold into `XYHandle.onPointerDown` at `packages/react/src/components/Handle/index.tsx:139`.

`XYHandle` captures the container bounds and starting pointer position after resolving the originating handle at `packages/system/src/xyhandle/XYHandle.ts:55`. Movement past the connection drag threshold starts the connection at `packages/system/src/xyhandle/XYHandle.ts:118` and `packages/system/src/xyhandle/XYHandle.ts:128`. On subsequent movement, it converts the pointer to canvas-relative coordinates, converts that point through the current viewport transform for nearby-handle lookup, and starts the auto-pan loop once at `packages/system/src/xyhandle/XYHandle.ts:147`. The loop uses the latest pointer position and `calcAutoPan` to compute a signed screen-space delta, calls `panBy`, and schedules another animation frame at `packages/system/src/xyhandle/XYHandle.ts:80`. `calcAutoPan` uses a 40-pixel edge band by default and ramps velocity toward the edge up to the configured speed at `packages/system/src/utils/general.ts:57`. React's `panBy` delegates to the system helper, which constrains the requested viewport to `translateExtent` and returns whether it changed at `packages/react/src/store/index.ts:417` and `packages/system/src/utils/store.ts:510`.

On pointer movement, xyflow also resolves the closest candidate handle and checks the element under the pointer, connection validity, and handle coordinates at `packages/system/src/xyhandle/XYHandle.ts:149` and `packages/system/src/xyhandle/XYHandle.ts:251`. It updates the store with a connection state whose `to` point snaps to a valid target handle or follows the pointer at `packages/system/src/xyhandle/XYHandle.ts:178` and `packages/react/src/store/index.ts:447`. `GraphView` mounts `ConnectionLineWrapper`, which reads that state and renders an SVG connection line while a connection is in progress at `packages/react/src/container/GraphView/index.tsx:176` and `packages/react/src/components/ConnectionLine/index.tsx:24`. The auto-pan animation frame changes the viewport; it does not itself repeat handle hit testing or update the connection state. Those happen on pointer movement.

On pointer release, `XYHandle` calls `onConnect` for a valid target, invokes connection-end callbacks, resets connection state, cancels the animation frame, and removes document mouse and touch listeners at `packages/system/src/xyhandle/XYHandle.ts:201`. The React `Handle` callback adds the edge to internally managed edges and forwards `onConnect` to consumers at `packages/react/src/components/Handle/index.tsx:124`. The pan loop starts only after an actual connection drag; `autoPanOnConnect: false` makes the frame callback return without panning at `packages/system/src/xyhandle/XYHandle.ts:81`.

## Flow production and test path

Flow's vanilla host starts a connection on a source handle, captures the pointer, and creates an SVG line whose origin is the source handle center in flow coordinates at `apps/vanilla/src/mount-flow.ts:633` and `apps/vanilla/src/mount-flow.ts:415`. It stores the pointer in canvas coordinates at `apps/vanilla/src/mount-flow.ts:660`. Canvas pointer movement updates that position and the preview endpoint; unless `autoPanOnConnect` is `false`, it starts an animation-frame loop at `apps/vanilla/src/mount-flow.ts:1953`. The option is part of the mount boundary at `apps/vanilla/src/mount-flow.ts:83`.

The frame loop calls the shared core `selectionAutoPanDelta`, pans the rendered viewport, converts the stationary screen pointer through the new viewport, and updates the SVG endpoint at `apps/vanilla/src/mount-flow.ts:683`. It stops when the pointer leaves the edge band or the viewport cannot move farther, and otherwise schedules another frame at `apps/vanilla/src/mount-flow.ts:696`. On release, the host checks the target handle under the pointer, validates and publishes `edge-add`, and publishes a viewport change if panning occurred at `apps/vanilla/src/mount-flow.ts:2227`. Clearing or canceling the connection removes the preview, releases capture, and cancels any pending frame at `apps/vanilla/src/mount-flow.ts:428`.

Flow's browser helper checks that a connection preview appears on press and disappears on release at `apps/vanilla/e2e/canvas.e2e.ts:95`. A zoomed-viewport test checks the preview origin's flow coordinates and verifies that one change is published after release at `apps/vanilla/e2e/canvas.e2e.ts:1389`. The connection auto-pan browser test holds the pointer near the canvas edge until the viewport moves more than 550 pixels, moves to the newly visible target handle, releases, and checks preview removal, one rendered edge, an `edge-add` change, and retained viewport translation at `apps/vanilla/e2e/gesture-options.e2e.ts:218`.

## Conformity and deviations

- **Conforming:** Flow pans during an active connection while the pointer remains near the edge, keeps the preview endpoint at that screen position as the viewport moves, validates the newly visible target on release, and publishes the semantic edge and viewport changes. The Flow browser test crosses the viewport and completes that connection.
- **Intentionally different:** Flow uses Pointer Events and a straight SVG line in a vanilla host, while the pinned React adapter accepts mouse and touch listeners and renders a configurable path. Flow reuses a constant 15-pixel step in the 40-pixel edge band and stops its frame loop when no movement is possible; the pinned helper ramps speed toward the edge and keeps scheduling frames. Flow exposes `autoPanOnConnect` but no configurable pan speed.
- **Unverified:** Neither browser suite asserts frame cancellation after release or disabled-option behavior. The pinned test does not prove preview alignment or target-hit behavior after auto-pan, while the Flow test proves a connection to a newly visible target but does not measure preview coordinates during each pan frame. Visual parity remains unverified.
