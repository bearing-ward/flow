## React production path

The public `ReactFlow` prop `nodeDragThreshold` is documented as a pixel distance with a default of one at `packages/react/src/types/component-props.ts:670`. `ReactFlow` passes it to `StoreUpdater` at `packages/react/src/container/ReactFlow/index.tsx:142` and `packages/react/src/container/ReactFlow/index.tsx:247`; that updater tracks it at `packages/react/src/components/StoreUpdater/index.tsx:67`. The initial store value is one at `packages/react/src/store/initialState.ts:114`. A visible, draggable `NodeWrapper` calls `useDrag` at `packages/react/src/components/NodeWrapper/index.tsx:64` and `packages/react/src/components/NodeWrapper/index.tsx:72`. The hook creates `XYDrag` from the current store and attaches it to the node element at `packages/react/src/hooks/useDrag.ts:35` and `packages/react/src/hooks/useDrag.ts:63`.

`XYDrag` keeps `dragStarted`, initial canvas-relative mouse position, last flow position, and drag items as transient state at `packages/system/src/xydrag/XYDrag.ts:107`. Its d3 start callback records the pointer positions; only a threshold of zero calls `startDrag` immediately at `packages/system/src/xydrag/XYDrag.ts:306`. While no drag has started, its move callback measures Euclidean distance between the initial and current positions in **client pixels**, independent of zoom. It starts only when `distance > nodeDragThreshold` at `packages/system/src/xydrag/XYDrag.ts:346`. A move equal to the threshold does not start a drag. Multi-touch or removal of the active node aborts at `packages/system/src/xydrag/XYDrag.ts:329`.

Starting a drag resolves selection, captures the selected draggable items, and fires start callbacks at `packages/system/src/xydrag/XYDrag.ts:259`. Once started, a pointer move with a different flow position updates node positions at `packages/system/src/xydrag/XYDrag.ts:358`; `updateNodes` publishes changed positions with `dragging: true` and skips unchanged positions at `packages/system/src/xydrag/XYDrag.ts:201`. The end callback returns without stop callbacks if the threshold was never crossed. Otherwise, it publishes final positions with `dragging: false` only if positions changed and fires stop callbacks at `packages/system/src/xydrag/XYDrag.ts:364`. Thus the threshold gates drag lifecycle and movement; a press and release within it produces no drag change. The separate d3 `nodeClickDistance` option controls click suppression at `packages/system/src/xydrag/XYDrag.ts:306`. React's node click handler still handles selection, with a branch for a positive threshold, at `packages/react/src/components/NodeWrapper/index.tsx:108` and `packages/react/src/components/NodeWrapper/index.tsx:217`.

React maps updated drag items to a batch of position changes and forwards them to `triggerNodeChanges` at `packages/react/src/store/index.ts:211`. That store applies the batch to default nodes and calls `onNodesChange` at `packages/react/src/store/index.ts:263`. The wrapper's `dragging` class and absolute CSS transform show the result at `packages/react/src/components/NodeWrapper/index.tsx:184`.

## Conformity and deviations

- **Conforming:** Flow's default threshold is one canvas/client pixel, and activation uses Euclidean distance with a strict greater-than comparison, independent of zoom. Subthreshold movement leaves the node position unchanged and allows click selection. The new Flow browser test covers both sides of a configured eight-pixel threshold.
- **Intentionally different:** Flow uses native pointer capture and one final semantic change, while the pinned engine uses d3 drag and emits position changes during movement and on stop. The browser adapter owns pointer lifecycle.
- **Unverified:** The Flow browser test does not cover equality at the threshold, a zero threshold, zoom independence, or start-span timing. The pinned reference tests also lack a direct threshold-boundary assertion. No live side-by-side comparison was run.
