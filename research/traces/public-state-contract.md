# Public state contract: three host traces and JavaScript implementation

Captured 2026-09-26. The shared contract is implemented in bounded form by JavaScript, Vue, and the Foldkit host, with focused local tests. Current website names in the matrix are live docs; the pinned source remains a separate dated snapshot. These checks establish local behavior, not hosted CI or React Flow parity.

## Shared committed-state contract

The shared value is a Schema-derived `{ document, viewport }` snapshot from the complete accepted model. It includes every node and edge in the document, including hidden elements and elements omitted by viewport culling. Node `position` stays parent-relative. Missing IDs return `undefined`. The snapshot excludes measured geometry, DOM nodes, canvas dimensions, active pointer/connection sessions, and transient preview positions. Preview/lifecycle state needs its own later contract.

Controlled semantic interactions emit a proposal but do not change accepted reads until the owner acknowledges it through the controlled input/replacement path. Uncontrolled semantic interactions commit first; reads after the interaction observe the accepted value. External document or viewport replacement is an accepted-state transition in either mode. A canceled preview produces no accepted document-state transition. Viewport pan can produce successive accepted viewport values in uncontrolled mode; controlled mode exposes the proposal through the existing semantic channel while accepted reads remain at the last acknowledgement.

Host read surfaces:

| Host | Read surface | Value ownership |
| --- | --- | --- |
| JavaScript | `getSnapshot()`, `getNodes()`, `getEdges()`, `getNode(id)`, `getEdge(id)`, `getViewport()` | Implemented as detached deeply immutable snapshot/projection values. Each call is a point-in-time read; object identity is not stable. Mutation attempts cannot change live state. |
| Vue | readonly computed `snapshot`, `document`, `nodes`, `edges`, `viewport`; `getNode(id)` / `getEdge(id)` lookup functions | Reactive readonly views with no identity stability promise. They must not expose mutable aliases to owner props or internal state; runtime protection must be tested, not inferred from TypeScript `readonly`. |
| Foldkit | pure selectors over the Schema-derived model plus typed state request/response and accepted-state ports | Immutable-by-contract model values and readonly selector results. No runtime freeze guarantee is implied. Host must supply current model values through the Runtime boundary; callers do not gain internal-store access. |

The read contract is value-oriented: consumers compare schema values, not object identity. JavaScript detaches because it has no reactive owner boundary; Vue preserves dependency tracking through readonly computed projections; Foldkit follows its immutable model/update style. All hosts must protect accepted state against caller mutation, with the stated host-specific mechanism verified in their own adapter plan.

### Accepted-state notification policy

Semantic `FlowChange` remains a proposal/event stream and is never redefined as an accepted-state event. A distinct accepted-state notification carries `{ previous, current, cause }`, where `cause` identifies owner replacement or an accepted semantic transition. Emit synchronously after the accepted model value has been installed. For a local uncontrolled operation, preserve legacy semantic callback delivery first, then deliver accepted-state notification; for a controlled proposal, emit only the proposal until acknowledgement, then notify on the replacement. Initial subscription has no callback; callers explicitly read the initial snapshot. Notify only when the schema-level `{document, viewport}` value differs, so no-op replacements and duplicate equal values are deduplicated.

Within one event, observers run in subscription order from a stable listener snapshot. Unsubscribe takes effect immediately, including during dispatch. Disposal invalidates every subscription and prevents later notifications; subscribing after disposal returns an inert unsubscribe. Listener exceptions are isolated per listener, reported at the host failure boundary, and do not prevent later listeners or roll back accepted state. Reentrant mutations are queued FIFO until all listeners for the current notification finish; nested notifications do not interleave. Reads inside a listener see that notification's `current`; queued mutations become visible before their own notification. These are new contract choices, not behavior established by current implementations. Per-host plans must test exception, reentrancy, disposal, equality, and mutation safety.

### Proposal/callback-family mapping

`FlowChange` variants describe semantic candidates (node positions/bounds/size, selection, edges, viewport). They do not encode the complete gesture lifecycle. Proposed future mappings: node drag start/move/stop maps to pointer-session start, preview updates, and finish; connection/reconnection callbacks map to session start, candidate changes, success, and cancellation; `onMoveStart/onMove/onMoveEnd` map to viewport gesture lifecycle. Cancellation (pointercancel, Escape, node removal, unmount/destroy) ends the lifecycle with a cancellation reason and emits no accepted document change for an uncommitted preview. In controlled mode finish emits a semantic proposal; only owner acknowledgement creates an accepted-state notification. Do not claim a state callback replaces any start/move/end callback. Implementation is deferred to a separate lifecycle plan.

## Vue: `FlowCanvas` and `useFlow`

Production entry: `packages/vue/src/flow-canvas.ts:265-308` selects authoritative active document/viewport from controlled props or canvas-owned refs. `stateSnapshot` at `310-315` recursively unwraps Vue proxies and builds a detached FlowSnapshot, which the core snapshot constructor freezes. `packages/vue/src/use-flow.ts:48-90` exposes readonly computed document, nodes, edges, viewport and snapshot views; `getSnapshot`, `getNode`, and `getEdge` read the current computed snapshot. `useNodes`, `useEdges`, and `useViewport` are direct composable projections. Missing provider throws the actionable error at `51-54`.

The local `subscribeState` registry is created alongside the computed snapshot (`flow-canvas.ts:317-322`). A synchronous watcher compares schema values, installs the accepted current snapshot before dispatch, skips equal values, and drains reentrant notifications FIFO (`324-364,380-408`). Listeners run in registration order from a stable copy; unsubscription is immediate, exceptions are reported and isolated, and canvas unmount clears listeners and queued changes (`324-364,1117-1129`). Subscription does not deliver an initial event. `publish` emits `change` before controlled proposals; uncontrolled document changes carry `semantic-change` (`581-627`). `updateDocument` and `updateViewport` emit in controlled mode or update owned refs with their corresponding causes (`629-650`). Prop acknowledgement/replacement is observed from active props; Vue computed reads invalidate immediately, while DOM rendering follows Vue's render tick.

Node drag preview applies a transform without changing the document (`611-684`, movement continuation `1087+`); finish emits a position proposal only past its threshold (`776-814`). Pan calls viewport update on movement (`1055-1064`). Hidden/offscreen nodes and hidden edges are filtered from render at `589-609`, `868-870`, and `909-919`, but remain in the active document. Graph-derived node position can be absolute for rendering (`586-587`); state reads must expose parent-relative document values. Cleanup on unmount removes observers/listeners and preview at `985-993`; preview cleanup releases capture and clears session (`522-536`).

Tests: `apps/vue/e2e/public-state.e2e.ts:3-108` mounts real descendants using package exports and verifies controlled proposal/acknowledgement, external replacement, edge removal, viewport update and acknowledgement, missing IDs, hidden/cull reads, frozen projections, canvas isolation, observer unmount, canvas disposal, and the outside-provider error. ## Foldkit: `createProgram`, typed ports, and graph selectors

Production browser entry: `apps/foldkit/src/main.ts:31-35` calls `createProgram`. `packages/foldkit/src/application.ts:34-71` defines the schema-derived snapshot request/response and inbound/outbound ports. `createProgram` composes the Element Runtime at `221-255`; `hostSubscriptions` wires real request/action ports at `144-152`. Snapshot requests are handled against the latest graph model at `166-194`, with optional point lookups and a complete snapshot. No initial accepted-state event is sent; callers explicitly request the initial value.

The schema-derived model at `packages/foldkit/src/graph.ts:37-46` includes the complete document, viewport, ownership modes, and active pointer session. Pure selectors read snapshot, nodes, edges, point lookups, and viewport at `89-106`. They return immutable-by-contract model values (no runtime freeze guarantee), preserve hidden/culled entries and document order, return undefined for missing IDs, retain parent-relative positions, and exclude pointerSession previews. `snapshotEquivalence` uses the FlowSnapshot schema at `108-120`; semantic commits attach accepted state separately at `123-133`, while external document/viewport replacements report accepted state at `135-145`. `Graph.update` routes replacements and user messages at `318-356`.

The application preserves event ordering: `PublishChanges` emits a legacy semantic change before accepted state at `80-98`; graph outputs are translated to that command at `109-142`. Controlled proposals retain the current model and do not publish accepted state until the owner acknowledges through replacement; uncontrolled commits update the model first. Equal replacement values are deduplicated at schema value level. Foldkit's port implementation provides FIFO reentrant sends, immediate unsubscribe, per-listener failure isolation, and disposal as exercised by host tests; these are local adapter evidence, not upstream runtime parity.

The view filters hidden/offscreen nodes only in its projection (`graph.ts:392-439`); edge rendering filters hidden edges/endpoints (`441-458`). The model document remains complete. Nested coordinate conversion uses absolute graph positions for drag and subtracts parent absolute position when writing `position` (`265-302`). Pointer cancellation clears the transient session without changing the accepted snapshot (`304-356`).

Tests: `apps/foldkit/e2e/test-harness.ts:215-246` embeds two real Runtime programs and observes typed ports; it starts them and issues correlated snapshot requests at `248-295`, then drives replacement, command, unsubscribe, listener failure, reentrancy, and disposal helpers at `295-435`. `apps/foldkit/e2e/public-state.e2e.ts:3-55` verifies initial complete reads and rendered projection; `57-249` verifies uncontrolled/controlled document and viewport flows plus cancellation; `251-373` verifies schema-value deduplication, program isolation, unsubscribe, error isolation, FIFO reentrancy, and post-disposal behavior. These local tests exercise the package-owned Foldkit adapter through the demo E2E harness. They do not establish packed-consumer behavior, hosted CI, or React Flow runtime parity.

## Explicit input/action/output cases for downstream tests

| Input | Action | Expected accepted reads | Expected notifications |
| --- | --- | --- | --- |
| Initial document has visible, hidden, and culled nodes/edges; subscribe after mount | Read snapshot and selectors | All document entries; viewport; IDs preserve document order; hidden/culling do not filter; positions remain parent-relative | No initial state callback; explicit read supplies initial value |
| Existing document and viewport | External document replacement | Complete replacement, including removals | One accepted-state event after install if value differs; no `FlowChange` proposal |
| Controlled owner state at A | Propose node move to B, then later acknowledge with replacement B | Reads remain A before acknowledgement; read B after acknowledgement | Proposal first; no accepted-state event for proposal; one after ack |
| Uncontrolled state at A | Commit node move to B | Reads B after commit | Legacy semantic proposal first, then accepted-state event |
| Any viewport | External viewport update or uncontrolled viewport command | Current accepted viewport | Accepted event only when different; controlled command alone retains old viewport |
| Query nonexistent node/edge id | `getNode/getEdge` | `undefined` | None |
| Active preview | Cancel via pointercancel/Escape/removal/unmount/destroy | Committed document unchanged; session/preview excluded from snapshot | Lifecycle cancellation belongs to future callback family; no accepted document event absent a commit |
| Active subscription | Unsubscribe, dispose, then attempt further update/subscribe | Reads on a live host remain available until disposal; after disposal public methods follow host disposal rule and subscriptions are inert | No callbacks after unsubscribe/disposal; listener exception does not stop peers; reentrant changes queue FIFO |

## Conformity and deviations

- **Conforming in selected JavaScript value shape:** `FlowSnapshotSchema` composes FlowDocumentSchema and ViewportSchema (`packages/core/src/domain/flow-snapshot.ts:8-11`), and getters expose parent-relative authoritative document values (`apps/vanilla/src/mount-flow.ts:6013-6027`). JavaScript reads preserve hidden and culled entries. Vue exposes partial computed reads (`packages/vue/src/use-flow.ts:7-27`); Foldkit exposes package-owned selectors and typed state ports; all three host suites exercise their bounded read surfaces. These tests do not establish React Flow runtime equivalence or package-consumer availability for Foldkit.
- **Intentionally different:** snapshots exclude DOM measurement, internal renderer objects and pointer-preview state, unlike a framework instance's broader internal access. Current Flow render projections filter hidden/culled entries while accepted-state reads retain authoritative document entries (`mount-flow.ts:2463-2569`; Vue `flow-canvas.ts:589-609`; Foldkit `graph.ts:327-349`). Test boundary: existing browser tests assert selected rendering outcomes; no test yet compares full getter contents.
- **Intentionally different:** accepted-state subscriptions are separate from semantic proposals and React Flow's callback families. JavaScript now tests proposal-before-accepted ordering, controlled acknowledgement, deduplication, listener failure isolation, reentrancy, unsubscribe and disposal. Vue and Foldkit implement this selected accepted-state contract in their host boundaries. Test boundary: local adapter browser tests; no live upstream behavior comparison or native multi-pointer test.
- **Unverified:** live React Flow documentation describes current members but does not prove a behavior-by-behavior runtime match; the pinned snapshot proves only its dated source revision. No equivalent current website runtime capture, listener reentrancy/error experiment, or native multi-pointer test was run. The live-doc comparison is nomenclature/interface evidence, not parity evidence.

- **Conforming in the selected Foldkit host boundary:** the app exposes schema-derived complete snapshot/lookup reads and a distinct accepted-state port, with schema-value deduplication and controlled proposals separate from acceptance. Evidence is the actual Runtime embed and typed-port suite in `apps/foldkit/e2e/public-state.e2e.ts`; the adapter is package-owned, but this app E2E does not establish packed-consumer availability.

- **Conforming within the shared Flow test contract:** [`public-state-contract.json`](../fixtures/public-state-contract.json) defines four versioned Flow-authored cases. The vanilla controller, Vue descendant composable, and Foldkit Runtime ports each read their production accepted state and emit observed semantic/accepted-state sequences; each host E2E compares those observations, core graph queries, settled rendered DOM, and disposal counts ([vanilla](../../apps/vanilla/e2e/shared-conformance.e2e.ts), [Vue](../../apps/vue/e2e/shared-conformance.e2e.ts), [Foldkit](../../apps/foldkit/e2e/shared-conformance.e2e.ts)). Existing eight rendering fixtures remain separate. This is Flow cross-host evidence, not an upstream fixture or parity result. The initial fixture records host-specific edge DOM before handle measurement; accepted edge records and graph queries remain identical.
