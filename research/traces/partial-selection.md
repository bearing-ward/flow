`Pane` calls `getNodesInside` with `selectionMode === SelectionMode.Partial` and `excludeNonSelectableNodes: true` at `packages/react/src/container/Pane/index.tsx:221`. The shared function converts the rectangle from screen to flow coordinates, skips hidden or nonselectable nodes, obtains measured or declared node bounds, and calculates overlap area at `packages/system/src/utils/graph.ts:264`. Partial mode requires positive overlap area; Full mode requires overlap area at least the node area. The shared helper computes overlap from the product of positive intersection widths and heights, then applies `Math.ceil` at `packages/system/src/utils/general.ts:129`. An unmeasured node without handle bounds is included for initial rendering, and a dragging node is included, regardless of the overlap test at `packages/system/src/utils/graph.ts:294`. Those exceptions are part of the pinned source and should not be inferred away when discussing exact parity.

The matching node IDs are written as selection changes, with selectable connected edges, at `packages/react/src/container/Pane/index.tsx:218`. `triggerNodeChanges` applies the changes to default nodes or calls `onNodesChange` for controlled owners at `packages/react/src/store/index.ts:265`. ## Conformity and deviations

- **Conforming:** Flow's default Full mode follows the React default. Flow's Partial mode selects a node with positive overlap, as the core unit and targeted browser tests show. The core unit test also verifies Full versus Partial, edge-touch exclusion, and hidden and nonselectable exclusion. Shift rectangle rendering and connected-edge selection have the test coverage identified above.
- **Intentionally different:** Flow publishes one `selection-set` when the pointer is released; the pinned React and Svelte adapters update selection on pointer movement. Flow uses known node measurements or a host fallback for bounds, while pinned `getNodesInside` also allows unmeasured and dragging nodes through its predicate.
- **Unverified:** The pinned shared Playwright test does not exercise partial boundary overlap. Flow's browser test checks one positive-overlap case; the Full/Partial and edge-touch distinctions have core unit coverage but no direct browser assertion. The pinned unmeasured and dragging-node exceptions are also not reproduced in Flow's selection predicate, so a broad visual or interaction parity claim remains unsupported.
