# Node placement extents

Status: pinned xyflow production and test paths traced at commit `0a1f9575b25679f2880175de8d3eae21aedde921`. Upstream citations are relative to `research/artifacts/xyflow/0a1f9575b25679f2880175de8d3eae21aedde921/`; Flow citations are relative to the repository root.

## Public contract and production path

React Flow's `nodeExtent` is a flow-coordinate top-left and bottom-right boundary for node placement, separate from `translateExtent`, which limits viewport panning (`packages/react/src/types/component-props.ts:492`, `packages/react/src/types/component-props.ts:499`). `ReactFlow` passes it to the initial store wrapper, prop updater, and graph view (`packages/react/src/container/ReactFlow/index.tsx:190`, `packages/react/src/container/ReactFlow/index.tsx:214`, `packages/react/src/container/ReactFlow/index.tsx:316`). The initial store substitutes an infinite extent when none is provided, then adopts user nodes (`packages/react/src/store/initialState.ts:58`, `packages/react/src/store/initialState.ts:61`). Controlled node updates pass the current extent to the same adoption path; a changed extent re-adopts nodes (`packages/react/src/store/index.ts:99`, `packages/react/src/store/index.ts:120`, `packages/react/src/store/index.ts:395`).

```text
ReactFlow nodeExtent + nodes
  -> store adoption -> internal absolute positions
  -> NodeWrapper CSS transform
  -> ResizeObserver -> measured size -> position clamp

pointer drag -> XYDrag -> calculateNodePosition -> internal positions
  -> node position changes -> store / controlled callback -> NodeWrapper transform
```

For a root node, adoption converts the user position for its origin, chooses the node's own coordinate extent if present or the global extent otherwise, and clamps the internal absolute position (`packages/system/src/utils/store.ts:146`, `packages/system/src/utils/store.ts:152`). The clamp keeps the **whole measured rectangle** inside the extent: its maximum x and y subtract node width and height (`packages/system/src/utils/general.ts:22`). Child nodes have extra coordinate conversions: the child position is relative to its parent, while the global extent constrains absolute position; `extent: 'parent'` also constrains it to the parent's measured rectangle (`packages/system/src/utils/store.ts:278`, `packages/system/src/utils/store.ts:289`, `packages/system/src/utils/store.ts:293`, `packages/system/src/utils/store.ts:299`). A per-node extent can override the global extent for a root node (`packages/system/src/utils/store.ts:71`).

The wrapper observes visible nodes, and its shared `ResizeObserver` sends their DOM measurements to `updateNodeInternals` (`packages/react/src/components/NodeWrapper/useNodeObserver.ts:31`, `packages/react/src/container/NodeRenderer/useResizeObserver.ts:16`). That store path calls the system measurement function and updates absolute positions (`packages/react/src/store/index.ts:167`, `packages/react/src/store/index.ts:180`, `packages/react/src/store/index.ts:194`). Measurement can reclamp a node after its true dimensions become known (`packages/system/src/utils/store.ts:441`, `packages/system/src/utils/store.ts:449`, `packages/system/src/utils/store.ts:459`). `NodeWrapper` renders the internal absolute position with CSS `translate(...)` (`packages/react/src/components/NodeWrapper/index.tsx:202`). Thus the rendered node may initially be at an extent boundary and shift inward once its width and height are measured.

A visible, draggable wrapper attaches `XYDrag` through `useDrag` (`packages/react/src/components/NodeWrapper/index.tsx:72`, `packages/react/src/hooks/useDrag.ts:40`). On movement, `XYDrag` obtains the global extent, computes a candidate position, and calls `calculateNodePosition` for each dragged item (`packages/system/src/xydrag/XYDrag.ts:130`, `packages/system/src/xydrag/XYDrag.ts:166`, `packages/system/src/xydrag/XYDrag.ts:192`). That function prefers a node-specific extent; for `extent: 'parent'`, it builds a rectangle from the parent's absolute position and dimensions; a numeric child extent is offset by its parent's position. It then clamps using the node's measured size and maps the absolute result back to its user position (`packages/system/src/utils/graph.ts:429`, `packages/system/src/utils/graph.ts:434`, `packages/system/src/utils/graph.ts:436`, `packages/system/src/utils/graph.ts:449`, `packages/system/src/utils/graph.ts:456`). For a multi-node drag, `XYDrag` adjusts the global extent per item from the group's bounding box so the selection keeps its spacing at the boundary (`packages/system/src/xydrag/XYDrag.ts:146`, `packages/system/src/xydrag/XYDrag.ts:176`, `packages/system/src/xydrag/XYDrag.ts:192`). It updates internal positions and emits node changes only when a position actually changes (`packages/system/src/xydrag/XYDrag.ts:201`, `packages/system/src/xydrag/XYDrag.ts:210`, `packages/system/src/xydrag/XYDrag.ts:214`). React applies default-node changes or forwards controlled changes, and the wrapper's CSS transform reflects the accepted position (`packages/react/src/store/index.ts:263`, `packages/react/src/components/NodeWrapper/index.tsx:205`).

## Reference test path

The mounted React Cypress test supplies `nodeExtent = [[0, 0], [50, 50]]` to a controlled flow with a node at `(200, 200)` and asserts the rendered CSS transform becomes `(50, 50)` (`examples/react/cypress/components/reactflow/view-props.cy.tsx:193`, `examples/react/cypress/components/reactflow/view-props.cy.tsx:207`). This demonstrates initial clamping in that fixture. The utility test adopts a node measured at `50 × 25` under a `100 × 100` extent and asserts absolute x/y equal the maximum boundary minus width/height (`examples/react/cypress/components/utils/adopt-user-nodes.cy.ts:48`, `examples/react/cypress/components/utils/adopt-user-nodes.cy.ts:63`, `examples/react/cypress/components/utils/adopt-user-nodes.cy.ts:69`). Another utility case covers a parent and child under a global extent (`examples/react/cypress/components/utils/adopt-user-nodes.cy.ts:146`, `examples/react/cypress/components/utils/adopt-user-nodes.cy.ts:176`, `examples/react/cypress/components/utils/adopt-user-nodes.cy.ts:185`). These cited tests do not assert live dragging, group-boundary behavior, dynamic extent changes, or the post-measurement shift.

## Flow production path

The public `mountFlow` decodes options and document before creating the vanilla host (`apps/vanilla/src/mount-flow.ts:3461`, `apps/vanilla/src/mount-flow.ts:3470`). The mount schema accepts a finite global `nodeExtent`, separate from the viewport pan extent (`apps/vanilla/src/mount-flow.ts:99`, `apps/vanilla/src/mount-flow.ts:103`). Flow nodes have positions but no per-node extent or parent relation (`packages/core/src/domain/flow.schema.ts:44`). Core clamps the whole measured node rectangle and centers one that cannot fit (`packages/core/src/domain/flow-node-extent.schema.ts:25`, `packages/core/src/domain/flow-node-extent.schema.ts:40`). The group helper constrains a shared movement delta, preserving relative spacing (`packages/core/src/domain/flow-node-extent.schema.ts:50`, `packages/core/src/domain/flow-node-extent.schema.ts:72`).

The host derives `adoptedPosition` from each supplied position and current DOM measurement, using zero dimensions before measurement (`apps/vanilla/src/mount-flow.ts:333`, `apps/vanilla/src/mount-flow.ts:341`, `apps/vanilla/src/mount-flow.ts:397`). `restoreAdoptedPosition` stores only a difference from the authoritative position in `renderedNodePositions` for edge geometry (`apps/vanilla/src/mount-flow.ts:400`, `apps/vanilla/src/mount-flow.ts:403`, `apps/vanilla/src/mount-flow.ts:406`). Initial mount reconciles after attaching the canvas; reconcile adopts every node before culling or rendering (`apps/vanilla/src/mount-flow.ts:3251`, `apps/vanilla/src/mount-flow.ts:3255`, `apps/vanilla/src/mount-flow.ts:1173`, `apps/vanilla/src/mount-flow.ts:1180`). New DOM entries and changed nodes render the adopted transform, and edges receive the override map (`apps/vanilla/src/mount-flow.ts:1675`, `apps/vanilla/src/mount-flow.ts:1681`, `apps/vanilla/src/mount-flow.ts:1341`, `apps/vanilla/src/mount-flow.ts:1366`). The resize observer updates measurement, readopts the non-dragging node, and reconciles edges (`apps/vanilla/src/mount-flow.ts:441`, `apps/vanilla/src/mount-flow.ts:458`, `apps/vanilla/src/mount-flow.ts:461`, `apps/vanilla/src/mount-flow.ts:472`). A controller document update replaces the authoritative document and runs the same reconciliation (`apps/vanilla/src/mount-flow.ts:3374`, `apps/vanilla/src/mount-flow.ts:3379`, `apps/vanilla/src/mount-flow.ts:3381`).

Pointer drag snapshots begin at adopted positions, and keyboard movement first builds a document of adopted positions before applying the existing group extent rule (`apps/vanilla/src/mount-flow.ts:1767`, `apps/vanilla/src/mount-flow.ts:1773`, `apps/vanilla/src/mount-flow.ts:1778`, `apps/vanilla/src/mount-flow.ts:2981`, `apps/vanilla/src/mount-flow.ts:2992`, `apps/vanilla/src/mount-flow.ts:3001`). A cancelled drag restores the adopted position and edge override (`apps/vanilla/src/mount-flow.ts:1023`, `apps/vanilla/src/mount-flow.ts:1051`, `apps/vanilla/src/mount-flow.ts:1064`). Controlled publication restores the adopted authoritative display until the owner acknowledges a node-position change; uncontrolled publication updates the document and reconciles (`apps/vanilla/src/mount-flow.ts:1424`, `apps/vanilla/src/mount-flow.ts:1428`, `apps/vanilla/src/mount-flow.ts:1435`, `apps/vanilla/src/mount-flow.ts:1452`, `apps/vanilla/src/mount-flow.ts:1464`). Mount, update, and measurement adoption themselves do not publish a position change.

## Flow test path

Core tests reject inverted extents and negative dimensions, check complete-node clamping, center an oversized node, and check a shared group delta (`packages/core/src/domain/flow-node-extent.schema.test.ts:13`, `packages/core/src/domain/flow-node-extent.schema.test.ts:30`, `packages/core/src/domain/flow-node-extent.schema.test.ts:47`, `packages/core/src/domain/flow-node-extent.schema.test.ts:57`). It checks the emitted proposal and that the rendered node returns to the owner's adopted position before acknowledgement (`apps/vanilla/e2e/flow-followups.e2e.ts:116`, `apps/vanilla/e2e/flow-followups.e2e.ts:121`, `apps/vanilla/e2e/flow-followups.e2e.ts:124`, `apps/vanilla/e2e/flow-followups.e2e.ts:137`, `apps/vanilla/e2e/flow-followups.e2e.ts:142`, `apps/vanilla/e2e/flow-followups.e2e.ts:149`). It does not assert the initial provisional position before measurement or an owner acknowledgement after the emitted proposal.

## Conformity and deviations

- **Conforming:** Flow now adopts initial and later supplied positions into a bounded rendered position and readopts after measurement (`apps/vanilla/src/mount-flow.ts:1180`, `apps/vanilla/src/mount-flow.ts:458`, `apps/vanilla/src/mount-flow.ts:3379`). The mounted test asserts initial and controlled display clamping and a controlled drag proposal from the bounded position (`apps/vanilla/e2e/flow-followups.e2e.ts:116`, `apps/vanilla/e2e/flow-followups.e2e.ts:124`, `apps/vanilla/e2e/flow-followups.e2e.ts:142`). This matches the compared upstream adoption and measurement boundary at the tested level (`packages/react/src/store/initialState.ts:61`, `packages/react/src/store/index.ts:120`, `packages/system/src/utils/store.ts:459`).
- **Intentionally different:** Flow keeps the owner-supplied document position authoritative while holding a bounded display override (`apps/vanilla/src/mount-flow.ts:394`, `apps/vanilla/src/mount-flow.ts:400`, `apps/vanilla/src/mount-flow.ts:3379`). It has no nested parent nodes or per-node extents and centers an oversized node or group when it cannot fit (`packages/core/src/domain/flow.schema.ts:44`, `packages/core/src/domain/flow-node-extent.schema.ts:33`, `packages/core/src/domain/flow-node-extent.schema.ts:50`).
- **Unverified:** The Flow test boundary covers core geometry, mounted gestures, measured initial adoption, and a controlled replacement and proposal. It does not establish a pre-measurement visual position, connected edge placement after adoption, post-movement resize, controlled owner acknowledgement, cancelled gesture, oversized-node browser behavior, or snap-plus-extent interaction. The cited upstream tests cover initial/adoption clamping but not a live drag at the boundary (`examples/react/cypress/components/reactflow/view-props.cy.tsx:193`, `examples/react/cypress/components/utils/adopt-user-nodes.cy.ts:48`); no side-by-side parity test was run.

Source similarity does not establish full xyflow parity.
