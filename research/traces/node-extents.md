## Public contract and pinned production path

React Flow passes `nodeExtent` through the initial store wrapper and prop updater (`packages/react/src/container/ReactFlow/index.tsx:190`, `packages/react/src/container/ReactFlow/index.tsx:214`). The initial store adopts the supplied nodes, and later controlled `setNodes` calls run the same adoption (`packages/react/src/store/initialState.ts:61`, `packages/react/src/store/index.ts:120`).

Adoption converts a node's anchor to physical top-left coordinates, resolves its numeric extent or the global extent, then calls `clampPosition` with `getNodeDimensions(userNode)` (`packages/system/src/utils/store.ts:154`, `packages/system/src/utils/store.ts:156`, `packages/system/src/utils/store.ts:157`). Dimensions prefer `measured`, declared dimensions, then initial dimensions, falling back to zero on each unknown axis (`packages/system/src/utils/general.ts:351`, `packages/system/src/utils/general.ts:359`). The internal node owns a separate measured object and the accepted absolute position (`packages/system/src/utils/store.ts:162`, `packages/system/src/utils/store.ts:167`).

The exact axis rule is `Math.min(Math.max(position, minimum), maximum - size)` (`packages/system/src/utils/general.ts:20`, `packages/system/src/utils/general.ts:27`). For a node at `(200,200)` inside `[[0,0],[50,50]]`:

- Before measurement, unknown dimensions are `0x0`, so adoption returns `(50,50)`.
- After measurement, the DOM dimensions are `150x44`, so the result is `(-100,6)`.
- On an oversized axis, `maximum - size` wins even when it is below the minimum. There is no centering branch.

The wrapper attaches its node observer to the shared `ResizeObserver` (`packages/react/src/components/NodeWrapper/useNodeObserver.ts:31`, `packages/react/src/container/NodeRenderer/useResizeObserver.ts:16`). React's store calls system `updateNodeInternals` and then `updateAbsolutePositions` (`packages/react/src/store/index.ts:185`, `packages/react/src/store/index.ts:194`). System reads the DOM size, reclamps the absolute position with that size, and installs the measured internal node (`packages/system/src/utils/store.ts:441`, `packages/system/src/utils/store.ts:449`, `packages/system/src/utils/store.ts:459`, `packages/system/src/utils/store.ts:464`). The wrapper renders `internals.positionAbsolute` as a CSS translation (`packages/react/src/components/NodeWrapper/index.tsx:205`). A measurement update also emits a dimensions change (`packages/system/src/utils/store.ts:485`).

During drag, `XYDrag` computes the candidate top-left, snaps it if configured, and calls `calculateNodePosition` (`packages/system/src/xydrag/XYDrag.ts:166`, `packages/system/src/xydrag/XYDrag.ts:192`). That function resolves a per-node or parent extent and clamps with `node.measured`, then converts back to the stored anchor (`packages/system/src/utils/graph.ts:434`, `packages/system/src/utils/graph.ts:436`, `packages/system/src/utils/graph.ts:456`, `packages/system/src/utils/graph.ts:465`). Multi-node drag shifts each item's extent by the group's physical bounds before the same clamp (`packages/system/src/xydrag/XYDrag.ts:178`, `packages/system/src/xydrag/XYDrag.ts:180`, `packages/system/src/xydrag/XYDrag.ts:186`). Thus oversized nodes and groups use the maximum-minus-size rule during drag too.
